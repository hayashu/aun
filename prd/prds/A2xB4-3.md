# PRD: プロジェクト開始時に分野間の「誰が・何を・どの形で渡すか」を決める受け渡し取り決め表（A2xB4-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A2×B4（暗黙の期待・ルールがわからない × 専門領域の違いで認識がずれる）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は個人の作法カード、版2は2人の当たり前の交換を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがるプロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。Bさんの部署は機械系の社員が多い。

分野をまたぐプロジェクトでは、分野の間で多くのものが受け渡される。基板の外形データ、筐体の寸法、部品の発熱量、変更の依頼。しかし、**誰が・何を・どの形式で・誰に渡すかは決まっておらず、それぞれの分野の暗黙の作法に任されている**。機械は図面と依頼書で受けたい、電気はチャットとPDFで済ませたい。プロジェクトのたびに、同じ作法のずれが起きる。

**誤解の実態**: Bさんは、基板のコネクタ位置と筐体の穴のずれをチャットで機械の担当者に伝え、「了解です」と返されて安心した。機械側では、寸法の変更は依頼書で受けるのが作法で、チャットは相談扱いだった。2週間後に穴が変わっていないとわかった。同じプロジェクトで、基板の外形データも、機械が欲しい3D形式ではなくPDFで渡され、機械側が手で寸法を拾い直していた。調整役のAさんは、こうした受け渡しのずれを個別に聞いて回るしかなかった。

**気づきの実態**: 問題は個人の作法の知識だけではない。**分野間の受け渡しの形が、プロジェクトとして決まっていない**ことが原因である。決まっていなければ、各自が自分の分野の作法で渡し、相手の作法と合わなければ止まる。プロジェクトの最初に受け渡しの形を一覧で決めれば、個人が相手の作法を推測する必要はなくなる。

**練習機会の実態**: プロジェクトのキックオフでは日程と役割を決めるが、分野間で何をどう渡すかは話題にならない。前のプロジェクトでうまくいった受け渡しの形も、次のプロジェクトに引き継がれない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。分野間の受け渡しで、形式の違いによる手戻りがどれだけ起きているかは測られていない。

## Goals / Non-Goals

**Goals**

- 分野間の受け渡しで、形式や手順のずれによる停滞が減る（受け渡しのうち、取り決め表の形で行われた割合を効果指標とする）
- 受け渡しの形が、プロジェクトの最初に決まる（プロジェクト開始から2週間以内に取り決め表が作られた割合を効果指標とする）
- うまくいった受け渡しの形が、次のプロジェクトに引き継がれる（前のプロジェクトの取り決め表を下敷きにして作った割合を効果指標とする）

**Non-Goals**

- 正式な設計変更手続きの改定（手続きは既存のものを使い、取り決め表はその使い方を決める）
- 受け渡しの監視（受け渡しが取り決めどおりかを個人の評価に使わない）
- 全社標準の作成（一つのプロジェクトで試し、うまくいった形を広げる）
- 個人の作法の学習（版1）、2人の当たり前の交換（版2）の範囲

## Proposed Solution / Feature Description

プロジェクトの開始時に、**分野間で受け渡すものを一覧にし、それぞれ「誰が・何を・どの形式で・誰に・どの手順で渡すか」を決める取り決め表**を作る仕組みを提供する。キックオフの30分で、各分野の代表が表を埋める。表はプロジェクトの全員が見られ、受け渡しのたびに参照される。

**主要な構成要素**:

- **受け渡しの一覧** — 分野間で受け渡すもの（外形データ、寸法、発熱量、変更依頼など）を一覧にする。過去のプロジェクトの一覧を下敷きにできる
- **取り決めの項目** — 受け渡しごとに、渡す人、受ける人、形式（3D、図面、PDF、チャット）、手順（依頼書の要否、誰を経由するか）、受け取りの確認方法を決める
- **作法の違いの表示** — 分野ごとの作法が違う項目（機械は依頼書、電気はチャット、など）に印を付け、キックオフで話し合う項目として示す
- **受け取りの確認** — 取り決めに沿って渡したら、受け手が「受け取った・対応を始めた」を返す。「了解」の意味の曖昧さをなくす
- **次のプロジェクトへの引き継ぎ** — プロジェクトが終わったら、うまくいった取り決めと、変えたほうがよい取り決めに印を付けて保存する

## User Stories

- **US-001 受け渡しの形が分野ごとに違って止まる問題**
  利用者（Bさん）は、機械に変更を頼むとき、どの形式でどの手順で渡せばよいかを、プロジェクトの取り決めとして知りたい。それにより、チャットで頼んで「了解」と言われ、2週間止まる事態を避けたい。
  背景: 現状は受け渡しの形が決まっておらず、各自の分野の作法で渡す。相手の作法と合わなければ止まり、それは後工程で初めてわかる。

- **US-002 受け渡しのずれを個別に聞いて回る問題**
  利用者（調整役のAさん）は、分野間の受け渡しの形を、プロジェクトの最初に一覧で決めたい。それにより、ずれを個別に聞いて回る手間をなくしたい。
  背景: 現状は受け渡しのずれが起きるたびに、調整役が当事者に聞いて回るしかない。

- **US-003 前のプロジェクトの経験が引き継がれない問題**
  利用者（プロジェクトリーダー）は、前のプロジェクトでうまくいった受け渡しの形を、次のプロジェクトで使いたい。それにより、毎回同じずれを繰り返す事態を避けたい。
  背景: 現状はプロジェクトが終わると、受け渡しの経験が個人の記憶にしか残らない。

## Open Questions

- キックオフの30分で、受け渡しの一覧を十分に洗い出せるか。途中で増える受け渡しをどう追加するか
- 作法が違う項目で、どちらの作法に合わせるかを誰が決めるか
- 取り決め表を参照する習慣がつくか
- **モックで確かめたいこと**: キックオフの場で、各分野の代表が取り決め表を30分以内に埋められるか
- **モックで確かめたいこと**: 作法の違いの印が付いた項目を見て、話し合うべき点がひと目でわかるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **表の形骸化** — 作って満足する → 参照されない → 元の作法に戻る。軽減: 受け取りの確認を表から行う形にし、表を使う場面を作る
- **手続きの重さ** — 細かく決めすぎる → 受け渡しの手間が増える → 現場が嫌がる。軽減: 決めるのは形式と手順と確認方法の三つに絞る
- **強い分野への合わせ込み** — 立場の強い分野の作法に統一される → 他の分野の負担が増える → 不満が溜まる。軽減: 作法の違いは話し合いで決め、決めた理由を一行残す
- **特定の人のための仕組みと見られる** — 外国籍社員への配慮に見える → ベテランが面倒がる → 導入が止まる。回避: プロジェクト全員の受け渡しの取り決めとして導入する
