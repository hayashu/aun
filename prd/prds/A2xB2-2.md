# PRD: 先輩が「これは聞いてくれていい」を先に公開する、聞いてよかった質問リスト（A2xB2-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門は機械系の社員が多く、社内規格や図面の読み方、部門独自の略語が前提として会話が進む。

2人は、わからないことを先輩に聞きたいと思っている。しかし、**何を聞いてよくて、何を聞くと「そんなことも知らないのか」と思われるのか**という暗黙の線がわからない。線がわからないので、安全側に倒して聞かない。先輩の側は、「何でも聞いてね」と言っているのに、なぜ聞いてこないのかわからない。

**誤解の実態**: Bさんは設計会議で出てきた「DR2」という言葉の意味がわからなかった。先輩は日頃から「何でも聞いてね」と言っていたが、Bさんは入社3年目の自分が設計審査の呼び方を知らないのは恥ずかしいと思い、聞かなかった。一人で調べても出てこず、DR2の期限を取り違えて対応が1週間遅れた。後で先輩は「なんで聞かなかったの、みんな最初は知らないよ」と言った。先輩にとって、DR2は入社した誰もが最初に聞く言葉だった。Bさんにはそれがわからなかった。

**気づきの実態**: 「何でも聞いてね」は、先輩の本心である。しかしその言葉からは、どの質問が「みんな最初に聞くもの」なのかがわからない。先輩は、自分が昔聞いた質問、後輩によく聞かれる質問を覚えている。その記憶が後輩に渡れば、後輩は「これは聞いていいんだ」と安心できる。今は、その記憶が先輩の頭の中にしかない。

**練習機会の実態**: 部門のチャットに質問する場はあるが、全員が見る場で初歩的な質問をするのは、なおさら気が引ける。個別に聞くにしても、先輩の時間を取る申し訳なさがある。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。若手が聞けずに一人で調べている時間は測られていない。

## Goals / Non-Goals

**Goals**

- 若手が、聞いてよい質問を安心して聞けるようになる（リストに載った質問と同じ種類の質問を、若手が先輩に聞いた回数を効果指標とする）
- 聞かずに取り違える件数が減る（前提知識の取り違えで対応が遅れた件数の自己申告を効果指標とする）
- 先輩の「何でも聞いてね」が、具体的な形で伝わる（「先輩に聞きやすい」と答えた若手の割合を効果指標とする）

**Non-Goals**

- 質問への自動回答（答えるのは先輩で、リストは「聞いてよい」ことを伝えるもの）
- 部門の用語集の網羅的な作成（版3の範囲）
- 本人の前提知識の記録（版1の範囲）

## Proposed Solution / Feature Description

先輩が**「自分が昔聞いた質問」「後輩によく聞かれる質問」を、答えではなく質問の形で公開する**リストを提供する。各質問には、先輩の一言（「僕も1年目に聞いた」「毎年みんな聞く」）が付く。若手はリストを見て、同じ質問を先輩に聞いてよいことを知る。リストは答えを載せず、質問の入口だけを示す。聞くこと自体を、先輩とのつながりにする。

**主要な構成要素**:

- **聞いてよかった質問** — 先輩が、自分が昔聞いた質問を一行で登録する（例:「DRって何の略ですか」「一般公差はどの規格を見ればいいですか」）。答えは載せない
- **先輩の一言** — 各質問に、「僕も1年目に聞いた」「毎年聞かれる」のような一言を付ける。質問の恥ずかしさを下げる
- **この質問を聞く** — 若手は、リストの質問を選んで「この質問を聞きたい」を先輩に送れる。登録した先輩か、その分野に詳しい先輩に届く
- **自分もそう思った** — 若手は、リストの質問に「自分もこれがわからなかった」の印を付けられる。印が多い質問は、先輩にとって「みんなが困っている」ことの手がかりになる
- **聞いたら加える** — 若手が先輩に聞いて解決した質問を、リストに加えることを提案できる。次の後輩のための入口になる

## User Stories

- **US-001 聞いてよいかわからず聞かない問題**
  利用者（Bさん）は、自分のわからないことが、先輩たちも昔聞いた質問なのかを知りたい。それにより、恥ずかしさで聞かずに一人で調べ、取り違えて遅れる事態を避けたい。
  背景: 現状は「何でも聞いてね」と言われても、どこまで聞いてよいかの線がわからず、安全側に倒して聞かない。取り違えは作業の期限で結果として現れる。

- **US-002 「何でも聞いてね」が伝わらない問題**
  利用者（先輩）は、後輩に気軽に聞いてもらえるよう、聞いてよい質問の例を示したい。それにより、後輩が一人で抱え込んで遅れる事態を防ぎたい。
  背景: 現状は「何でも聞いてね」と言っても後輩が聞いてこず、遅れが出てから知る。

## Open Questions

- 先輩が質問を登録してくれるか。登録のきっかけが必要かもしれない（新人の配属時期に呼びかけるなど）
- 答えを載せないことが、若手にとってもどかしくないか。答えを載せると先輩とのつながりが生まれないが、急ぎのときには困る
- **モックで確かめたいこと**: 若手が質問リストを見て、「これは聞いていいんだ」と安心できるか
- **モックで確かめたいこと**: 先輩が自分の昔の質問を、1分以内で登録できるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **リストが育たない** — 先輩が登録しない → 質問が少ない → 若手が使わない。軽減: 最初に部門の数人に10個ずつ登録してもらい、配属時期に案内する
- **答えがない不満** — 答えを知りたいのに載っていない → 若手がもどかしく感じる → 使わなくなる。軽減: 「この質問を聞く」から先輩の返事がすぐ届く経路を用意する
- **質問の集中** — 詳しい先輩に質問が集まる → 負担が偏る → 返事が遅れる。軽減: 同じ分野の先輩を複数表示し、未回答が多い人には送らない
- **恥ずかしさの残存** — リストにない質問はまだ聞きにくい → 結局聞かない → 効果が限られる。軽減: 「聞いたら加える」でリストを広げ、版1・版3と組み合わせる
