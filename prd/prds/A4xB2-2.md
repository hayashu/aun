# PRD: 設計レビューのあと先輩と15分、責めずに「なぜ起きたか」を一緒にたどるミス振り返りシート（A4xB2-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B2（失敗の原因がわからない × ハードウェアの知識が足りず焦る）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は本人の原因切り分け、版3は部署の設計ミス事例集を扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門は機械系の社員が多く、筐体・機構・材料の知識が前提として会話が進む。

設計レビューでミスが指摘されると、レビューの場では「ここ直しておいて」で終わる。**なぜそのミスが起きたのかを、一緒に考えてくれる人がいない**。先輩はミスの原因に心当たりがあることも多いが、レビューの場で指摘すると責めているように聞こえるので、言わない。若手は原因がわからないまま、焦って知識不足と決めつけ、やみくもに勉強する。

**誤解の実態**: Bさんは、基板の取り付け穴が筐体のリブと干渉していることを指摘された。レビューの場で機械の先輩は「ここ直しておいて」とだけ言った。先輩は、Bさんが古い筐体データを使っていたのではないかと思っていたが、人前でそれを言うと責めているようで言わなかった。Bさんは機械の知識不足だと思い込み、教科書を読み始めた。翌月、Bさんは別の基板でまた古いデータを使い、同じ干渉を起こした。先輩は「前回言っておけばよかった」と後悔した。

**気づきの実態**: 先輩は原因に気づいていた。Bさんは原因に気づいていなかった。2人が少しだけ話す時間があれば、原因は共有できた。しかし、レビューの場は人前で、原因を話すと責める雰囲気になる。レビューのあとに、2人だけで、責めずに原因をたどる時間と型があれば、先輩は気づいていたことを伝えられ、Bさんは同じミスを防げた。

**練習機会の実態**: 部門には振り返りの文化がなく、ミスは直して終わる。なぜなぜ分析の研修はあるが、品質トラブル向けで、個人の小さな設計ミスに使われることはない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。設計ミスの原因が共有されずに再発した件数は、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 設計ミスの原因が、先輩と若手の間で共有される（指摘されたミスのうち、振り返りシートが使われた割合を効果指標とする）
- 同じ設計ミスの繰り返しが減る（振り返ったミスと同じ種類のミスが、その後に起きた件数を効果指標とする）
- 若手が、ミスを責められずに振り返れたと感じる（「責められずに原因を話せた」の自己申告を効果指標とする）

**Non-Goals**

- 品質トラブルの分析手法の置き換え（大きな不具合は既存の手法で扱う）
- ミスの責任の判定（誰が悪いかを決めない）
- 本人の原因切り分け（版1）、部署の事例集（版3）の範囲

## Proposed Solution / Feature Description

設計レビューでミスが指摘されたあとに、**指摘した先輩と若手が15分だけ2人で話し、決まった質問に沿ってミスの経緯をたどる**振り返りシートを提供する。質問は「何が起きたか」「そのとき何を見ていたか」「何があれば防げたか」「次はどうするか」の4つ。「なぜミスをしたのか」とは聞かず、「何があれば防げたか」と聞くことで、責める雰囲気を避ける。

**主要な構成要素**:

- **振り返りの依頼** — 設計レビューのあと、若手か先輩のどちらからでも、15分の振り返りを依頼できる
- **4つの質問** — 何が起きたか、そのとき何を見ていたか（使っていたデータ、参照していた資料）、何があれば防げたか、次はどうするかを、2人で順にたどる。若手が先に答え、先輩が気づいたことを書き足す
- **先輩の気づき** — 先輩が、原因の心当たりを一行で書ける欄を設ける。レビューの場では言いにくかったことを、2人の場で伝えられる
- **次の対策** — 振り返りの結果、次にどうするかを一つに絞って書く（例:「配置の前に、機械側に最新の筐体データを確かめる」）
- **振り返りの記録** — 2人の振り返りを残す。次に同じような設計をするとき、若手が見返せる

## User Stories

- **US-001 原因がわからずに知識不足と決めつける問題**
  利用者（Bさん）は、設計ミスの原因を、気づいている人と一緒にたどりたい。それにより、教科書を読んでも同じミスを繰り返す事態を避けたい。
  背景: 現状はレビューの場で「直しておいて」で終わり、原因を話す時間がない。原因がわからないまま翌月に同じミスを起こす。

- **US-002 気づいていた原因を人前で言えない問題**
  利用者（機械の先輩）は、若手のミスの原因に気づいたとき、責めずにそれを伝えたい。それにより、同じミスが繰り返されて後悔する事態を避けたい。
  背景: 現状はレビューの場で原因を言うと責めているようで、言わずに終わる。

## Open Questions

- 先輩が15分の時間を取ってくれるか。レビューのたびに振り返りをするのは負担にならないか
- 若手が先輩に振り返りを依頼するのは気が引けないか
- 先輩が原因に気づいていない場合、振り返りはどこまで役に立つか
- **モックで確かめたいこと**: 4つの質問に沿って話すことで、15分以内に原因と次の対策にたどり着けるか
- **モックで確かめたいこと**: 「何があれば防げたか」という問い方が、若手にとって責められていると感じない形になっているか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **先輩の負担** — 振り返りのたびに15分 → 先輩が忙しくなる → 依頼を断る。軽減: 振り返りは同じ種類のミスが2回目のとき、など条件を決めて絞る
- **責める場になる** — 先輩の言い方がきつい → 若手が萎縮する → 振り返りを避ける。軽減: 質問の文面を責めない形に固定し、先輩向けに言い方の例を示す
- **形式的な振り返り** — 質問を埋めるだけになる → 本当の原因に届かない → 同じミスが続く。軽減: 先輩の気づきの欄を設け、経験からの視点を入れる
- **評価への転用** — 振り返りの記録が残る → 人事評価に使われる → 正直に話さなくなる。軽減: 記録は2人だけが見られる設定にする
