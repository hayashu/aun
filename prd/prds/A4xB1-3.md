# PRD: 試作の評価観点をチームで公開し、一度の失敗では機会を取り上げない「次の機会」保証（A4xB1-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B1（失敗の原因がわからない × やりたいものづくりができない）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は本人の指摘の振り返り、版2は上司のフィードバックカードを扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門の業務の多くは会議資料のパワーポイント作成で、実際に手を動かして作る機会は少ない。

チームでは、試作がよいかどうかの**評価観点が決まっていない**。治具なら何を満たせばよいのか、評価基板なら何が確かめられていればよいのか。観点は上司の頭の中にあり、上司ごとに違う。若手は観点を知らないまま試作し、うまくいかなかったときも、どの観点で外したのかがわからない。さらに、一度うまくいかなかった若手には、次の機会が回りにくい。失敗の原因がわからず、改善の機会もない。

**誤解の実態**: Bさんは評価治具を作り、課長に「現場では使いにくい」と言われて、治具は使われなかった。課長の観点は「作業者が片手で扱えるか」「工具なしで部品を交換できるか」だった。別の係長は、同じような治具を「強度は十分か」「材料費は予算内か」の観点で見ていた。Bさんは誰からも観点を聞いておらず、何を満たせばよかったのかわからなかった。次の治具の製作は、別の先輩に任された。Aさんも試作基板の評価で「詰めが甘い」と言われ、その後は評価の仕事が回ってこなかった。

**気づきの実態**: 問題は個人の振り返りや上司の伝え方だけではない。**試作の評価観点がチームで共有されていない**ことと、**一度の失敗で機会が途切れる**ことの二つが重なっている。観点が事前に公開されていれば、若手は観点を満たすように試作でき、外したときもどの観点かがわかる。そして、改善してもう一度試す機会があれば、失敗は学びに変わる。

**練習機会の実態**: チームには試作の承認手続きがあるが、承認されたかどうかだけが記録され、何を見て判断したかは残らない。失敗した試作のやり直しの機会も、制度としてはない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。チームの若手が試作の機会を一度の失敗で失っている件数は測られていない。

## Goals / Non-Goals

**Goals**

- 試作の評価観点が、試作の前に公開される（試作の種類のうち、評価観点が書かれた割合を効果指標とする）
- 試作がうまくいかなかったとき、どの観点で外したかがわかる（うまくいかなかった試作のうち、外した観点が示された割合を効果指標とする）
- 一度うまくいかなかった若手にも、やり直しの機会が回る（うまくいかなかった試作のうち、やり直しが行われた割合を効果指標とする）

**Non-Goals**

- 試作の採点（観点を満たしたかどうかを示すだけで、点数は付けない）
- 若手の人事評価への反映（試作の結果を評価に使わない）
- 全社の試作基準の統一（チームの観点から始める）
- 本人の振り返り（版1）、上司のフィードバック（版2）の範囲

## Proposed Solution / Feature Description

チームで**試作の種類ごとの評価観点を一覧にして公開し、うまくいかなかった試作には一度のやり直しの機会を保証する**仕組みを提供する。試作を始める前に、若手はその種類の観点を見る。試作を見せたときに、上司は観点ごとに「満たしている／もう一歩」を選ぶ。「もう一歩」があれば、その観点を直してやり直す機会が自動で設定される。

**主要な構成要素**:

- **評価観点の一覧** — 試作の種類（治具、評価基板、筐体の試作など）ごとに、評価観点を3〜5個書く（例: 治具＝片手で扱えるか、工具なしで交換できるか、強度、材料費）。チームの数人で書き出し、上司ごとの観点の違いをそろえる
- **試作前の確認** — 試作を任されたら、その種類の観点を若手に表示する。若手は観点ごとに、どう満たすかを一行書いてから始める
- **観点ごとの判断** — 試作を見せたときに、上司が観点ごとに「満たしている／もう一歩」を選び、もう一歩の観点には一行の理由を書く
- **やり直しの機会** — 「もう一歩」の観点があれば、その観点だけを直すやり直しの期限が設定される。やり直しは一度保証される
- **観点の見直し** — 観点を満たしていても使われなかった試作や、観点にない理由で指摘された試作があれば、観点の追加を提案できる

## User Stories

- **US-001 何を満たせばよいかわからずに試作する問題**
  利用者（Bさん）は、試作を始める前に、その試作が何を満たせばよいかを知りたい。それにより、作り終えてから「使いにくい」と言われる事態を避けたい。
  背景: 現状は評価観点が上司の頭の中にあり、上司ごとにも違う。外したことは作り終えてから知る。

- **US-002 一度の失敗でものづくりの機会を失う問題**
  利用者（Aさん）は、試作がうまくいかなかったときに、直してもう一度試す機会がほしい。それにより、一度の失敗でものづくりから遠ざかる状態を変えたい。
  背景: 現状はやり直しの機会がなく、一度うまくいかなかった若手には次の試作が回らない。

- **US-003 上司ごとに試作の見方が違う問題**
  利用者（チームリーダー）は、チームの試作の見方をそろえたい。それにより、若手がどの上司に見せるかで評価が変わる状態を変えたい。
  背景: 現状は観点が上司ごとに違い、若手は誰の観点に合わせればよいかわからない。

## Open Questions

- 評価観点を書き出すことに、上司たちが協力してくれるか
- 観点にすべてを書くことはできない。観点にない理由での指摘をどう扱うか
- やり直しの機会を一度保証すると、業務の日程に影響しないか
- **モックで確かめたいこと**: 試作前に観点を見て、どう満たすかを書く流れが、若手にとって負担ではなく道しるべに感じられるか
- **モックで確かめたいこと**: 上司が観点ごとに「もう一歩」を選んだとき、若手がやり直しの機会を前向きに受け取れるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **観点の形骸化** — 観点を満たしても使われない試作が出る → 観点が信用されない → 一覧が使われない。軽減: 観点の見直しを提案できるようにし、定期的に更新する
- **観点への過剰適応** — 観点だけを満たそうとする → 創意工夫がなくなる → 試作が型にはまる。軽減: 観点は最低限の条件であることを明記し、観点以外の工夫も評価の会話で取り上げる
- **やり直しの負担** — やり直しが日程を圧迫する → 上司がやり直しを嫌がる → 機会の保証が空約束になる。軽減: やり直しは「もう一歩」の観点だけに絞り、範囲を小さくする
- **評価への転用** — 観点の判断が記録される → 人事評価に使われる → 若手が試作を避ける。軽減: 評価に使わない方針を明記する
