# PRD: 毎朝2分で「昨日・今日・詰まり」を共有し、詰まりはその場で手伝う人を決めるチームの朝会（A3xB3-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B3（適切なコミュニケーション方法がわからない × 自分で進める道筋を作れない）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は本人の報告の下書き、版2は上司と部下の信号の合図を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

チームでは、困っていることは**本人が自分で言い出す**ことになっている。しかし、いつ、誰に、どう言えばよいかは決まっていない。言い出すのが得意な人はすぐに助けを得られ、苦手な人は一人で抱え込む。自分で区切りを作って進めるのが苦手な人ほど、詰まりに気づくのが遅れ、気づいても言い出せないまま時間が過ぎる。チームの月次の報告会で初めて、誰かの仕事が大きく遅れていたことがわかる。

**誤解の実態**: Bさんはノイズ対策の評価で、測定器の設定がわからず3日間詰まっていた。隣の席の先輩はその測定器に詳しかったが、Bさんが詰まっていることを知らなかった。Bさんは、先輩の仕事を邪魔したくなくて言い出せなかった。月次の報告会で評価の遅れが報告され、先輩は「言ってくれれば5分で教えたのに」と言った。Aさんも、別の仕事で情報待ちのまま1週間止まっていたが、誰に催促すればよいかわからず黙っていた。

**気づきの実態**: 問題は、個人の言い出し方だけではない。**詰まりを共有する場が、チームの日々の流れに組み込まれていない**ことが原因である。毎朝、全員が短く「詰まり」を言う場があれば、言い出すかどうかを迷う必要はない。全員が言うので、詰まりを言うことは特別なことでも恥ずかしいことでもなくなる。

**練習機会の実態**: チームの会議は週1回の定例と月次の報告会だけで、日々の詰まりを共有する場はない。チャットは雑談と連絡に使われ、詰まりを書く人はほとんどいない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。チームの誰かが詰まってから、それがチームに知られるまでの日数は測られていない。

## Goals / Non-Goals

**Goals**

- 詰まりがチームに早く知られる（詰まりが朝会で共有されてから、解消するまでの日数を効果指標とする）
- 詰まりを言い出すことが当たり前になる（朝会で詰まりが共有された件数を効果指標とする）
- 一人で抱え込む時間が減る（「詰まりを一人で抱え込む時間が減った」の自己申告を効果指標とする）

**Non-Goals**

- 進捗の細かな管理（朝会は詰まりを共有する場で、進捗率を報告する場ではない）
- 個人の評価（詰まりの数を評価に使わない）
- 長い会議の追加（朝会は全体で10分以内とする）
- 本人の報告の下書き（版1）、上司との合図（版2）の範囲

## Proposed Solution / Feature Description

チームで**毎朝10分以内の朝会**を開き、その進行をWebで支える仕組みを提供する。各自が2分以内で「昨日やったこと・今日やること・詰まっていること」を言う。詰まりが出たら、その場で手伝える人が手を挙げ、朝会のあとに5分話す約束をする。詰まりを言うことを、毎朝の決まった手順にする。

**主要な構成要素**:

- **事前の一行入力** — 朝会の前に、各自が「昨日・今日・詰まり」を一行ずつ入力する。詰まりがなければ「なし」でよい。入力しておくことで、口頭で話すのが苦手な人も伝えられる
- **進行の画面** — 朝会では、進行役の画面に全員の入力を並べ、一人2分の時計を表示する。順番は日によって変える
- **詰まりの手伝い** — 詰まりが出たら、手伝える人が画面の「手伝える」を押す。朝会のあとに5分話す約束が記録される
- **詰まりの一覧** — チームの詰まりを一覧で見られる。解消したら本人が「解消」を押す。3日以上続く詰まりには印が付く
- **朝会の振り返り** — 一か月ごとに、詰まりの件数と、解消までの平均日数をチームに返す。個人別には出さない

## User Stories

- **US-001 詰まっていても言い出せない問題**
  利用者（Bさん）は、詰まっていることを、言い出すかどうか迷わずに伝えられる場がほしい。それにより、隣の先輩に5分聞けば解決することで3日間止まる事態を避けたい。
  背景: 現状は詰まりを共有する場がなく、言い出すのが苦手な人ほど一人で抱え込む。遅れは月次の報告会で初めてわかる。

- **US-002 誰に催促すればよいかわからない問題**
  利用者（Aさん）は、情報待ちで止まっていることを、チームに知らせたい。それにより、誰かが「その情報なら自分が持っている」と気づけるようにしたい。
  背景: 現状は誰に催促すればよいかわからず、黙って待つ。

- **US-003 チームの詰まりに気づけない問題**
  利用者（チームリーダー）は、メンバーの詰まりを、月次の報告会より前に知りたい。それにより、遅れが大きくなる前に手を打ちたい。
  背景: 現状はメンバーの詰まりが見えず、報告会で初めて遅れを知る。

## Open Questions

- 毎朝10分の朝会を、チームが続けられるか。在宅勤務の日はどうするか
- 詰まりを人前で言うことに、抵抗を感じる人はいないか。事前の一行入力だけで済ませる選択肢を用意するか
- 「手伝える」が特定の人に集中しないか
- **モックで確かめたいこと**: 事前の一行入力から朝会の進行まで、全体で10分以内に収まるか
- **モックで確かめたいこと**: 詰まりが出たときに「手伝える」が押され、5分話す約束が自然に決まる流れになっているか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **形骸化** — 毎朝同じ報告になる → 「詰まりなし」ばかりになる → 朝会の意味がなくなる。軽減: 詰まりの例（情報待ち、やり方がわからない、判断待ち）を入力欄に示す
- **長時間化** — 詰まりの議論が朝会の中で始まる → 朝会が長くなる → 続かない。軽減: 朝会では詰まりの共有と手伝う人の決定までにし、議論は朝会のあとの5分に回す
- **人前で言う負担** — 詰まりを人前で言うのが恥ずかしい → 本当の詰まりを言わない → 効果が出ない。軽減: 事前入力の詰まりは、本人が希望すれば口頭で読み上げずに一覧に載るだけにする
- **評価への転用** — 詰まりの数が記録される → 評価に使われる → 詰まりを隠す。軽減: 個人別の件数を集計せず、評価に使わない方針を明記する
