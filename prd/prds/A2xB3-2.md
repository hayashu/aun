# PRD: 上司と週1回5分、3つの質問で期待と進め方をそろえる期待合わせチェックイン（A2xB3-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A2×B3（暗黙の期待・ルールがわからない × 自分で進める道筋を作れない）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は本人の完了条件の計画、版3はチームの進め方の明文化を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

課長は、部下に任せることが成長につながると考えている。だから仕事を渡したあとは、部下が相談に来るまで口を出さない。しかし課長の頭の中には、「このくらいで一度見せに来るだろう」「ここまでやれば十分」という**暗黙の期待**がある。部下はその期待を知らず、いつ見せればよいか、どこまでやればよいかがわからないまま進める。期待のずれは、最後に見せたときに初めてわかる。

**誤解の実態**: 課長はBさんに電源ICの候補調査を任せた。課長は1週間後に途中経過を見せに来ると思っていたが、Bさんは完成するまで見せるものではないと思っていた。3週間後、Bさんは20個の候補を詳細に調べた資料を持ってきた。課長は3つに絞った推奨がほしかった。課長は「任せたのに、なぜ途中で相談しなかったのか」と思い、Bさんは「任されたから一人でやりきろうとした」と思った。同じことがAさんとの間でも、評価の仕事で起きていた。

**気づきの実態**: 課長も部下も、相手の期待が自分と違うことに気づいていない。課長にとって「途中で見せに来る」は当然のことで、言う必要を感じない。部下にとって「任された」は「一人でやりきる」ことである。定期的に短く話す場があれば、ずれは週単位で見つかった。しかし、1on1の面談は月に一度で、話題はキャリアや評価が中心になり、目の前の仕事の進め方は扱われない。

**練習機会の実態**: 部門の定例会議では全体の進捗だけが報告され、一人ひとりの仕事の期待合わせは行われない。部下から「進め方を確認させてください」と言い出すのは、任されたことを放棄するようで気が引ける。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。上司と部下の期待のずれによる手戻りは、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 上司と部下の期待のずれが、週単位で見つかる（チェックインで「期待が違った」と記録された件数を効果指標とする。ずれが見つかること自体を成果として数える）
- 最後に見せたときの大きな作り直しが減る（仕事のうち、最初の提出で大きな方向転換を求められた割合を効果指標とする）
- 部下が自分で区切りを作って進められる（チェックインで部下が「次の区切り」を自分で言えた割合を効果指標とする）

**Non-Goals**

- 評価面談の置き換え（チェックインは目の前の仕事の進め方だけを扱い、評価には使わない）
- 部下の進捗の細かな監視（週1回5分に限り、日々の報告は求めない）
- 本人の完了条件の計画（版1）、チームの進め方の明文化（版3）の範囲

## Proposed Solution / Feature Description

上司と部下が**週に1回、5分だけ、決まった3つの質問で話す**チェックインの仕組みを提供する。質問は「いまの仕事で、どこまでやれば完了だと思っているか」「次の区切りはいつで、そこで何を見せるか」「詰まっていることはあるか」の三つ。部下は事前に答えを書き、上司はそれを見て一言返す。暗黙の期待を、毎週言葉にする場を作る。

**主要な構成要素**:

- **3つの質問** — 部下が、完了の基準、次の区切り、詰まっていることの三つに、それぞれ一行で答える。チェックインの前日に知らせる
- **上司の一言** — 上司は部下の答えを見て、「完了の基準はそれでよい／ここが違う」「区切りはそれでよい／もっと早く見せて」を選び、必要なら一言添える
- **ずれの印** — 上司が「違う」を選んだ項目には印が付き、部下は直した答えを書く。どこがずれやすいかが、2人の履歴に残る
- **5分の時計** — チェックインの時間を5分に区切る時計を表示する。長くならないことが、続けるための条件である
- **履歴** — 上司と部下が、過去のチェックインの答えと印を見返せる。2人の間で何がずれやすいかがわかる

## User Stories

- **US-001 任されたから一人でやりきろうとする問題**
  利用者（Bさん）は、任された仕事でも、上司が途中で何を見たいと思っているかを毎週知りたい。それにより、3週間一人でやりきって、最後に方向違いを指摘される事態を避けたい。
  背景: 現状は「任された」を「一人でやりきる」と受け取り、途中で見せない。期待のずれは最後に初めてわかり、そのときには時間がすでに使われている。

- **US-002 口を出すと任せたことにならない問題**
  利用者（課長）は、部下に任せながらも、自分の期待を週に一度だけ短く伝えたい。それにより、部下の自主性を損なわずに、大きな作り直しを防ぎたい。
  背景: 現状は口を出すことをためらい、部下が相談に来るのを待つ。部下は相談に来ず、ずれが最後に判明する。

## Open Questions

- 上司が毎週5分の時間を確保できるか。忙しい週に省かれると、続かない
- 3つの質問で足りるか。仕事の種類によっては、別の質問が必要かもしれない
- 部下が事前に答えを書くことが負担にならないか
- **モックで確かめたいこと**: 部下が3つの質問に答えるのが2分以内で、上司の一言が1分以内で済むか
- **モックで確かめたいこと**: 上司が「ここが違う」を選んだとき、部下が責められたと感じずに「早めにわかってよかった」と感じられるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **続かない** — 忙しい週に省かれる → 間が空く → ずれが溜まる。軽減: 5分に限り、上司が忙しい週は答えへの一言だけで済ませられるようにする
- **評価面談化** — 上司が評価の話を持ち込む → 部下が正直に答えなくなる → 期待合わせの場でなくなる。軽減: 評価には使わない方針を明記し、話題を3つの質問に限る
- **監視の道具化** — 毎週の答えが記録される → 進捗の監視に使われる → 部下が嫌がる。軽減: 履歴は2人だけが見られる設定にする
- **部下だけの負担** — 部下が答えを書く → 上司は見るだけ → 部下だけが気を遣う。軽減: 上司の一言を必須にし、双方の手順にする
