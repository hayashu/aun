# PRD: 計画と実績のずれを区切りごとに残し、自分の「見積もり癖」を見つける見積もり癖ノート（A4xB3-1）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B3（失敗の原因がわからない × 自分で進める道筋を作れない）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は上司との遅れの経緯たどり、版3はチームの実績日数ライブラリを扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

Bさんは、自分で区切りを作って進めるのが苦手で、仕事がよく締め切りに遅れる。上司から「また遅れたね」と言われるが、**なぜ遅れたのかが自分でもわからない**。見積もりが甘かったのか、途中で別の仕事が入ったのか、特定の作業に時間がかかったのか。原因がわからないので、次の仕事でも同じように見積もり、同じように遅れる。Aさんも、上司から遅れの理由を聞かれて答えられず、「計画性がない」と言われたことがある。

**誤解の実態**: Bさんは評価資料を「1週間でできます」と答えたが、2週間かかった。上司に理由を聞かれ、「思ったより時間がかかりました」としか答えられなかった。実は、測定そのものは予定どおり3日で終わっていた。遅れたのは、測定データのグラフ化と資料のまとめに、見積もりの3倍の時間がかかったからだった。Bさんは、毎回同じところ（データのまとめ）で遅れていることに気づいていなかった。Aさんも、調査の仕事で毎回「関係者への確認待ち」で数日止まっていたが、それを見積もりに入れていなかった。

**気づきの実態**: 遅れの原因は、多くの場合、特定の作業の見積もりの甘さか、見積もりに入れていなかった待ち時間にある。そして、同じ人は同じところで遅れる傾向がある。区切りごとに計画と実績を残しておけば、この傾向は見える。2人は計画を立てても実績を残さないので、どこで遅れたかがわからず、傾向にも気づけない。

**練習機会の実態**: タスク管理アプリは予定を並べるが、計画と実績のずれを分析する機能は使われていない。上司との面談でも、遅れは結果として話題になるだけで、原因の分析はされない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。若手の見積もりと実績のずれは、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 遅れの原因を、本人が具体的に説明できる（遅れた仕事のうち、どの区切りで何が原因で遅れたかを本人が一行で書けた割合を効果指標とする）
- 見積もりと実績のずれが小さくなる（仕事ごとの、見積もり日数に対する実績日数の比を効果指標とする）
- 次の見積もりに、自分の癖を反映できる（見積もりのときに、過去の癖を見て日数を調整した割合を効果指標とする）

**Non-Goals**

- 作業時間の細かな記録（区切りごとの日数だけを残し、毎時間の記録は求めない）
- 上司への進捗報告の代替（ノートは本人の振り返りのためのもの）
- 上司との経緯たどり（版2）、チームの実績日数ライブラリ（版3）の範囲

## Proposed Solution / Feature Description

仕事を始めるときに**区切り（測定、まとめ、確認待ちなど）ごとの見積もり日数を書き、区切りが終わるたびに実績日数を一つ入れる**個人向けWebツールを提供する。仕事が終わると、区切りごとのずれを並べて示す。複数の仕事のずれをまとめると、本人がどの種類の区切りで遅れやすいかという「見積もり癖」が見える。

**主要な構成要素**:

- **区切りと見積もり** — 仕事を始めるときに、区切りを3〜5個に分け、それぞれの見積もり日数を書く。区切りの種類（調べる、作る・測る、まとめる、確認を待つ）を選ぶ
- **実績の入力** — 区切りが終わったら、実際にかかった日数を入れる。遅れた区切りには、理由を選択式（思ったより作業が多かった、割り込みが入った、待ちが発生した）で選ぶ
- **ずれの表示** — 仕事が終わると、区切りごとの見積もりと実績を棒で並べ、最も大きくずれた区切りを示す
- **見積もり癖** — 複数の仕事のずれを区切りの種類ごとに集計し、「まとめる作業は見積もりの平均2.5倍かかる」「確認待ちを入れ忘れやすい」のような癖を示す
- **次の見積もりの補助** — 新しい仕事の見積もりを書くときに、癖をもとに「まとめる作業はこれまで2.5倍かかっています」と表示する。日数を決めるのは本人である

## User Stories

- **US-001 なぜ遅れたのか自分でもわからない問題**
  利用者（Bさん）は、仕事が遅れたときに、どの区切りで何が原因で遅れたかを知りたい。それにより、「思ったより時間がかかった」ではなく、具体的な原因を上司に説明し、次に同じところで遅れないようにしたい。
  背景: 現状は計画と実績を残さず、遅れた場所がわからない。毎回同じ作業で遅れていることに気づかないまま、同じ見積もりを繰り返す。

- **US-002 待ち時間を見積もりに入れ忘れる問題**
  利用者（Aさん）は、自分が見積もりに入れ忘れやすいものを知りたい。それにより、毎回「確認待ち」で数日止まって遅れる状態を変えたい。
  背景: 現状は待ち時間を見積もりに入れず、待ちが発生するたびに遅れる。

## Open Questions

- 区切りごとの実績を入れ続けてもらえるか。忙しいときに入力が抜けると、癖が正しく出ない
- 区切りの種類の分け方が、本人の仕事に合うか
- 癖が見えるまでに、いくつの仕事の記録が必要か
- **モックで確かめたいこと**: ずれの表示で、どの区切りで遅れたかがひと目でわかるか
- **モックで確かめたいこと**: 見積もり癖を見て、本人が「自分はここで遅れるのか」と納得し、次の見積もりを変えたくなるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **入力の負担** — 区切りごとに入力する → 面倒になる → 使われなくなる。軽減: 区切りが終わったときに、日数を一つ選ぶだけにする
- **自己批判の強化** — ずれが大きく見える → 自分を責める → 計画を立てること自体を嫌がる。軽減: ずれは「次の見積もりに使える情報」として示し、責める表示にしない
- **見積もりの水増し** — 癖を知る → 見積もりを大きくしすぎる → 上司に疑われる。軽減: 癖は区切りの種類ごとに示し、全体を一律に増やすのではなく、遅れやすい区切りだけを調整するよう促す
- **上司の監視への転用** — 本人の記録を上司が見る → 評価に使われる → 正直に入力しなくなる。軽減: 記録は本人だけが見られる設定にする
