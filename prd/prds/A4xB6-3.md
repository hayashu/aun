# PRD: 注意や助言を「場面・行動・代わりにどうするか」の具体例つきで返すチームのフィードバックの型（A4xB6-3）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B6（失敗の原因がわからない × 具体と抽象を行き来する会話が苦手）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は一人で高さのずれを振り返るシート、版2は2人で置いていかれた地点を指し合うマップを扱う。本PRDは、注意する側の言葉が抽象的すぎて原因が伝わらない問題を、注意の形式を変えることで扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。部門の上司やベテランは、注意や助言を抽象的な言葉で返すことが多い。

部門の注意や助言は、**「もっと主体的に」「視座を上げて」「詰めが甘い」のように抽象的な言葉で返され、受け取った側は何をどう直せばよいかがわからない**。注意する側は、頭の中に具体的な場面を思い浮かべているが、それを言わない。具体的に考える若手や、言葉の裏を読むのに苦労する外国籍の社員ほど、原因を特定できず、同じ注意を繰り返し受ける。

**誤解の実態**: Bさんは期中の面談で、課長から「もう少し主体的に動いてほしい」と言われた。Bさんは「主体的」を、会議で発言を増やすことだと受け取り、次の会議から毎回発言するようにした。半年後の面談でも、同じことを言われた。課長が思い浮かべていたのは、試作の部品の納期が遅れたとき、Bさんが課長に言われるまで代わりの部品を探さなかった場面だった。Aさんも別の面談で「視座を上げて」と言われ、半年間何を変えればよいかわからなかった。

**気づきの実態**: 注意に「どの場面で」「何をしたか」「代わりにどうしてほしかったか」が一つずつ添えられていれば、受け取った側はすぐに直せる。抽象的な言葉は、その具体例のまとめとして後ろに付ければよい。しかし、注意の仕方は上司の癖に任されており、具体例を添える型がない。上司の側も、抽象的な言葉で十分伝わっていると思っている。

**練習機会の実態**: 上司向けの面談研修はあるが、注意を具体的に伝える型を、日常の注意や助言にまで落とした例はない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。同じ注意が繰り返された件数は、部門では記録されていない。

## Goals / Non-Goals

**Goals**

- 注意や助言に、具体的な場面と代わりの行動が添えられる（型で書かれた注意のうち、3項目がそろった割合を効果指標とする）
- 受け取った側が、次に何を直すかを決められる（注意を受けた人が「直す一点がわかった」と答えた割合を効果指標とする）
- 同じ注意の繰り返しが減る（同じ人に同じ言葉の注意が繰り返された回数を効果指標とする）

**Non-Goals**

- 人事評価の仕組みの変更（型は日常の注意と助言に使うもので、評価の制度は変えない）
- 注意の内容の正しさの審査（型は伝え方を整えるもので、注意が妥当かは問わない）
- 一人の振り返り（版1）、2人のマップ（版2）の範囲

## Proposed Solution / Feature Description

チームで使う**フィードバックの型**を、Webの小さな記入画面として提供する。注意や助言をする側は、「場面（いつ・どの件で）」「行動（何をしたか）」「代わりにどうしてほしかったか」の3項目を書き、最後に抽象的なまとめの言葉（「主体的に」など）を添える。受け取った側は「直す一点がわかった／まだわからない」を返し、わからないときは質問を一つ付けられる。

**主要な構成要素**:

- **3項目の記入** — 注意する側が、場面・行動・代わりの行動を一行ずつ書く。抽象的なまとめの言葉は最後に任意で添える。まとめの言葉だけでは送れない
- **言い換えの手がかり** — 注意する側が「主体的に」「視座を上げて」などの抽象的な言葉を書くと、「この言葉を、どの場面のことか一つ思い出してください」と促す
- **受け取った側の返事** — 受け取った側が「直す一点がわかった／まだわからない」を選ぶ。わからないときは質問を一つ書く
- **チームの集計** — チーム全体で、3項目がそろった注意の割合と、「わかった」の割合だけを見せる。誰が誰に何を言ったかは出さない

## User Stories

- **US-001 抽象的な注意を受けて何を直せばよいかわからない問題**
  利用者（Bさん）は、注意を受けたとき、どの場面の何を直せばよいかを知りたい。それにより、「主体的」を自分の解釈で直して半年後に同じ注意を受ける状態を変えたい。
  背景: 現状は注意の言葉が抽象的で、上司が思い浮かべた場面がわからない。

- **US-002 注意の言葉の裏を読めない問題**
  利用者（Aさん）は、「視座を上げて」のような言葉を、具体的な場面とともに受け取りたい。それにより、半年間何を変えればよいかわからない状態を変えたい。
  背景: 現状は抽象的な言葉の裏を推測するしかなく、聞き返すと反抗しているように感じられる。

- **US-003 注意しても伝わらない問題**
  利用者（課長）は、自分の注意が部下に伝わったかを知りたい。それにより、同じ注意を繰り返す手間を減らしたい。
  背景: 現状は抽象的な言葉で伝わったと思い、半年後に同じことを言っている。

## Open Questions

- 上司が、日常の注意まで型に書く手間を負えるか。面談のときだけに限るほうが現実的か
- 書いて残すことで、注意がかえって重く受け取られないか
- チームの集計を、上司が自分への評価と感じないか
- **モックで確かめたいこと**: 抽象的なまとめの言葉だけの注意と、3項目がそろった注意を並べて見たとき、受け取る側が直す一点の見つけやすさの違いを感じられるか
- **モックで確かめたいこと**: 抽象的な言葉を書いたときの「どの場面のことか思い出して」の促しが、注意する側に押しつけがましく感じられないか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **注意する側が使わない** — 書く手間が増える → 口頭の抽象的な注意に戻る → 仕組みが形だけになる。軽減: 3項目は一行ずつに限り、口頭の注意のあとに10秒で書ける画面にする
- **注意が重くなる** — 書いて残る → 受け取る側が記録されたと感じる → 萎縮する。軽減: 記録は2人だけが見られ、一定期間で消える設定にする
- **評価への転用** — 注意の記録が残る → 人事評価に使われる → 正直に書かなくなる。軽減: 人事評価に使わない方針を明記し、チームの集計は割合だけにする
