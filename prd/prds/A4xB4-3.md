# PRD: 分野をまたぐ手戻りを月に一度、責めずに原因を分類し、受け渡しの取り決めに反映する手戻りレビュー会（A4xB4-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B4（失敗の原因がわからない × 専門領域の違いで認識がずれる）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は個人の手戻り経緯マップ、版2は2分野の理解の分かれ目シートを扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがるプロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。Bさんの部署は機械系の社員が多い。

プロジェクトでは、分野をまたぐ手戻りが毎回の試作で起きる。しかし、**手戻りの原因はプロジェクトとして分析されず、個人の間で処理される**。手戻りを起こした担当者が謝り、修正し、終わる。原因が分野間の受け渡しの仕組みにあっても、それは見直されない。若手や分野外の担当者ほど「自分のせいだ」と受け取り、ベテランは「また若手のミスか」と受け取る。同じ種類の手戻りが、試作のたびに繰り返される。

**誤解の実態**: 2回目の試作で基板のコネクタと筐体の開口部が2mmずれた。Bさんは自分の配置ミスとして謝った。3回目の試作では、別の若手の担当者で、基板の高さと筐体のリブが干渉した。これも担当者のミスとして処理された。調整役のAさんが後で並べてみると、どちらも機械側の変更がチャットだけで伝えられ、図面が改版されていなかったことが原因だった。原因は個人のミスではなく、変更の伝え方の仕組みにあった。しかし、それを指摘する場はなかった。

**気づきの実態**: 問題は個人の振り返りだけではない。**手戻りを分野横断で集めて原因を分類する場がない**ことが原因である。手戻りを一つずつ見ると個人のミスに見えるが、複数を並べると、同じ仕組みの問題が繰り返し原因になっていることがわかる。それがわかれば、受け渡しの仕組み自体を直せる。

**練習機会の実態**: プロジェクトの定例会議では進捗と課題が話されるが、手戻りの原因を振り返る時間はない。品質部門の不具合分析は、顧客に影響する大きな不具合だけが対象である。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。プロジェクトの手戻りのうち、仕組みに原因があったものの割合は測られていない。

## Goals / Non-Goals

**Goals**

- 分野をまたぐ手戻りが、プロジェクトとして集められ、原因が分類される（手戻りのうち、レビュー会で扱われた割合を効果指標とする）
- 個人のミスとされていた手戻りのうち、仕組みの原因が見つかる（扱った手戻りのうち、原因に仕組みの要因が含まれた割合を効果指標とする）
- 仕組みの見直しで、同じ種類の手戻りが減る（見直しのあと、同じ種類の手戻りが起きた件数を効果指標とする）

**Non-Goals**

- 責任の追及（誰の手戻りかを問わない）
- 品質部門の不具合分析の置き換え（顧客に影響する不具合は既存の仕組みで扱う）
- 個人の経緯マップ（版1）、2人の理解の並べ合い（版2）の範囲

## Proposed Solution / Feature Description

プロジェクトで**月に一度、30分の「手戻りレビュー会」**を開き、その運営をWebで支える仕組みを提供する。その月に起きた分野をまたぐ手戻りを、担当者の名前を伏せて登録する。レビュー会では、手戻りを原因の分類（見落とし、伝え方、確認の不足、受け渡しの仕組み）ごとに並べ、同じ原因が繰り返されていないかを見る。繰り返されている原因があれば、受け渡しの取り決めを一つ見直す。

**主要な構成要素**:

- **手戻りの登録** — 手戻りが起きたら、何が合わなかったか、関係する分野、原因の候補を登録する。担当者の名前は登録しない。調整役か、当事者のどちらでも登録できる
- **原因の分類** — レビュー会で、各手戻りの原因を4つの分類から選ぶ。複数選んでよい
- **繰り返しの表示** — 原因の分類ごとに、これまでの手戻りの件数を表示する。同じ分類が3件以上あれば、仕組みの見直しの候補として示す
- **取り決めの見直し** — 見直しの候補について、分野間の受け渡しの取り決めを一つ変える（例:「確定した変更は必ず図面を改版する」）。変えた取り決めはプロジェクトの全員に知らせる
- **見直しの効果** — 取り決めを変えたあと、同じ分類の手戻りが減ったかを、次のレビュー会で確かめる

## User Stories

- **US-001 手戻りがすべて個人のミスとして処理される問題**
  利用者（Bさん）は、自分が起こした手戻りの原因が、個人のミスだけでなく仕組みにもあったかを知りたい。それにより、すべてを自分のせいだと受け取って萎縮する状態を変えたい。
  背景: 現状は手戻りが個人の間で処理され、仕組みの原因は見直されない。同じ手戻りが別の担当者で繰り返される。

- **US-002 繰り返される手戻りの共通の原因を指摘する場がない問題**
  利用者（調整役のAさん）は、複数の手戻りに共通する原因を、プロジェクトとして扱いたい。それにより、受け渡しの仕組みを見直したい。
  背景: 現状は共通の原因に気づいても、それを指摘して仕組みを変える場がない。

- **US-003 若手のミスだと思い込む問題**
  利用者（ベテランの担当者）は、若手の手戻りの原因が、自分たちの伝え方にもあったかを知りたい。それにより、「また若手のミスか」という思い込みを確かめたい。
  背景: 現状は手戻りの原因が分析されず、担当者のミスとして受け取られる。

## Open Questions

- 月に一度、30分の時間をプロジェクトの関係者が確保できるか
- 担当者の名前を伏せても、プロジェクトの規模によっては誰の手戻りかわかってしまう
- 原因の分類を、レビュー会の場でどう合意するか
- **モックで確かめたいこと**: 原因の分類ごとの件数を見て、仕組みの見直しが必要な原因がひと目でわかるか
- **モックで確かめたいこと**: 手戻りが個人のミスではなく仕組みの問題として並んだとき、当事者が責められていないと感じられるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **責任追及の場になる** — 手戻りを並べる → 誰の手戻りかを探す → 当事者が萎縮する。軽減: 名前を登録せず、議論は「取り決めをどう変えるか」に限るルールを画面に表示する
- **登録が集まらない** — 手戻りを登録したくない → 件数が少ない → 繰り返しが見えない。軽減: 調整役が登録を担い、当事者の負担をなくす
- **取り決めの増えすぎ** — 毎月取り決めを変える → 受け渡しが複雑になる → 守られなくなる。軽減: 見直しは月に一つまでとし、効果を確かめてから次に進む
- **特定の分野への偏り** — ある分野の伝え方ばかりが問題になる → その分野が反発する → 協力が得られない。軽減: 原因は分野ではなく受け渡しの仕組みとして示す
