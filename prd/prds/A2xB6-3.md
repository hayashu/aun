# PRD: 会議や報告の種類ごとに「結論の高さ」と「詳しさ」を決めておくチームの粒度ガイド（A2xB6-3）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A2×B6（暗黙の期待・ルールがわからない × 具体と抽象を行き来する会話が苦手）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は一人で抽象度を見積もるはしご、版2は依頼の時に粒度の見本を合わせる形を扱う。A2×B1-3（資料ダイエット）は資料の型と枚数を減らす話、本PRDは場ごとに求める抽象度を明文化する話を扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。部門には、朝会、週次の定例、月次の部長会、設計レビューなど、多くの会議と報告の場がある。

会議や報告の場ごとに、**どの抽象度で話せばよいかが決まっているのに、書かれていない**。部長会では結論と判断事項だけを話すのが当たり前で、設計レビューでは測定値まで話すのが当たり前だが、それは長くいる人の頭の中にしかない。具体的に考える若手や、外国籍の社員は、場ごとの高さの違いを、外して注意されることでしか知れない。

**誤解の実態**: Bさんは初めて月次の部長会で報告することになり、設計レビューと同じように、測定条件と波形を5枚の資料で説明した。部長は2枚目で「で、判断してほしいことは何？」と遮った。Bさんは、部長会では結論と判断事項を最初に言うのが当たり前だと知らなかった。逆にAさんは、設計レビューで部長会のように結論だけを話し、「根拠のデータがないと議論できない」と言われた。2人とも、事前に誰からも場ごとの決まりを聞いていなかった。

**気づきの実態**: 場ごとの高さの違いは、長くいる人なら一言で説明できる。「部長会は結論と判断事項を最初の1分で」「設計レビューは数値と条件まで」。しかしそれが書かれていないので、新しく来た人は外して学ぶしかない。抽象的な話を好む上司は、場の高さを言葉にする必要を感じていない。

**練習機会の実態**: 新人研修には会議のマナーがあるが、部門ごとの会議の高さの違いは扱わない。先輩に聞けば教えてもらえるが、何を聞けばよいかがわからない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。会議の場ごとの決まりが明文化されているかは、部門では確かめられていない。

## Goals / Non-Goals

**Goals**

- 会議や報告の場ごとに、求める高さが書かれる（部門の主要な場のうち、粒度ガイドが書かれた割合を効果指標とする）
- 場の高さを外して遮られる場面が減る（初めてその場で報告した人のうち、「高さが合っていなかった」と自己申告した割合を効果指標とする）
- 新しく来た人が、報告の前にガイドを読む（報告の前にガイドを開いた割合を効果指標とする）

**Non-Goals**

- 会議の数や時間の削減（ガイドは場の高さを書くもので、会議の整理はしない）
- 報告の出来の評価（ガイドは事前の手引きで、報告を採点しない）
- 一人のはしご（版1）、2人の見本合わせ（版2）の範囲

## Proposed Solution / Feature Description

部門の会議や報告の場ごとに、**「最初に話す高さ（結論・判断事項・数値）」「詳しさ（何分・何枚・どこまで）」「よくある外し方」の3項目を1枚に書いた粒度ガイド**をチームで作り、共有する仕組みを提供する。報告の予定が入った人には、その場のガイドが届く。場の主催者が年に一度見直す。

**主要な構成要素**:

- **場ごとのガイド** — 場の名前、最初に話す高さ、詳しさ、よくある外し方を1枚に書く。主催者と、その場に長く出ている人が書く
- **高さの図** — 各場を「方針」から「手順」までの高さの帯に並べ、どの場がどの高さで話すかを一目で見せる
- **報告前のお知らせ** — 報告の予定が入った人に、その場のガイドを届ける。初めての人には、過去の良い報告の構成（中身は伏せる）も添える
- **見直しの声** — ガイドを読んだ人が「ここがわからなかった」を匿名で残せる。主催者が年に一度見直す

## User Stories

- **US-001 初めての場で高さを外す問題**
  利用者（Bさん）は、初めて部長会で報告する前に、その場で最初に話す高さを知りたい。それにより、5枚の資料の2枚目で遮られる状態を変えたい。
  背景: 現状は場ごとの決まりが書かれておらず、外して注意されることでしか知れない。

- **US-002 場ごとの違いがわからない問題**
  利用者（Aさん）は、会議によって高さが違うことを、事前に一覧で知りたい。それにより、設計レビューで結論だけを話して「根拠がない」と言われる状態を変えたい。
  背景: 現状は場ごとの違いを、長くいる人だけが知っている。

- **US-003 毎回同じことを注意する問題**
  利用者（部長）は、新しい報告者に場の高さを毎回説明する手間を減らしたい。それにより、会議の時間を判断に使いたい。
  背景: 現状は報告者が変わるたびに、会議の場で遮って説明している。

## Open Questions

- 主催者が、場の高さを言葉にできるか。長くいる人ほど当たり前すぎて書けないことがある
- ガイドが「決まり」として固くなりすぎ、柔軟な報告を妨げないか
- 部門の会議が多い場合、どの場から書くか
- **モックで確かめたいこと**: 高さの図で各場が並んでいるのを見て、新しく来た人が場ごとの違いを一目で理解できるか
- **モックで確かめたいこと**: 報告前に届いたガイドが、1分で読める量に収まっているか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **ガイドが書かれない** — 主催者が忙しい → ガイドが空のまま → 仕組みが形だけになる。軽減: 3項目に限り、「よくある外し方」は過去の会議の様子から一緒に書く
- **型の押しつけ** — ガイドを守ることが目的になる → 場に合わない報告まで型にはめる → 議論が浅くなる。軽減: ガイドは「最初に話すこと」に限り、それ以降は自由にする
- **古いガイド** — 会議の性格が変わる → ガイドが合わなくなる → 読んだ人が外す。軽減: 匿名の声を受けて年に一度見直す
