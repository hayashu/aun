# PRD: 新人の「わからなかった」を集めて部署の略語・規格の手引きに育てる新人目線ログ（A2xB2-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A2×B2（暗黙の期待・ルールがわからない × ハードウェアの知識が足りず焦る）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は本人の前提知識の記録、版2は先輩が聞いてよい質問を示すリストを扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門は機械系の社員が多く、社内規格や図面の読み方、部門独自の略語が前提として会話が進む。

部門の略語や社内規格の使い方は、**長くいる人の頭の中にしかない**。「DR」「ES品」「一般公差は社内規格による」のような言葉は、新しく来た人が毎回つまずくのに、どこにも書かれていない。部門には用語集を作ろうとした過去があったが、ベテランが書いたため、新しい人がつまずく言葉が抜けていた。ベテランには、どの言葉が当然でないのかが見えない。

**誤解の実態**: Bさんは設計会議で「ES品だからDR2までに差し替えて」と言われ、どちらの言葉も知らなかった。調べても社内の略語なので出てこず、期限を取り違えて1週間遅れた。Aさんも図面の注記の意味がわからず、規格書を探すのに半日を使った。同じ年に配属された他の若手も、同じ言葉で同じようにつまずいていた。部門全体では、毎年同じ言葉で、同じ時間が失われている。

**気づきの実態**: つまずいた言葉を最もよく知っているのは、つまずいた本人である。新しく来た人の「わからなかった」を集めれば、ベテランには見えない「当然でない言葉」の一覧ができる。しかし今は、つまずいた本人が一人で調べて終わり、その経験は次の人に渡らない。

**練習機会の実態**: 部門には古い用語集があるが、数年前に作られたまま更新されていない。新人研修は全社共通で、部門の略語は扱わない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。部門の若手が略語や規格でつまずいている時間は測られていない。

## Goals / Non-Goals

**Goals**

- 新しく来た人がつまずく言葉が、部署の手引きに載る（手引きの項目のうち、新人の「わからなかった」から生まれたものの割合を効果指標とする）
- 同じ言葉で毎年つまずく件数が減る（新人が記録した「わからなかった」のうち、手引きにすでに載っていた割合を効果指標とする。この割合が上がれば、手引きが新人の必要に追いついている）
- 手引きが更新され続ける（月あたりの追加・修正件数を効果指標とする）

**Non-Goals**

- 技術の体系的な教材の作成（手引きは略語・規格・社内の呼び方に絞る）
- 新人の理解度の評価（「わからなかった」の数を評価に使うと、記録しなくなる）
- 全社の用語集の統一（部門ごとの言葉の違いを残す）
- 個人の記録（版1）、先輩の質問リスト（版2）の範囲

## Proposed Solution / Feature Description

部署の新しく来た人（配属1年以内、他分野から来た人を含む）が**「わからなかった言葉」を匿名で記録し、ベテランが意味を書き足して手引きに育てる**仕組みを提供する。手引きの項目は、ベテランが思いついた言葉ではなく、新人が実際につまずいた言葉から生まれる。

**主要な構成要素**:

- **わからなかった記録** — 新しく来た人が、つまずいた言葉と出てきた場面を匿名で記録する。誰が記録したかは残さない
- **意味の書き足し** — 記録された言葉は、ベテランに「意味を書いてほしい言葉」として届く。ベテランは一行の意味と、関連する規格や資料の場所を書く
- **手引き** — 意味が書かれた言葉は、分類（略語／規格／図面／工程）ごとの手引きに載る。各項目には「新人が◯人つまずいた」が表示される
- **つまずき数の表示** — 同じ言葉が何人に記録されたかを数え、多い言葉を手引きの上に並べる。新しく来た人は、多くの人がつまずいた言葉から読める
- **配属時の案内** — 新しく配属された人に、手引きの上位20語を案内する。第2段階に置き、現時点のプロトタイプには入っていない

## User Stories

- **US-001 毎年同じ言葉でつまずく問題**
  利用者（Bさん）は、先にこの部署に来た人たちがつまずいた言葉を、最初に知りたい。それにより、略語の意味を取り違えて対応が遅れる事態を避けたい。
  背景: 現状は、つまずいた経験が本人の中で終わり、次の人に渡らない。毎年同じ言葉で同じ時間が失われる。

- **US-002 ベテランが作る用語集に新人の言葉が載らない問題**
  利用者（ベテランの先輩）は、新人が本当につまずいている言葉を知りたい。それにより、自分には当然すぎて見えない言葉の意味を書き足したい。
  背景: 現状はベテランが思いつく言葉で用語集を作り、新人がつまずく言葉が抜ける。

- **US-003 わからなかったことを言いにくい問題**
  利用者（Aさん）は、わからなかった言葉を、名前を出さずに伝えたい。それにより、知らないことを恥ずかしく思わずに、部署の手引きに役立てたい。
  背景: 現状はわからなかったことを人に言いにくく、一人で調べて終わる。

## Open Questions

- ベテランが意味の書き足しに時間を使ってくれるか。書き足しが止まると、記録だけが溜まる
- 匿名にすると、少人数の部署では誰が記録したか推測できてしまう
- 手引きの意味の正確さを誰が確かめるか
- **モックで確かめたいこと**: 手引きで「新人が◯人つまずいた」の表示を見て、新しく来た人が「自分だけじゃない」と安心できるか
- **モックで確かめたいこと**: ベテランが「意味を書いてほしい言葉」の一覧から、1語1分以内で意味を書けるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **書き足しの停滞** — ベテランが忙しい → 意味が書かれない → 手引きが育たない。軽減: 一語一行の意味だけを求め、つまずき数の多い言葉から順に頼む
- **古い情報の放置** — 規格が改定される → 手引きが古いまま → 誤った情報で作業する。軽減: 各項目に最終更新日を表示し、古い項目は印を付ける
- **評価への転用** — 記録の数が見える → 新人の理解度の評価に使われる → 記録しなくなる。軽減: 誰が記録したかを残さない
- **形だけの用語集** — 作った時点で満足する → 更新されない → 以前の用語集と同じ道をたどる。軽減: 新人の記録が続く限り項目が増える仕組みにし、更新件数を振り返りで共有する
