# PRD: 「話が細かすぎる」と言われた会話を振り返り、どこで高さがずれたかを見つける抽象度ずれの振り返りシート（A4xB6-1）

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。2人の上司の課長は、方針や考え方を抽象的な言葉で語ることを好む。

2人は、課長との会話がうまくいかなかったとき、**何が原因だったのかを特定できない**。課長は「話が細かすぎる」「もっと大きく捉えて」と抽象的に注意するので、どの場面の何を直せばよいかがわからない。原因が中身なのか、話の順番なのか、話の高さなのかを切り分けられないまま、次の会話でも同じことが起きる。

**誤解の実態**: Bさんは課長に試作の遅れを報告し、「話が細かすぎる。もっと大きく捉えて」と言われた。Bさんは「細かすぎる」を、資料の枚数が多いことだと受け取り、次の報告で資料を半分にした。しかし課長の反応は同じだった。課長が気にしていたのは枚数ではなく、Bさんが遅れの原因（部品の納期）から話し始め、「全体の日程にどう響くか」という高さの話が最後まで出てこなかったことだった。Bさんは3回同じ注意を受けてから、Aさんに相談したが、Aさんも原因を説明できなかった。

**気づきの実態**: 会話の失敗は、振り返れば「どの高さで始め、どの高さで終わったか」として見える。相手が求めた高さと自分が話した高さを、会話の流れに沿って並べれば、ずれた地点がわかる。しかし2人とも、会話を高さで振り返る手順を持っていない。注意の言葉が抽象的なので、思いつく直し方（枚数を減らす、早口をやめる）を試しては外す。

**練習機会の実態**: 上司に「具体的にどこが細かかったですか」と聞けば答えてくれるかもしれないが、注意された直後に聞き返すのは反抗しているように感じられる。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。同じ注意を繰り返し受けた件数は、社内で記録されていない。

## Goals / Non-Goals

**Goals**

- 会話の失敗を、高さのずれとして振り返れる（シートで振り返った会話の数を効果指標とする）
- 同じ注意を繰り返し受ける回数が減る（同じ言葉で注意された回数の自己申告を効果指標とする）
- 次の会話で直す一点を決められる（振り返りのあとに「次に直す一点」を書いた割合を効果指標とする）

**Non-Goals**

- 上司の注意の正しさの判断（注意が妥当かどうかではなく、原因の候補を見つけることに限る）
- 会話の録音・自動分析（記録すると、相手との関係に影響する。振り返りは本人の記憶から行う）
- 上司・同僚による評価や採点（他人が見る前提にすると、失敗を書けなくなる）

## Proposed Solution / Feature Description

うまくいかなかった会話のあとに、**自分が話した順番を3〜5段に分けて書き、それぞれが「方針・構造・具体策・事実」のどの高さだったかを選び、相手が最初に聞きたかった高さと並べて見る**振り返りシートをWebで提供する。ずれた地点が見えたら、次に直す一点を本人が書く。

**主要な構成要素**:

- **注意の言葉** — 言われた注意をそのまま書く（「細かすぎる」「もっと大きく」など）。注意の言葉ごとに、高さのずれとしての読み方の候補を示す（「細かすぎる」→ 高さが低いまま始めた可能性）
- **話した順番** — 自分が話したことを、話した順に3〜5段に分けて一行ずつ書く
- **高さの印** — 各段に「方針」「構造」「具体策」「事実」のどれかの印を付ける。印は縦の線で結ばれ、話の高さの流れが折れ線のように見える
- **相手が求めた高さ** — 相手が最初に聞きたかったことを一行で推測して書き、その高さを選ぶ。自分の折れ線の横に線で示し、ずれた地点を色で示す
- **次に直す一点** — ずれた地点を見て、次の会話で直す一点を一行で書く（「最初に全体の日程への影響を言う」など）。過去の振り返りを並べ、同じずれが続いているかを見られる

## User Stories

- **US-001 抽象的な注意から原因を特定できない問題**
  利用者（Bさん）は、「細かすぎる」と言われた会話を、話の高さで振り返りたい。それにより、資料の枚数を減らすような外れた直し方を繰り返す状態を変えたい。
  背景: 現状は注意の言葉が抽象的で、思いつく直し方を試しては外し、同じ注意を3回受ける。

- **US-002 後輩の失敗の原因を説明できない問題**
  利用者（Aさん）は、Bさんから相談を受けたとき、一緒にシートを見ながら原因を探したい。それにより、「わからない」としか言えない状態を変えたい。
  背景: 現状は自分も原因を説明する手順を持っていない。

## Open Questions

- 本人の記憶だけで、話した順番を正確に書けるか
- 「相手が求めた高さ」を本人が推測できるか。推測が外れていれば、振り返りも外れる
- 4段の高さで、職場の会話を十分に表せるか
- **モックで確かめたいこと**: 話した順番に高さの印を付けて折れ線のように見たとき、本人が「最初から低いところで話していた」と気づけるか
- **モックで確かめたいこと**: 注意の言葉から高さのずれの読み方の候補が出たとき、本人が納得できるか、決めつけられたと感じるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **原因の取り違え** — 原因が高さ以外（中身の誤り、時機）なのに、高さのずれだと決めつける → 直しても変わらない → ツールへの不信。軽減: 高さ以外の原因（中身・時機・相手の機嫌）も選べるようにする
- **自己批判の強化** — 失敗を振り返り続ける → 自分を責める → 使うのがつらくなる。軽減: 振り返りの最後は必ず「次に直す一点」で終わり、過去の改善も並べて見せる
- **記録の流出** — 上司の注意が書かれている → 他人に見られる → 関係が悪くなる。軽減: 記録は端末の中だけに保存し、共有機能を持たない
