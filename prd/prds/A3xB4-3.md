# PRD: 分野をまたぐ会議に「事前共有」と「言い直し確認」を組み込む進行キット（A3xB4-3）

版: v1（2026-11-22、パイロット） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B4（適切なコミュニケーション方法がわからない × 専門領域の違いで認識がずれる）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は話し手個人の準備、版2は2人の間のずれの可視化を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。Bさんの部署は機械系の社員が多く、電気側の話ができる相手が少ない。

このプロジェクトの週次の設計会議には、**暗黙の進め方**がある。重要な変更は会議の前に関係者へ個別に伝えておく。会議の場では、わからない言葉があっても聞き返さず、後で詳しい人に聞く。結論は口頭で決まり、議事録には結論だけが残る。長くいる日本人社員はこの進め方を自然に身につけている。しかし、AさんとBさんにとっては、どちらも書かれていないルールである。

**誤解の実態**: Bさんは、試作基板の発熱が想定を超えていることを設計会議で報告した。事前に誰にも伝えていなかったため、機械チームのリーダーは「初めて聞いた」という反応になり、「持ち帰って検討」で議題が終わった。会議の司会だったAさんは、この返事を次回までに対応してもらえる意味だと受け取り、議事録に「機械側で検討」と書いた。機械側は、Bさんの使った「ディレーティング」の意味をつかめないまま、優先度の低い話として扱った。2週間後、筐体の金型が予定どおり発注されたことがわかり、通気の変更は次の試作まで持ち越しになった。

**気づきの実態**: 会議のどの時点でも、誰も「ずれている」と言わなかった。機械チームのリーダーは、事前に聞いていないことに不満を持っていたが、それを口にしなかった。Bさんの言葉がわからなかった機械側の参加者も、聞き返さなかった。Aさんは、議事録の「検討」が実際には何を意味するのかを確かめなかった。ずれは個人の能力の問題ではなく、**会議の進め方に確かめる場面が組み込まれていない**ことから生まれている。

**練習機会の実態**: 個人向けの報連相研修を受けても、会議の進め方が変わらなければ、事前共有の段取りは本人任せのままになる。用語集を配っても、会議の場で開かれなければ使われない。会議ルールを文書にしている部署もあるが、守られているかを確かめる手段がなく、形だけになりやすい。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、対策として「コミュニケーションのローコンテキスト化」を掲げている。しかし、同報告書は職場側が具体的に何をどう変えるかの手順を示していない。

## Goals / Non-Goals

**Goals**

- 会議で初めて聞かされる重要な議題が減る（議題のうち、会議の前に関係者へ共有されていたものの割合を効果指標とする）
- 会議の結論が、参加者によって違う意味で受け取られる件数が減る（終わりの言い直し確認で、言い直しが食い違った議題の数と、それが会議後に判明した件数との比を効果指標とする）
- 分野外の言葉を会議の場で確認する頻度が増える（会議中に「用語の確認」として扱われた件数を効果指標とする）

（一つめと三つめは会議の進め方を変える目標で、チームが型を使えば達成できる。二つめは結果であり、型を入れても残るずれがある。言い直しで食い違いが見つかること自体を成果として数える）

**Non-Goals**

- 個人の発言の評価（誰が準備を怠ったかを記録すると、型が監視の道具になる）
- 会議の自動録音・自動議事録（録音を前提にすると率直に話せなくなる。記録は会議の型が求める最小限に限る）
- 全社の会議ルールの策定（一つのチームで試してから広げる。最初から全社に入れると形だけになる）
- 話し手個人の事前準備の支援（版1の範囲）
- 会話中の用語のずれの細かな可視化（版2の範囲）

## Proposed Solution / Feature Description

分野をまたぐ会議の**前・中・後の三か所に、確かめる場面を組み込む**進行キットを提供する。暗黙のルールだった「事前に伝える」「わからない言葉を確かめる」「結論を確かめる」を、会議の型として明文化し、司会者が画面に沿って進めるだけで実行されるようにする。個人に頑張らせるのではなく、確かめることを会議の手順にしてしまうことが目的である。

**主要な構成要素**:

- **事前共有チェック** — 議題を登録するときに、影響を受ける分野と、会議前に伝えた相手を記入させる。未共有の議題には、会議の二日前に登録者へ知らせる。共有されていない議題は、会議では「報告のみ」の扱いにし、その場で結論を求めない
- **用語の事前登録** — 議題の登録者が、説明に使う専門用語を三つまで書き、短い言い換えを添える。会議の画面では、議題の横にこの一覧が表示される。分野外の参加者が、会議中に聞き返さなくても意味を確かめられる
- **会議中の確認カード** — 参加者が手元の画面から「この言葉を確認したい」を匿名で出せる。司会者の画面に件数が表示され、議題の区切りで司会者が取り上げる
- **終わりの言い直し確認** — 各議題の最後に、司会者が関係する分野から一人ずつ指名し、結論を自分の言葉で一文に言い直してもらう。言い直しが食い違ったら、その場で結論を詰め直す。「検討します」のような持ち帰りは、誰が・いつまでに・何を決めるかの形に書き直してから議事録に残す
- **振り返り** — 一か月ごとに、事前共有率、確認カードの件数、言い直しで食い違った議題の数をチームに返す。個人別の数字は出さない
- **会議の型の調整** — チームごとに、どの手順を使うかを選べる。最初は言い直し確認だけから始め、慣れたら他を足す。手順の組み合わせを他チームに共有する機能は第2段階に置き、現時点のプロトタイプには入っていない

## User Stories

- **US-001 会議で初めて聞かされる問題**
  利用者（司会者のAさん）は、会議の前に、重要な議題が関係者へ共有されているかを知りたい。それにより、会議の場で「初めて聞いた」という反応で議題が止まることを防ぎたい。
  背景: 現状は事前共有の段取りが本人任せで、書かれていないルールを知らない人ほど準備なしで議題に出す。会議で保留になり、その間に後工程が進んで、変更が次の機会まで持ち越される。

- **US-002 持ち帰りの結論が違う意味で受け取られる問題**
  利用者（司会者のAさん）は、会議の結論を各分野の参加者が同じ意味で受け取ったかを、会議が終わる前に確かめたい。それにより、「検討」という言葉が別々の意味で議事録に残ることを防ぎたい。
  背景: 現状は結論を口頭で確かめる場面がなく、議事録には「検討」とだけ残る。ずれは後工程で結果としてのみ現れ、その時点で取り返しがつかない。

- **US-003 分野外の言葉を会議中に聞けない問題**
  利用者（報告者のBさん）は、自分の説明に分野外の人がわからない言葉が含まれていたら、会議の場で知りたい。それにより、相手が意味をつかめないまま優先度を下げることを防ぎたい。
  背景: 現状は分野外の参加者が聞き返さず、後で詳しい人に聞く慣習がある。後で聞かれなかった言葉は、わからないまま扱われる。

## Open Questions

- 言い直し確認を入れると会議が長くなる。一議題あたり何分までなら受け入れられるか。長すぎれば省かれ、短すぎれば形だけになる
- 事前共有を「済み」と記入させても、本当に共有したかは確かめられない。自己申告のままでよいか、共有された側の確認を取るか
- 司会者が型を守らなければ、キットは機能しない。司会者の負担をどこまで画面に肩代わりさせられるか
- 「報告のみ」の扱いにすると、急ぎの議題が遅れる。緊急時の例外をどう設けるか
- **モックで確かめたいこと**: 司会者の画面で、議題ごとの事前共有の状態、用語一覧、確認カードの件数がひと目でわかり、会議を止めずに進められるか
- **モックで確かめたいこと**: 終わりの言い直し確認で、食い違いが見つかったときに結論を詰め直す流れが自然に回るか（「持ち帰り」を「誰が・いつまでに・何を」に書き直せるか）

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **形骸化** — 手順が増える → 忙しい週に省かれる → 守られないルールが一つ増える。軽減: 最初は言い直し確認だけから始め、チームが選んで手順を足す形にする
- **監視の道具化** — 事前共有率や確認件数が記録される → 個人の評価に使われる → 正直に記入しなくなる。軽減: 個人別の数字を出さず、チーム単位の数字だけを返す
- **外国籍社員だけのための仕組みと見られる** — 特定の人のための配慮に見える → 周りが面倒がる → 本人が気まずくなる。回避: 分野をまたぐ全員の会議の型として導入し、誰のためかを名指ししない
- **言い直しで責められる** — 言い直しが食い違う → 理解できていない人として扱われる → 言い直しを嫌がる。軽減: 食い違いは結論の書き方の問題として扱い、議事録の書き直しで解消する
- **緊急時の遅れ** — 未共有の議題は報告のみ → 急ぎの判断が一週遅れる → 現場から反発が出る。軽減: 司会者の判断で例外にできる経路を用意し、例外の件数も振り返りに出す
