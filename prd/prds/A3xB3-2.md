# PRD: 部下が仕事に青・黄・赤の信号を付け、黄と赤には上司が15分の相談枠を返す進捗の信号合図（A3xB3-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B3（適切なコミュニケーション方法がわからない × 自分で進める道筋を作れない）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は本人の報告の下書き、版3はチームの朝会の型を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

遅れや詰まりを伝えるのは、部下にとって難しい。どう切り出せばよいか、どこまで説明すればよいか、上司の時間を取ってよいのか。**伝え方がわからないので、部下は言い出すきっかけを待ち続ける**。一方、上司は部下が困っていれば言ってくるだろうと思っている。上司から「どう？」と聞くと、部下は反射的に「大丈夫です」と答えてしまう。結果として、遅れは大きくなってから見つかる。

**誤解の実態**: Bさんはノイズ対策の評価で、測定器の不調から作業が遅れていた。課長は廊下で「評価、どう？」と聞いた。Bさんは、廊下で悪い知らせを長々と話すのは失礼だと思い、「大丈夫です、進めています」と答えた。1週間後、遅れが隠せなくなって報告すると、課長は「この前聞いたときに言ってくれれば」と言った。Bさんは「あの場では言えなかった」と思った。Aさんも、詰まっていることを相談したかったが、課長が忙しそうでタイミングがつかめなかった。

**気づきの実態**: 部下が遅れを言い出せないのは、伝え方の型がなく、伝える場もないからである。上司の「どう？」は、部下にとって状況を説明する場ではなく、挨拶に近い。もし、部下が言葉で説明しなくても、状況を一目で伝えられる合図があれば、上司は早く気づける。そして上司のほうから相談の時間を提案すれば、部下は切り出す必要がなくなる。

**練習機会の実態**: 部門の進捗管理は、月次の報告会で数字を報告する形で、日々の状況を伝える手段はない。チャットで報告することもできるが、悪い知らせを文章で書くのは、口頭以上に難しいと感じる人もいる。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。部下の遅れが上司に伝わるまでの日数は、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 遅れや詰まりが、上司に早く伝わる（仕事に黄または赤が付いてから、上司が相談の時間を提案するまでの日数を効果指標とする）
- 部下が言葉で切り出さなくても、状況を伝えられる（仕事のうち、信号が週に一度以上更新された割合を効果指標とする）
- 遅れを伝えることへのためらいが減る（「困っていることを伝えやすい」の自己申告を効果指標とする）

**Non-Goals**

- 進捗の細かな数値管理（信号は3段階だけで、進捗率は求めない）
- 部下の評価（赤の数を評価に使わない）
- 本人の報告の下書き（版1）、チームの朝会（版3）の範囲

## Proposed Solution / Feature Description

部下が自分の仕事に**青（予定どおり）・黄（遅れそう、または詰まり気味）・赤（遅れている、または助けが必要）の信号を付け**、上司がそれを一覧で見られる仕組みを提供する。黄か赤が付くと、上司に知らせが届き、上司は**15分の相談枠を部下に提案する**。部下は言葉で切り出さなくても、信号を変えるだけで状況を伝えられ、相談のきっかけは上司から来る。

**主要な構成要素**:

- **信号の更新** — 部下は、自分の仕事ごとに信号を選ぶ。黄と赤のときだけ、理由を選択式（測定器の不調、情報待ち、技術的に詰まった、など）で選ぶ。説明文は求めない
- **上司の一覧** — 上司は、部下の仕事と信号を一覧で見られる。黄と赤は上に並ぶ
- **相談枠の提案** — 黄か赤が付くと、上司に知らせが届く。上司は、空いている15分の時間帯を部下に提案する。部下は選ぶだけで相談の時間が決まる
- **相談のメモ** — 相談のあと、決まったこと（期限の延長、手伝い、優先度の変更など）を一行で残す。信号は部下が更新する
- **信号の履歴** — 仕事ごとに、信号がどう変わったかを見られる。黄が長く続いた仕事は、上司が気づけるように印を付ける

## User Stories

- **US-001 廊下で聞かれて「大丈夫です」と答えてしまう問題**
  利用者（Bさん）は、言葉で説明しなくても、自分の仕事が遅れそうなことを上司に伝えたい。それにより、「大丈夫です」と答えたまま遅れが大きくなる事態を避けたい。
  背景: 現状は悪い知らせを伝える場も型もなく、上司の「どう？」に反射的に「大丈夫」と答える。遅れは隠せなくなってから見つかる。

- **US-002 部下の困りごとに気づけない問題**
  利用者（課長）は、部下が困っていることを、部下が言い出す前に知りたい。それにより、自分から相談の時間を提案し、遅れが大きくなる前に手を打ちたい。
  背景: 現状は部下が言ってくるのを待ち、「どう？」と聞いても本当の状況はわからない。

## Open Questions

- 部下が正直に黄や赤を付けるか。赤を付けることに抵抗を感じないか
- 上司が知らせを受けて、実際に相談枠を提案するか。上司が忙しいと、知らせが放置されないか
- 信号の更新を、部下が習慣にできるか
- **モックで確かめたいこと**: 部下が信号を黄に変えるのが、10秒以内で気軽にできるか
- **モックで確かめたいこと**: 上司から相談枠の提案が届いたとき、部下が「自分から言い出さなくてよかった」と感じられるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **青ばかりになる** — 赤を付けるのが怖い → 全部青にする → 合図の意味がなくなる。軽減: 黄を「遅れそう」と広く定義し、赤より付けやすくする。赤の数を評価に使わないと明記する
- **上司が反応しない** — 知らせが届いても忙しい → 相談枠を提案しない → 部下が失望する。軽減: 黄が3日続いたら、上司に再度知らせる
- **監視の道具化** — 信号の一覧が見える → 上司が細かく管理する → 部下が嫌がる。軽減: 信号は3段階だけにし、進捗率や作業時間は求めない
- **会話が減る** — 信号で済ませる → 直接話す機会が減る → 関係が冷える。軽減: 黄と赤のときは必ず15分の相談枠を持つ形にし、信号は会話の入口に留める
