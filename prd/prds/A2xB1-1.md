# PRD: 部署の資料の「暗黙の型」を先に見つけて、作り直しを減らす資料チェッカー（A2xB1-1）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A2×B1（暗黙の期待・ルールがわからない × やりたいものづくりができない）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は依頼者と作成者の間、版3はチームの資料ルールを扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門の業務の多くは会議資料のパワーポイント作成で、2人とも、本当はものづくりにもっと時間を使いたいと思っている。

部門の資料には、**書かれていない型**がある。1枚目に結論を置く、数字には必ず前回比を付ける、部長向けは3枚以内、色は2色まで、などである。長くいる社員は過去の資料を見て自然に身につけているが、誰も文書にしていない。2人はこの型を知らないまま資料を作り、何度も作り直す。作り直しに時間を取られ、ものづくりに使える時間がさらに減る。

**誤解の実態**: Bさんは評価結果の報告資料を10枚で作った。課長から「部長向けだから3枚にして」と言われ、作り直した。次に「結論が最後にあるとわからない」と言われ、また作り直した。最後に「前回の数字がないと比べられない」と言われた。3回の作り直しで、Bさんは丸2日を使った。その間、試作基板の評価に使うはずだった時間がなくなった。Aさんも同じ週、色を多く使った資料を「見づらい」と言われて作り直していた。

**気づきの実態**: 指摘はいつも一つずつ、作り終えたあとに来る。最初から型を知っていれば一度で済んだ。しかし2人は、何を知らないのかがわからないので、事前に聞くこともできない。課長の側も、型が当然すぎて、最初に伝えるという発想がない。

**練習機会の実態**: 社内に資料のテンプレートはあるが、色とロゴを決めているだけで、構成や枚数の決まりは書かれていない。過去の資料は共有フォルダにあるが、どれが「良い例」なのかはわからない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。資料の作り直しにかかる時間は、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 資料の作り直しの回数が減る（1つの資料が提出から承認までに差し戻された回数を効果指標とする）
- 資料作成にかかる時間が減り、ものづくりに使える時間が増える（週あたりの資料作成時間の自己申告を効果指標とする）
- 部署の資料の暗黙の型を、本人が説明できるようになる（型のチェック項目のうち、本人が事前に満たせた割合を効果指標とする）

**Non-Goals**

- 資料の自動作成（資料を自動で作ると、型を知らないまま提出することになる）
- 文章の添削・敬語の修正（既存サービスの領域。扱うのは構成と型である）
- 唯一の正しい型の提示（部署や相手によって型は違う）
- 依頼者との合意（版2）、チームの資料ルール（版3）の範囲

## Proposed Solution / Feature Description

部署の過去の資料と、過去に受けた指摘をもとに、**部署の暗黙の型をチェック項目として本人の手元にためる**個人向けWebツールを提供する。資料を作る前に、提出先（課長／部長／他部署）と目的を選ぶと、該当するチェック項目が出る。本人は作る前に項目を確かめ、作り終えたあとにもう一度確かめる。指摘を受けたら、その内容を新しいチェック項目として追加する。

**主要な構成要素**:

- **提出先と目的の選択** — 資料の提出先と目的（報告／相談／承認）を選ぶ。型は提出先によって変わるため、最初に選ばせる
- **型のチェック項目** — 選んだ提出先に対して、「1枚目に結論」「数字に前回比」「3枚以内」のような項目を出す。最初は一般的な候補を出し、使ううちに本人の部署の項目に置き換わる
- **指摘の記録** — 受けた指摘を一行で書き、どの提出先・目的のときに言われたかを選ぶ。記録した指摘は、次から同じ条件のチェック項目に加わる
- **良い例の印** — 共有フォルダの過去の資料のうち、「一度で通った」資料に本人が印を付けて、参考として残せる
- **時間の記録** — 資料1つにかかった時間と、作り直しの回数を記録する。減っていく様子を本人に返し、ものづくりに回せた時間として見せる

## User Stories

- **US-001 指摘が一つずつ後から来る問題**
  利用者（Bさん）は、資料を作る前に、提出先に合わせた暗黙の型を知りたい。それにより、3回作り直して丸2日を使い、ものづくりの時間を失う事態を避けたい。
  背景: 現状は型を知らないまま作り、指摘は作り終えたあとに一つずつ来る。作り直しのたびに、他の作業の時間が削られる。

- **US-002 同じ指摘を何度も受ける問題**
  利用者（Aさん）は、一度受けた指摘を、次の資料で忘れずに守りたい。それにより、同じ理由で作り直す事態を避けたい。
  背景: 現状は指摘をどこにも残しておらず、次に同じ条件の資料を作るときには忘れている。

## Open Questions

- 最初の一般的なチェック項目が、本人の部署の型とずれていたら、かえって混乱しないか
- 指摘を記録するのは、言われた直後の気分が沈んでいるときである。そのときに書く気になるか
- **モックで確かめたいこと**: 提出先を選んでチェック項目が出る流れが、資料を作り始める前の1分で済むか
- **モックで確かめたいこと**: 指摘を記録すると次のチェック項目に加わる様子が、「同じ指摘を受けなくなる」という手応えにつながるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **一般論の押し付け** — 一般的な型を示す → 部署の型と合わない → 信頼を失う。軽減: 本人の記録した指摘を優先して表示し、一般的な項目は少しずつ置き換える
- **資料作りの効率化だけで終わる** — 資料作成が速くなる → 浮いた時間に別の資料を頼まれる → ものづくりの時間は増えない。軽減: 浮いた時間を本人に見せ、上司との相談の材料にできるようにする（版3との組み合わせ）
- **記録の負担** — 指摘のたびに書く → 面倒になる → 使われなくなる。軽減: 指摘の一行と提出先の選択だけで記録できるようにする
- **型への過剰適応** — 型を守ることに集中する → 中身が薄くなる → 本来の目的を見失う。軽減: チェック項目は構成と形式に限り、中身の評価はしない
