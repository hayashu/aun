# PRD: 2つの分野が「いま動かせるもの・動かせないもの」を見せ合う制約交換シート（A1xB4-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B4（相手の真意がわからない × 専門領域の違いで認識がずれる）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は個人が相手の分野の事情を学ぶツール、版3は設計レビューの運用を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがるプロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。Bさんの部署は機械系の社員が多い。

電気と機械の担当者が設計の変更を相談するとき、**それぞれが「自分の側で動かせないもの」を言葉にしない**。言葉にしないのは、隠しているからではない。自分の分野では当たり前すぎて、相手が知らないとは思わないからである。そのため返事は「なんとかならない？」「ちょっと難しいかな」のような遠回しな言葉になり、相手はその裏の事情を読めない。

**誤解の実態**: Bさんは試作基板の発熱対策として、筐体に通気口を追加してほしいと機械の担当者に頼んだ。機械の担当者は「電気側でなんとかならないかな」と答えた。機械の担当者にとって、金型が前週に発注済みであることは当然の前提で、言うまでもないことだった。Bさんにとっては、基板を改版できるのはあと1回だけという事情が当然の前提だった。2人はお互いの事情を知らないまま、「相手の側で何とかしてくれる」と期待して2週間が過ぎた。

**気づきの実態**: どちらの分野にも、いま動かせないもの（金型、改版回数、試験の日程）と、まだ動かせるもの（材料の選定、部品の定数、ソフトの設定）がある。この一覧を相談の最初に見せ合っていれば、「通気口は次の試作まで無理、そのかわり内部のヒートシンクは追加できる」という具体的な話に進めた。現状は、それぞれの事情が頭の中にしかないため、遠回しな言葉の応酬になる。

**練習機会の実態**: 設計変更の申請書はあるが、変更を頼む側の書式で、頼まれる側の事情を書く欄はない。日程表はプロジェクト全体の節目だけを示し、各分野の「いつまでなら変えられるか」は載っていない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。分野をまたぐ設計変更で、事情の行き違いによる手戻りがどれだけあるかは測られていない。

## Goals / Non-Goals

**Goals**

- 分野をまたぐ相談で、相手の事情を知らずに待つ期間が短くなる（相談から、両分野の対応方針が決まるまでの日数を効果指標とする）
- 遠回しな断りが、事情を含んだ具体的な返事に置き換わる（相談のうち、制約交換シートで「動かせない理由」が示された割合を効果指標とする）
- 代わりの案が相談の場で出る（相談のうち、「動かせるもの」から代わりの案が出た割合を効果指標とする）

**Non-Goals**

- 設計変更の正式な承認手続きの置き換え（承認は既存の手続きで行う。シートは承認の前の相談に使う）
- どちらの分野が対応すべきかの自動判定（判断は当事者と上長が行う）
- 隣の分野の事情を個人で学ぶこと（版1）、設計レビューの運用（版3）の範囲

## Proposed Solution / Feature Description

分野をまたぐ設計の相談をするとき、双方が**「いま動かせないもの（理由と、いつから動かせるか）」と「まだ動かせるもの」をそれぞれ書き、並べて見せ合う**Webのシートを提供する。並べてから話すことで、遠回しな言葉を使わなくても、どこで折り合えるかが見える。

**主要な構成要素**:

- **相談の起点** — 頼む側が、何を変えたいかと、その理由を一行で書く
- **制約の記入** — 双方が、この件に関係する「動かせないもの」と「動かせるもの」を、分野ごとの候補（金型、材料、改版、部品、試験日程など）から選んで書く。動かせないものには理由と「いつから動かせるか」を添える。相手の記入は、自分が書き終えるまで見えない
- **並べて表示** — 双方の記入を左右に並べる。片方の「動かせるもの」で、もう片方の困りごとを解決できそうな組み合わせに印を付ける
- **方針のメモ** — 話し合って決めた方針（どちらが何をするか）を一行で残す。決まらなければ、誰が・いつまでに決めるかを書く
- **よくある制約の候補** — 分野ごとの「動かせないもの」の候補を、過去のシートから増やしていく。第2段階に置き、現時点のプロトタイプには固定の候補だけを入れる

## User Stories

- **US-001 相手の「なんとかならない？」の裏が読めない問題**
  利用者（Bさん）は、相談の相手が何を動かせて何を動かせないのかを、相談の最初に知りたい。それにより、相手の側で対応してもらえると期待して2週間待つ事態を避けたい。
  背景: 現状は相手の事情が言葉にされず、遠回しな返事の真意がわからない。事情がわかるのは後工程が進んでからである。

- **US-002 自分の事情を言葉にしていない問題**
  利用者（機械の担当者）は、自分の分野では当然の事情を、相手にわかる形で伝えたい。それにより、相手が無理な期待をして待ち続けることを避けたい。
  背景: 現状は当然すぎる事情を言葉にせず、「難しいかな」で済ませている。

## Open Questions

- 相手の記入を見る前に自分の記入を終える仕組みが、急ぎの相談で手間にならないか
- 「動かせないもの」を書くことが、言い訳の一覧に見えないか
- 調整役のAさんが、両者の記入を見て話をまとめる役になるのか、それとも当事者だけで使うのか
- **モックで確かめたいこと**: 双方の記入が並んだとき、「ここなら折り合える」という組み合わせがひと目でわかるか
- **モックで確かめたいこと**: 制約の候補から選ぶ形で、自分の分野の当然の事情を書き出せるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **言い訳の一覧になる** — 動かせないものばかり書く → 互いに押し付け合う → 相談が止まる。軽減: 「動かせるもの」の記入を必須にし、少なくとも一つは書くようにする
- **書く手間** — 相談のたびにシートを書く → 面倒になる → 口頭に戻る。軽減: 候補から選ぶ形にし、1分で書ける量に絞る
- **事情の書き漏れ** — 当然すぎて書かない → 結局ずれが残る → 信頼を失う。軽減: 分野ごとの候補を一覧で示し、該当するかを一つずつ確かめる形にする
- **責任の押し付け** — 方針のメモが記録に残る → 後で責任追及に使われる → 正直に書かなくなる。軽減: メモは当事者と調整役だけが見られる設定にする
