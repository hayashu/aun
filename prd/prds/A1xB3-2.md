# PRD: 依頼を受けたら「いつ・何を・どこまで」を復唱して確かめる依頼の復唱シート（A1xB3-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B3（相手の真意がわからない × 自分で進める道筋を作れない）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は受け手が一人で期限を推測する個人ツール、版3はチームの依頼の仕組みを扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

依頼する側の課長は、部下の自主性を大事にしたいと考えている。だから「いい感じに進めておいて」「急ぎじゃないから」と細かく指定せずに頼む。しかし課長の頭の中には、使う予定の会議や、期待する完成度がある。**依頼の言葉には、その期待が含まれていない**。受け手は期待を読み取れず、自分で区切りを作るのも苦手なまま仕事を始める。

**誤解の実態**: 課長はBさんに「急ぎじゃないから、ノイズ対策の案をまとめておいて」と頼んだ。課長は2週間後の部長報告に使うつもりで、たたき台が1週間後にあれば十分だと思っていた。Bさんは急ぎではないと受け取り、他の資料作成を優先した。10日後に課長から声がかかり、徹夜で仕上げた。課長は「自主性に任せたら、ぎりぎりになった」と感じ、Bさんは「急ぎじゃないと言われた」と感じた。

**気づきの実態**: 依頼の瞬間に、受け手が「いつ・何を・どこまで」を一度言い直していれば、ずれはその場で見つかった。課長も、言い直しを聞けば「いや、1週間後にたたき台がほしい」と言えたはずである。しかし、依頼を言い直すことは、受け手には「理解力がないと思われる」不安があり、依頼者には「細かく管理しているように見える」不安がある。どちらからも言い出しにくい。

**練習機会の実態**: 報連相の研修では「復唱する」ことを教えるが、何をどう復唱すればよいかの型はない。口頭の復唱は記録に残らず、後で「言った・言わない」になる。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。依頼の場面で、どう言葉を補えばよいかの具体的な型は示されていない。

## Goals / Non-Goals

**Goals**

- 依頼の期限と完成度の食い違いが、依頼の時点で見つかる（復唱シートのうち、依頼者が内容を修正した割合を効果指標とする。修正があること自体を、ずれを早く見つけた成果として数える）
- 締め切り直前の頼み直しが減る（依頼の最終期限の3日前より後に、期限や内容が変更された件数を効果指標とする）
- 途中確認の時点が、依頼の時点で決まる（復唱シートのうち、途中確認の日付が入った割合を効果指標とする）

**Non-Goals**

- 依頼の自動作成（依頼者の言葉を機械が補うと、依頼者の真意から離れる）
- 部下の進捗の監視（途中確認は合意した1回に限り、日々の進捗を追わない）
- 受け手一人での期限の推測（版1）、チームの依頼ルール（版3）の範囲

## Proposed Solution / Feature Description

依頼を受けたら、受け手が**「いつまでに・何を・どの程度の完成度で・途中確認はいつ」の4項目を復唱シートに書いて依頼者に送り、依頼者が確認または修正する**Webツールを提供する。復唱する行為を「理解力の不足」ではなく「手順」にすることで、受け手も依頼者も気まずさなく期待をそろえられる。

**主要な構成要素**:

- **復唱シート** — 受け手が4項目を選択式と一行で書く。完成度は「たたき台／一次案／ほぼ完成」から選ぶ。依頼の言葉もそのまま書き写す
- **依頼者の確認** — 依頼者は「このとおり」か「ここが違う」を選び、違う項目だけを直す。直すのは1分以内で終わる量に限る
- **使い道の欄** — 依頼者に任意で「何に使うか（会議名など）」を書いてもらう。受け手は使い道から優先度を判断できる
- **途中確認の通知** — 合意した途中確認の日に、双方へ知らせる。受け手は一次案を見せ、依頼者は方向だけを確認する
- **復唱の履歴** — 依頼者と受け手が、過去の依頼と修正の履歴を見られる。どの項目がずれやすいかが、2人の間でわかる

## User Stories

- **US-001 「急ぎじゃない」の期限が食い違う問題**
  利用者（Bさん）は、依頼を受けたその場で、期限と完成度を依頼者と確かめたい。それにより、10日後に「明後日使いたい」と言われる事態を避けたい。
  背景: 現状は依頼の言葉に期限が含まれず、受け手は言葉どおりに後回しにする。ずれは本当の期限の直前に判明し、そのときには準備の時間がない。

- **US-002 細かく指定すると管理しているように見える問題**
  利用者（課長）は、部下の自主性を損なわずに、自分の期待する時期と完成度を伝えたい。それにより、任せた仕事がぎりぎりになる事態を避けたい。
  背景: 現状は細かく指定することをためらい、期待を言葉にしないまま依頼する。

## Open Questions

- 小さな依頼にも復唱シートを使うか。毎回使うと手間になり、使わないと大事な依頼でも使い忘れる。目安の基準（作業が3日以上かかるもの、など）が必要か
- 依頼者が「このとおり」を形式的に押すだけにならないか
- 口頭で依頼されたあとに、受け手がシートを書く運用で十分か
- **モックで確かめたいこと**: 受け手が復唱シートを2分以内で書け、依頼者が1分以内で確認できるか
- **モックで確かめたいこと**: 依頼者が項目を修正したとき、受け手が「間違えた」ではなく「そろった」と感じられる見せ方になっているか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **形骸化** — 依頼者が中身を見ずに確認する → ずれが残る → 元の問題に戻る。軽減: 完成度と使い道の欄を必ず見せ、確認画面で4項目を並べる
- **手間の増加** — 依頼のたびにシート → 面倒になる → 使われなくなる。軽減: 依頼の言葉を書き写すだけで4項目の初期値が入るようにする
- **監視ツールへの転用** — 履歴が残る → 上司が部下の遅れを記録する道具になる → 受け手が嫌がる。軽減: 履歴は2人だけが見られる設定にし、チームの集計には使わない
- **受け手だけの負担** — 復唱するのは受け手 → 依頼者は言葉を補わないまま → 受け手だけが気を遣う。軽減: 使い道の欄を依頼者側の手順として組み込む
