# PRD: 若手が上層の方針を具体例に、ベテランが若手の試作報告を一行の意味に翻訳し合う部署の抽象⇔具体翻訳ワークショップ（A5xB6-3）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A5×B6（安心して練習・相談できる場所がない × 具体と抽象を行き来する会話が苦手）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は一人の往復ドリル、版2は役割交代の練習ペアを扱う。A1×B6-3（方針カード）は方針を出す側が例を添える仕組み、本PRDは受け取る側と出す側が一緒に翻訳を練習する場を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。部門には、抽象的な方針を語るベテランや管理職と、具体的な作業をする若手がいる。

部門では、**上から降りてくる抽象的な方針と、下から上がる具体的な報告が、互いに翻訳されないまま行き交っている**。若手は方針を自分の作業に落とせず、ベテランは若手の報告から「つまり何が起きているか」を読み取るのに苦労する。抽象と具体を行き来する練習は、どちらの側にも必要だが、部署として練習する場はない。

**誤解の実態**: 部門長が期初に「今期は、壊れにくさで勝つ」と方針を示した。Bさんは、自分の回路設計の何を変えればよいかわからず、従来どおりの設計を続けた。一方、Bさんが月次の報告で「ESD試験で8kVのときにリセットがかかる個体が3台中1台」と書いたとき、課長はそれが方針の「壊れにくさ」に直結する話だと気づかず、報告は読み流された。方針と報告が同じ「壊れにくさ」の話をしていたのに、どちらの側も翻訳できなかった。Aさんは調整役として両方を見ていたが、つなぐ言葉を持っていなかった。

**気づきの実態**: 方針を若手が具体例に翻訳し、若手の報告をベテランが一行の意味に翻訳する練習を、部署で一緒に行えば、両方の側が相手の高さを知れる。若手は「方針はこういう作業のことか」を知り、ベテランは「この数字は方針のこの部分の話か」を知る。翻訳を見せ合うこと自体が、失敗しても困らない練習になる。しかし、部署には方針説明会と月次報告はあっても、両方をつなぐ場はない。

**練習機会の実態**: 部門の勉強会は技術の話題が中心で、方針や報告の伝え方を扱ったことはない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。方針と現場の報告がつながっているかは、部門では確かめられていない。

## Goals / Non-Goals

**Goals**

- 部署で、抽象と具体を翻訳し合う練習が定期的に行われる（月に一度のワークショップの開催回数と参加者数を効果指標とする）
- 若手が、方針を自分の作業に落とせる（ワークショップのあとに「方針と自分の作業のつながりがわかった」と答えた若手の割合を効果指標とする）
- ベテランが、若手の報告と方針のつながりに気づける（報告に「方針のこの部分」と付けられた件数を効果指標とする）

**Non-Goals**

- 方針の中身の議論（ワークショップは翻訳の練習で、方針の良し悪しは扱わない）
- 参加者の翻訳の採点（翻訳は答えが一つではない。比べるのは違いで、点数ではない）
- 一人のドリル（版1）、2人の練習（版2）の範囲

## Proposed Solution / Feature Description

部署で月に一度30分、**若手とベテランが組になって、方針と報告を翻訳し合うワークショップ**を開き、その進行をWebで支える仕組みを提供する。前半15分は、部門の方針の一文を若手が具体例3つに翻訳し、ベテランが「自分ならこう翻訳する」と並べる。後半15分は、若手の最近の報告の一つをベテランが一行の意味に翻訳し、若手が「自分が伝えたかったこと」と並べる。

**主要な構成要素**:

- **今月の題材** — 主催者が、部門の方針の一文と、若手の最近の報告から一つ（本人の同意を得て）を題材に選ぶ
- **下げる翻訳（前半）** — 若手が方針の一文を具体例3つに翻訳し、ベテランも同じ方針を翻訳する。画面に2人の翻訳が並び、重なりとずれが見える
- **上げる翻訳（後半）** — ベテランが若手の報告を一行の意味に翻訳し、若手が「伝えたかったこと」を一行で書く。2人の一行が並ぶ
- **翻訳の棚** — ワークショップで出た翻訳を、方針ごとに棚にためる。新しく来た人も、方針の具体例と、報告の読み方を見られる
- **進行の画面** — 前半・後半の時間と、今の段を大きく表示する。主催者が一人で進められる

## User Stories

- **US-001 方針を自分の作業に落とせない問題**
  利用者（Bさん）は、方針の一文を自分で具体例に翻訳し、ベテランの翻訳と比べたい。それにより、方針と関係なく従来どおりの作業を続ける状態を変えたい。
  背景: 現状は方針が抽象的で、自分の回路設計の何を変えればよいかわからない。

- **US-002 若手の報告から意味を読み取れない問題**
  利用者（課長）は、若手の具体的な報告を、方針とのつながりの一行に翻訳する練習をしたい。それにより、方針に直結する報告を読み流さないようにしたい。
  背景: 現状は報告の数字が方針のどの部分の話かに気づけない。

- **US-003 調整役として方針と現場をつなげない問題**
  利用者（Aさん）は、方針と報告の翻訳の棚を使って、両方をつなぐ言葉を持ちたい。それにより、調整役として話をつなげるようになりたい。
  背景: 現状は両方を見ているのに、つなぐ言葉を持っていない。

## Open Questions

- 月に一度30分の時間を、部署の業務として確保できるか
- 若手の報告を題材にすることに、本人が抵抗を感じないか
- ベテランが、自分の翻訳を若手と並べることに抵抗を感じないか
- **モックで確かめたいこと**: 若手とベテランの翻訳が並んだ画面を見て、双方が「相手はこの高さで考えていたのか」と気づけるか
- **モックで確かめたいこと**: 前半・後半の進行の画面だけで、主催者が一人で30分を回せるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **ベテランの指導の場になる** — ベテランの翻訳が正解として扱われる → 若手が萎縮する → 練習にならない。軽減: 前半は若手、後半はベテランが先に書き、どちらの翻訳も「一つの読み方」として並べる
- **時間の確保** — 業務が忙しい → ワークショップが流れる → 仕組みが止まる。軽減: 30分に限り、既存の月次会議の後ろにつなげる
- **報告の題材化への抵抗** — 自分の報告が皆の前で翻訳される → 恥ずかしい → 題材が集まらない。軽減: 題材は本人の同意を得て選び、名前を伏せられるようにする
