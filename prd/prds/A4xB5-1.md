# PRD: 試す前に「予想」を書き、結果とのずれから原因を考える小さな実験ノート（A4xB5-1）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B5（失敗の原因がわからない × 気軽に試して失敗できる場所がない）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は先輩との15分の実験レビュー、版3は部署の実験デーを扱う。A3×B5（失敗の伝え方）とは異なり、本セルは「試した結果から原因を学ぶこと」を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門には試作機や評価ボードがあるが、若手が自由に触れる機会は少ない。

2人は、たまに評価ボードを触る機会を得ても、**試した結果がうまくいかなかったときに、なぜうまくいかなかったのかがわからない**。何を変えたらどうなるかを考えずに試すので、うまくいかなくても、原因の手がかりが残らない。試す機会が少ないうえに、一回一回の試しから学べることも少ない。Bさんはもともとハードウェアを壊すことへの不安があり、学べないまま失敗すると、ますます試すのが怖くなる。

**誤解の実態**: Bさんは評価ボードで、ノイズを減らすためにコンデンサの値を変えてみた。しかしノイズは減らず、むしろ少し増えた。Bさんは「失敗した」と思い、元に戻して終わった。なぜ増えたのかはわからなかった。実は、変えたコンデンサの値がノイズの周波数と合っておらず、別の周波数で共振を起こしていた。試す前に「この値ならこの周波数のノイズが減るはず」と予想を書いていれば、結果とのずれから原因を考える手がかりになった。Aさんも、評価の設定をいくつか変えて試したが、何をどう変えたかを記録しておらず、うまくいった設定を再現できなかった。

**気づきの実態**: 試した結果から学ぶには、試す前に「何を変えて、どうなると予想するか」を書いておくことが欠かせない。予想と結果がずれたところが、原因を考える入口になる。2人は、試すことそのものに精一杯で、予想を書く習慣がない。原因の手がかりがないので、失敗はただの失敗で終わり、次の試しにつながらない。

**練習機会の実態**: 実験ノートの書き方は、大学の研究で教わることがあるが、職場の小さな試しで使う習慣はない。先輩に聞いても、「経験だよ」と言われることが多い。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。若手が試した結果から学べているかは、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 試した結果がうまくいかなくても、原因の手がかりが残る（試しのうち、予想と結果のずれから原因の推測が一つ以上書けた割合を効果指標とする）
- うまくいった試しを再現できる（ノートに記録した試しのうち、後で再現できた割合を効果指標とする）
- 試すことへの怖さが和らぐ（「失敗しても学べると思える」の自己申告を効果指標とする）

**Non-Goals**

- 技術的な正解の提示（ツールは原因の考え方を支えるだけで、技術の答えは出さない）
- 研究用の実験ノートの置き換え（職場の小さな試しのためのもの）
- 先輩との実験レビュー（版2）、部署の実験デー（版3）の範囲

## Proposed Solution / Feature Description

試す前に、**「何を変えるか」「どうなると予想するか」「なぜそう予想するか」を一行ずつ書き、試したあとに結果を書くと、予想とのずれを示して原因の推測を促す**個人向けWebツールを提供する。うまくいかなかった試しも、予想とのずれがあれば学びの記録になる。

**主要な構成要素**:

- **試す前の予想** — 変えるもの（部品の値、設定など）、予想する結果、そう予想する理由を一行ずつ書く。理由が書けなければ「わからない」でよい
- **結果の記録** — 試したあと、実際の結果を書く。測定値があれば入れる。写真を一枚添付できる
- **ずれの表示** — 予想と結果を並べ、ずれがあれば強調する。「予想どおり」「予想より良い」「予想と違う」から選ぶ
- **原因の推測** — 予想と違った場合に、「予想の理由のどこが違っていたか」を考えさせる。よくある原因の考え方（前提が違っていた、別の要因があった、測り方が違っていた）を候補で示す
- **次の一手** — 原因の推測をもとに、次に何を試すかを一行書く。試しが一つの流れとしてつながる
- **試しの一覧** — 過去の試しを、変えたもの、結果、原因の推測とともに一覧で見られる。うまくいった設定を再現できる

## User Stories

- **US-001 うまくいかなかった試しから何も学べない問題**
  利用者（Bさん）は、試す前に予想を書き、結果とのずれから原因を考えたい。それにより、「失敗した」で終わらせず、次に何を試せばよいかを見つけたい。
  背景: 現状は予想を書かずに試し、うまくいかなくても原因の手がかりが残らない。学べない失敗が重なり、試すことが怖くなる。

- **US-002 うまくいった試しを再現できない問題**
  利用者（Aさん）は、何をどう変えたかを記録し、うまくいった設定を後で再現したい。それにより、同じ試しを一からやり直す手間をなくしたい。
  背景: 現状は試した内容を記録せず、うまくいった設定がわからなくなる。

## Open Questions

- 試す前に予想を書くことが、試す気軽さを損なわないか
- 予想の理由が書けない場合（まったくわからない場合）、どう支えるか
- **モックで確かめたいこと**: 予想を書いてから試し、結果とのずれが強調される流れで、「失敗」が「学び」に変わる感覚が生まれるか
- **モックで確かめたいこと**: 原因の推測の候補を見て、本人が自分で原因を考えようと思えるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **記録の負担** — 毎回予想を書く → 面倒になる → 試すこと自体が減る。軽減: 予想は一行ずつ三つに限り、1分で書ける量にする
- **原因の思い込み** — 候補から原因を選ぶ → 確かめずに決めつける → 誤った学びになる。軽減: 原因は「推測」として残し、次の一手で確かめる流れにする
- **研究ノートとの誤認** — 堅い実験ノートに見える → 気軽な試しに使われない → 差別性を失う。回避: 項目を少なくし、スマートフォンで書ける形にする
- **安全の軽視** — 試すことを促す → 危険な試しをする → 事故が起きる。軽減: 電源や高電圧に関わる試しは、既存の安全手順に従うことを表示する
