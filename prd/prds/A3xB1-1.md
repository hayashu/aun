# PRD: 「やりたいこと」を業務とのつながりで組み立て、出す相手と時期を決める提案ビルダー（A3xB1-1）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B1（適切なコミュニケーション方法がわからない × やりたいものづくりができない）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は上司との1on1で引き出す質問カード、版3は部署の公式な提案の場を扱う。A1×B1（返事の真意を読む）とは異なり、本セルは「提案の出し方」を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門の業務の多くは会議資料のパワーポイント作成で、実際に手を動かして作る機会は少ない。

2人とも、ものづくりをしたいという希望を持っている。しかし、**その希望をどう出せば通るのかがわからない**。誰に先に話すか、いつ話すか、どう業務とつなげて話すか。この組み立てがわからないので、希望は「やりたいです」という気持ちの表明で終わり、上司には業務の都合と関係のない個人的な希望として受け取られる。

**誤解の実態**: Bさんは、課の忘年会の席で課長に「もっと手を動かす仕事がしたいです」と伝えた。課長は「そうか、考えておくよ」と答えたが、それきりだった。課長にとって、それは雑談の中の個人的な希望で、業務として何かを決める話ではなかった。Aさんは、繁忙期の真っ最中に、評価治具を自作したいと課長に提案した。課長は忙しさから「今はちょっと」と答えた。Aさんの提案は、評価の工数を減らす内容で、課にとっても利点があった。しかし、その利点は伝わらなかった。

**気づきの実態**: 提案が通らなかったのは、内容ではなく出し方の問題だった。業務の課題とつなげて話す、繁忙期を避ける、正式な場（1on1や面談）で出す、先に係長に相談しておく。こうした組み立てを知っていれば、2人の提案は違う受け取られ方をした。しかし、2人はその組み立てを知らず、何がまずかったのかもわからない。

**練習機会の実態**: 提案の出し方を教わる機会はない。社内の企画提案の研修は、大きな事業企画を対象としており、「自分が手を動かしたい」という小さな提案には使えない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。若手のものづくりの希望が、出し方の問題で通らなかった件数は測られていない。

## Goals / Non-Goals

**Goals**

- ものづくりの希望が、業務の提案として受け取られる（提案のうち、上司から具体的な返事（可否、条件、時期）が返ってきた割合を効果指標とする）
- 提案を出す前に、出し方を組み立てられる（提案のうち、相手・時期・業務とのつながりを決めてから出した割合を効果指標とする）
- 実際にものづくりの機会が増える（提案が通り、手を動かす仕事についた件数を効果指標とする）

**Non-Goals**

- 提案書の自動作成（本人が組み立てることが目的で、文書の代行はしない）
- 上司の判断を変えること（判断は上司のもので、ツールは出し方を整えるだけである）
- 上司との1on1の仕組み（版2）、部署の提案の場（版3）の範囲

## Proposed Solution / Feature Description

ものづくりの希望を、**「業務の課題」「自分がやること」「課にとっての利点」「必要な時間」の4つに分けて組み立て、出す相手と時期を決める**個人向けWebツールを提供する。組み立てたあと、最初の一言の下書きを複数出す。気持ちの表明を、業務の提案に変える。

**主要な構成要素**:

- **やりたいことの入力** — 手を動かしてやりたいことを一行で書く
- **業務とのつながり** — 「いま課で困っていること」「それが解決するとどうなるか」を本人に答えさせる。答えに詰まったら、よくある業務の課題（評価の工数、試作の待ち時間、外注費など）を候補で示す
- **出す相手と順序** — 誰に先に話すか（係長、課長、関係する他部署）を選ばせる。いきなり課長に出すか、先に係長に相談するかを、本人の職場の様子から決める
- **出す時期と場** — 繁忙期を避けるか、1on1や面談で出すか、雑談で出すかを選ばせる。それぞれの場で、提案がどう受け取られやすいかを示す
- **最初の一言の下書き** — 組み立てをもとに、最初の一言の候補を複数出す。一つを選んで、本人の言葉に直させる
- **提案の振り返り** — 提案を出したあと、相手の反応を記録する。通った提案と通らなかった提案の組み立ての違いを、本人に返す

## User Stories

- **US-001 希望が雑談の中の個人的な話で終わる問題**
  利用者（Bさん）は、ものづくりの希望を、業務の提案として上司に伝えたい。それにより、「考えておくよ」で終わらず、具体的な返事をもらいたい。
  背景: 現状は希望を気持ちとして表明し、上司には業務と関係のない話として受け取られる。返事は来ず、希望は忘れられる。

- **US-002 利点のある提案が時期のせいで通らない問題**
  利用者（Aさん）は、提案を出す時期と場を選び、課にとっての利点が伝わる形で出したい。それにより、繁忙期に出して「今はちょっと」で終わる事態を避けたい。
  背景: 現状は思いついたときに提案し、時期と場を考えない。内容の利点は、相手の忙しさに隠れて伝わらない。

## Open Questions

- 業務とのつながりを本人が見つけられない場合、どう支えるか。つながりが見つからない希望は、提案にならないのか
- 「先に係長に相談する」のような順序は職場ごとに違う。本人の職場の様子をどう取り込むか
- **モックで確かめたいこと**: 4つの要素に分けて組み立てる流れが、本人にとって「気持ちを提案に変えられた」と感じられるか
- **モックで確かめたいこと**: 出す時期と場の選択肢を見て、提案の受け取られ方の違いを想像できるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **業務に寄せすぎる** — 業務の利点ばかりを考える → 本人のやりたいことから離れる → 意欲が下がる。軽減: 最初に書いた「やりたいこと」を常に画面に表示し、離れていないかを本人が確かめられるようにする
- **組み立ての型の押し付け** — 一つの組み立て方を正解として示す → 職場に合わない → かえって外す。軽減: 出す相手と時期は選択肢として示し、振り返りで本人の職場に合う組み立てを学ぶ
- **提案疲れ** — 組み立てても通らない → 本人が落ち込む → 提案をやめる。軽減: 通らなかった提案の振り返りで、次に変えられる点を一つ示す
- **文化的な単純化** — 「日本の職場では根回しが必要」と一般化する → 偏見を強める。軽減: 根回しは選択肢の一つとして示し、本人の職場の傾向を振り返りから学ぶ
