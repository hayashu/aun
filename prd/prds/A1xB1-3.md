# PRD: 保留には「理由と期限」を必須にする、ものづくり時間の申請制度（A1xB1-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B1（相手の真意がわからない × やりたいものづくりができない）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は本人が返事を読み解く個人ツール、版2は提案者と上司の間の返事の形を扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門の業務の多くは会議資料のパワーポイント作成で、実際に手を動かして作る機会は少ない。

部門には「若手が手を動かす機会を増やしたい」という方針がある。しかし、それを実現する**手続きがない**。ものづくりをしたい人は、上司に個別に頼むしかない。上司は業務の都合を見ながらその場で返事をし、多くの場合「考えておく」で終わる。どの申し出が通り、どれが保留され、なぜなのかは、どこにも残らない。

**誤解の実態**: Bさんは課長に試作基板の評価をやりたいと申し出て、「落ち着いたらやろうか」と言われた。Aさんは治具の改善を申し出て、「前向きに考えておく」と言われた。2人とも許可と受け取って待った。同じ時期に、別の課の若手は部長に直接頼んで、評価業務を任されていた。3か月後、BさんとAさんの件は外注と見送りになっていた。2人は、自分たちの頼み方が悪かったのか、課長の判断なのか、部門の方針なのかがわからなかった。

**気づきの実態**: 個人の頼み方の問題に見えるが、実際には**返事の基準と期限が部門として決まっていない**ことが原因である。上司ごとに返事の仕方が違い、保留に期限がない。だから、言葉の真意を読む力がある人ほど得をし、読めない人ほど待たされる。外国籍社員や若手のように、暗黙の読み方に慣れていない人に不利が集まる。

**練習機会の実態**: 部門には業務改善提案の制度があるが、提案するのは改善のアイデアであって、「自分が手を動かす時間」ではない。ものづくりの時間を申し出る正式な経路はない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、対策として職場側の「ローコンテキスト化」を掲げている。部門内で、ものづくりの申し出がどれだけ保留のまま消えているかは測られていない。

## Goals / Non-Goals

**Goals**

- ものづくりの申し出が、期限のない保留のまま消える件数が減る（申し出のうち、期限内に「承認／条件付き承認／見送り（理由付き）」のいずれかで決着した割合を効果指標とする）
- 申し出が通る基準が、部門の誰にでも見えるようになる（「何があれば承認されるか」を説明できると答えた若手の割合を効果指標とする）
- 若手が実際に手を動かす時間が増える（承認されたものづくり時間の合計を効果指標とする）

（一つめと二つめは制度で直接届く。三つめは予算や業務量にも左右されるため、天井がある）

**Non-Goals**

- 申し出の承認の自動化（判断は上司と部門のもので、制度は判断の期限と形を決めるだけである）
- 個人の成果評価への組み込み（ものづくり時間を評価に使うと、申請が義務になる）
- 全社への一斉導入（一つの部門で試し、基準の作り方を固めてから広げる）
- 個人の返事の読み解き（版1）、提案者と上司の間の返事の形（版2）の範囲

## Proposed Solution / Feature Description

部門単位で、**ものづくり時間（月あたり上限を決めた業務時間）の申請と承認の流れ**を提供する。申請には、上司が決められた期限（例: 2週間）内に返事をしなければならず、保留にする場合は理由と次の判断日の記入を必須にする。期限を過ぎた申請は部門長の一覧に上がる。返事を「察する」必要をなくし、制度として決着させる。

**主要な構成要素**:

- **申請フォーム** — やりたいこと、月あたりの時間、使う設備、業務とのつながりを一枚で書く。資料の作成は求めない
- **返事の期限** — 申請ごとに返事の期限が付き、期限の数日前に上司へ知らせる。期限を過ぎると部門長の一覧に表示される
- **保留の書式** — 保留にする場合は、理由の分類（予算／設備／時期／業務量）と次の判断日の記入を必須にする。「考えておく」を制度上で選べないようにする
- **承認基準の公開** — 部門として、どんな申請が通りやすいか（業務とのつながり、設備の空き、時間の上限）を公開する。過去の承認例と見送り例を、本人の名前を伏せて載せる
- **部門の一覧** — 部門長が、申請の件数、決着までの日数、保留の理由の内訳を見られる。課ごとの偏りがあれば見える
- **成果の共有** — 承認されたものづくりの結果を、月一回の短い発表で共有する。第2段階に置き、現時点のプロトタイプには入っていない

## User Stories

- **US-001 保留が期限なく続く問題**
  利用者（Bさん）は、ものづくりの申し出に、決められた期限内に決着した返事をもらいたい。それにより、許可だと思って何か月も待ち、後で外注されていたと知る事態を避けたい。
  背景: 現状は保留に期限がなく、返事の真意を読めない人ほど長く待つ。気づいたときには機会が別に移っている。

- **US-002 何が通るのかわからない問題**
  利用者（Aさん）は、どんな申し出なら承認されるのかを、事前に知りたい。それにより、頼み方や相手の読み方ではなく、内容で判断されたい。
  背景: 現状は承認の基準が上司の頭の中にしかなく、直接頼むのがうまい人だけが機会を得ている。

- **US-003 申し出の状況がわからない問題**
  利用者（部門長）は、部門のものづくりの申し出がどれだけ放置されているかを知りたい。それにより、方針と実態のずれを直したい。
  背景: 現状は申し出が口頭で行われ、どこにも記録が残らない。

## Open Questions

- 月あたりの時間の上限をどう決めるか。少なすぎれば意味がなく、多すぎれば業務が回らない
- 保留の理由を必須にすると、上司が最初から見送りを選ぶようにならないか
- 承認基準を公開すると、基準に合わせた形だけの申請が増えないか
- **モックで確かめたいこと**: 上司の返事の画面で、「考えておく」に相当する選択肢がないことが、返事のしにくさより決めやすさにつながるか
- **モックで確かめたいこと**: 部門長の一覧で、放置されている申請と課ごとの偏りがひと目でわかるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **形骸化** — 申請が手間 → 若手が使わない → 口頭の頼み事に戻る。軽減: フォームを一枚に絞り、資料の添付を求めない
- **上司の負担増** — 期限が付く → 上司が追い立てられる → 制度に反発する。軽減: 期限を業務量に合わせて部門ごとに設定できるようにする
- **見送りの増加** — 理由が必須 → 面倒な保留より見送りを選ぶ → 機会がかえって減る。軽減: 見送りの件数と理由も部門長の一覧に出し、偏りを見えるようにする
- **評価への転用** — 承認時間が記録される → 人事評価に使われる → 申請が義務化する。軽減: 評価に使わない方針を制度の文書に明記する
- **特定の人のための制度と見られる** — 外国籍社員への配慮に見える → 周囲が使わない → 本人が浮く。回避: 部門の全員が使う制度として導入し、対象を名指ししない
