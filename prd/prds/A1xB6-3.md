# PRD: 方針を伝えるときに「具体例を1つ・やらないことを1つ」添えるチームの方針カード（A1xB6-3）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B6（相手の真意がわからない × 具体と抽象を行き来する会話が苦手）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は一人で具体例を作るノート、版2は2人で具体例をすり合わせるカードを扱う。A2×B3-3（進め方ガイド）は完了の基準を決める話、本PRDは方針の言葉の意味を例で固定する話を扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。部門長や課長は、期初の方針を「顧客起点で」「スピード重視」「シンプルに」といった抽象的な言葉で示す。

部門の方針は、**抽象的な言葉だけで伝えられ、その言葉が具体的に何を指すのかが、チームの中で人ごとに違う**。方針を出す側は、言葉の裏に具体的な場面を思い浮かべているが、それを書かない。受け取る側は、自分の経験から具体例を当てはめ、それぞれ違う方向に動く。

**誤解の実態**: 部門長は期初に「今期はスピード重視」と方針を示した。Bさんは試作の評価項目を減らして早く次に進むことだと受け取り、評価を一部省いた。機械チームのベテランは、図面の承認を早めることだと受け取った。Aさんは、会議の時間を短くすることだと受け取った。半年後、評価を省いたことで不具合が後工程で見つかり、部門長は「スピードとは品質を落とすことではない」と言った。誰も、方針の具体例を聞いていなかった。

**気づきの実態**: 方針の言葉に「たとえばこういうこと」と「これはやらない」が一つずつ添えられていれば、受け取る側の解釈の幅は狭まる。とくに「やらないこと」は、抽象的な言葉の境目を示す。しかし、方針の伝え方は出す側に任されており、具体例を添える決まりはない。外国籍の社員や、具体的に考える若手ほど、解釈の幅に迷う。

**練習機会の実態**: 方針説明会はあるが、質疑の時間は短く、「具体的には？」と聞く人はほとんどいない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。方針の解釈がチーム内でずれた件数は、記録されていない。

## Goals / Non-Goals

**Goals**

- 方針に、具体例とやらないことが添えられる（方針カードのうち、両方が書かれた割合を効果指標とする）
- 方針の解釈のずれが減る（方針説明の1か月後に、メンバーが自分の解釈を書いたときの一致度を効果指標とする）
- 方針について質問しやすくなる（方針カードに付いた質問の数を効果指標とする）

**Non-Goals**

- 方針そのものの良し悪しの議論（カードは伝え方を整えるもので、方針の中身を問わない）
- メンバーの理解度の評価（解釈を書いてもらうのは、ずれを見るためで、点数を付けない）
- 一人のノート（版1）、2人のカード（版2）の範囲

## Proposed Solution / Feature Description

部門やチームの方針を、**「方針の言葉・具体例を1つ・やらないことを1つ」の3行で書く方針カード**として共有する仕組みを提供する。メンバーは、方針カードに匿名で質問を付けられ、出した側は具体例を追加できる。1か月後に、メンバーが自分の解釈を一行で書き、ずれを見る。

**主要な構成要素**:

- **方針カード** — 方針を出す側が、方針の言葉、具体例を1つ、やらないことを1つ、の3行で書く。3行がそろわないと公開できない
- **匿名の質問** — メンバーが、方針カードに匿名で「これは方針に入りますか」と質問を付けられる。出した側が「入る／入らない」で答え、答えは具体例として追加される
- **解釈の確認** — 1か月後に、メンバーが「この方針で自分がやったこと」を一行で書く。チームの回答が並び、方針を出した側がずれを見られる
- **方針の一覧** — 部門の方針カードが一覧で見える。新しく来た人も、過去の具体例ごと読める

## User Stories

- **US-001 方針の言葉を人ごとに違う意味で受け取る問題**
  利用者（Bさん）は、方針の具体例とやらないことを知ったうえで、自分の作業を決めたい。それにより、方針と違う方向に進んで後から指摘される状態を変えたい。
  背景: 現状は「スピード重視」を自分の解釈で進め、評価を省いて後工程で不具合が出た。

- **US-002 方針説明で質問しにくい問題**
  利用者（Aさん）は、方針の範囲を匿名で確かめたい。それにより、説明会で手を挙げられないまま迷う状態を変えたい。
  背景: 現状は質疑の時間が短く、「具体的には？」と聞く人がいない。

- **US-003 方針が伝わったかわからない問題**
  利用者（部門長）は、自分の方針がチームにどう受け取られたかを知りたい。それにより、半年後にずれに気づく状態を変えたい。
  背景: 現状は方針の解釈を確かめる手段がない。

## Open Questions

- 方針を出す側が、毎回「やらないこと」を書けるか。書くと方針の幅を狭めると感じないか
- 匿名の質問が、批判の場にならないか
- 解釈の確認を、メンバーが面倒に感じないか
- **モックで確かめたいこと**: 方針の言葉に具体例とやらないことが並んだカードを見て、受け取る側が「これなら迷わない」と感じるか
- **モックで確かめたいこと**: 1か月後の解釈の一覧で、方針を出した側がずれに気づけるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **形だけのカード** — 3行が義務になる → 意味のない具体例が書かれる → 解釈のずれが減らない。軽減: 匿名の質問への答えを具体例として足していく形にし、カードを育てる
- **方針を出す側の負担** — 書く手間が増える → 方針カードが作られない → 仕組みが止まる。軽減: カードは3行に限り、書き方の例を示す
- **評価への転用** — 解釈の一覧が残る → メンバーの理解度の評価に使われる → 正直に書かなくなる。軽減: 解釈は名前を出さずに並べる
