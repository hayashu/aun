# PRD: 仕事の種類ごとの「完了の基準」と「相談のルール」をチームで明文化する進め方ガイド（A2xB3-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A2×B3（暗黙の期待・ルールがわからない × 自分で進める道筋を作れない）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は本人の完了条件の計画、版2は上司との週次の期待合わせを扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

チームには、仕事の進め方について**誰も書いていないルール**がある。調査は「3案に絞って推奨を付ける」まで、評価は「測定条件と再現性を書く」まで。詰まったら「半日以上悩まずに聞く」、方向が決まったら「一度見せる」。長くいる人は自然に守っているが、新しく来た人は外して指摘されるまで知らない。さらに、自分で区切りを作るのが苦手な人は、ルールを知らないと終わりの見えないまま仕事を続けてしまう。

**誤解の実態**: Bさんは電源ICの候補調査で20個の候補を3週間かけて調べ、「3つでよかった、早く見せてほしかった」と言われた。Aさんは評価で2日間詰まったまま悩み、「なんで早く言わなかったの」と言われた。同じ年に他の課でも、新しく来た人が同じ指摘を受けていた。課長たちは、指摘のたびに同じことを説明していた。チーム全体では、同じルールを知らないことで、毎年同じ時間が失われている。

**気づきの実態**: 問題は個人が知らないことだけではない。**ルールが暗黙のままであるため、新しく来た人は外すまで知りようがない**。課長たちは、自分たちのルールがチームの外から見えないことに気づいていない。ルールを書けば、新しく来た人は最初から知ることができ、課長たちは同じ説明を繰り返さずに済む。

**練習機会の実態**: 部門の業務マニュアルは、手続き（申請、購買、安全）を書いたもので、仕事の進め方の基準は書かれていない。新人研修でも扱わない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。進め方のルールを知らないことによる手戻りは、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 進め方のルールを知らないことによる指摘が減る（新しく来た人が受けた、完了の基準や相談のタイミングについての指摘の件数を効果指標とする）
- チームの暗黙のルールが文書になる（仕事の種類ごとに、完了の基準と相談のルールが書かれた割合を効果指標とする）
- 課長たちが同じ説明を繰り返さずに済む（「同じ説明をした」と感じた回数の自己申告を効果指標とする）

**Non-Goals**

- 業務マニュアルの全面改定（手続きのマニュアルはそのまま残し、進め方の基準だけを足す）
- 唯一の正しい進め方の強制（基準は目安であり、仕事によって変えてよい）
- 個人の進め方の評価（基準に沿っているかを評価に使わない）
- 本人の計画（版1）、上司との期待合わせ（版2）の範囲

## Proposed Solution / Feature Description

チームで**仕事の種類ごとの「完了の基準」と「相談のルール」を書き出し、一つのガイドにまとめる**仕組みを提供する。最初はチームの数人が集まり、よくある仕事の種類（調査、評価、設計、資料）ごとに、暗黙のルールを書き出す。新しく来た人が外したルールや、課長が同じ説明を繰り返したルールを、ガイドに追加していく。

**主要な構成要素**:

- **進め方ガイド** — 仕事の種類ごとに、完了の基準（どこまでやれば終わりか）、相談のルール（詰まったら何時間で聞くか、どの段階で誰に見せるか）を書いた一覧。各ルールには、なぜそうするのかの理由を一行添える
- **書き出しワーク** — チームで30分集まり、「新しく来た人に一番よく言うこと」を付箋のように書き出す画面。書き出したものを仕事の種類ごとに分類し、ガイドの項目にする
- **指摘からの追加** — 課長が新しく来た人に進め方の指摘をしたら、その内容をガイドへの追加として提案できる。同じ指摘を繰り返さないための仕組みである
- **仕事を受けたときの表示** — 仕事を渡すときに、その種類のガイドの項目を受け手に表示する
- **見直しの記録** — ガイドの各項目に、最後に見直した日と、何度参照されたかを表示する。古くなった項目は印を付ける

## User Stories

- **US-001 進め方のルールを外して初めて知る問題**
  利用者（Bさん）は、仕事を受けたときに、その種類の仕事の完了の基準と相談のルールを知りたい。それにより、3週間かけて「3つでよかった」と言われる事態を避けたい。
  背景: 現状はルールが暗黙で、外して指摘されるまで知りようがない。指摘は仕事の最後に来る。

- **US-002 同じ説明を何度も繰り返す問題**
  利用者（課長）は、新しく来た人に毎回同じ進め方を説明する代わりに、チームのガイドを示したい。それにより、自分の時間を節約し、説明の漏れも防ぎたい。
  背景: 現状は新しく来た人ごとに、外したあとで同じ説明をしている。

- **US-003 なぜそのルールなのかわからない問題**
  利用者（Aさん）は、進め方のルールに従うだけでなく、その理由を知りたい。それにより、ルールが合わない仕事のときに、自分で判断できるようになりたい。
  背景: 現状はルールの理由が説明されず、指摘をそのまま受け入れるしかない。

## Open Questions

- チームの数人が書き出しワークに30分を使ってくれるか
- ガイドの基準が、仕事によって合わないときにどう扱うか。「目安」であることをどう伝えるか
- ガイドを課ごとに作るか、部門で一つにするか。課ごとにルールが違う場合がある
- **モックで確かめたいこと**: 書き出しワークの画面で、チームのメンバーが暗黙のルールを書き出しやすいか
- **モックで確かめたいこと**: 仕事を受けたときに表示されるガイドの項目を見て、受け手が「最初に知れてよかった」と感じられるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **形骸化** — ガイドを作って満足する → 更新されない → 古いルールが残る。軽減: 指摘からの追加を手順にし、見直しの日付を表示する
- **規則の押し付け** — ガイドが規則として扱われる → 柔軟な判断ができなくなる → 仕事に合わない進め方を強いられる。軽減: 各ルールに理由を添え、目安であることを明記する
- **評価への転用** — ガイドに沿っているかが評価に使われる → 守ることが目的になる → 本来の仕事の質が下がる。軽減: 評価に使わない方針を明記する
- **特定の人のためのガイドと見られる** — 外国籍社員や若手への配慮に見える → ベテランが参加しない → 書き出しが進まない。回避: チーム全員の進め方の共有として導入する
