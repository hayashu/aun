# PRD: 月に半日、失敗を前提に試して「予想・結果・原因の推測」を発表し合う部署の実験デー（A4xB5-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B5（失敗の原因がわからない × 気軽に試して失敗できる場所がない）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は本人の実験ノート、版2は先輩との実験レビューを扱う。A3×B5-3（失敗共有会）は起きてしまった失敗の共有を扱い、本PRDは試す場そのものと原因を皆で考えることを扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門には試作機や評価ボードがあるが、若手が自由に触れる機会は少ない。

部門では、**試すことは業務の成果につながる場合にだけ認められる**。成果につながらない試し、うまくいくかわからない試しをする時間はない。そのため、若手が試す機会はほとんどなく、たまに試す機会があっても、失敗は許されない雰囲気がある。うまくいかなかったときの原因を考える時間もない。試す機会がないので失敗から学ぶ経験もなく、失敗の原因がわからないまま、試すことがますます怖くなる。

**誤解の実態**: Bさんはノイズ対策の評価で、コンデンサの値を変えてノイズを増やしてしまい、原因がわからないまま元に戻した。業務の締め切りがあり、原因を考える時間はなかった。Aさんも、評価の設定を試してみたかったが、業務の成果に直結しない試しはしにくかった。部門のベテランは、若い頃は試作が多く、失敗しながら原因を考える時間があったと話す。今の若手には、その時間がない。

**気づきの実態**: 問題は個人の学び方だけではない。**失敗を前提に試し、原因を考える時間が、業務の中に用意されていない**ことが原因である。成果を求められない試しの時間があれば、若手は安心して試せる。そして、試した結果を皆で見て原因を考えれば、ベテランの考え方を若手が学べる。

**練習機会の実態**: 部門の研修は、決められた手順をなぞる実習で、失敗しながら原因を考える経験にはならない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。部門の若手が業務外で試す時間は測られていない。

## Goals / Non-Goals

**Goals**

- 若手が、失敗を前提に試す時間を持てる（実験デーに参加した若手の数を効果指標とする）
- 試した結果の原因を、皆で考える経験が増える（実験デーで発表された試しのうち、原因の推測が議論された割合を効果指標とする）
- 試すことへの怖さが和らぐ（参加者の「失敗しても学べると思える」の自己申告を効果指標とする）

**Non-Goals**

- 業務の成果を出すこと（実験デーの試しは成果を求めない）
- 試しの採点や競争（うまくいったかどうかを競わない）
- 本人の実験ノート（版1）、先輩との実験レビュー（版2）の範囲

## Proposed Solution / Feature Description

部署で**月に一度、半日の「実験デー」**を設け、その運営をWebで支える仕組みを提供する。実験デーでは、若手もベテランも、業務と関係なく試したいことを試す。試す前に「何を変えて、どうなると予想するか」を登録し、終わりの1時間で「予想・結果・原因の推測」を一人3分で発表する。うまくいかなかった試しほど、皆で原因を考える材料になる。

**主要な構成要素**:

- **試しの登録** — 実験デーの前に、試したいこと、使う機材、予想する結果を登録する。機材の重なりがあれば調整する
- **練習用の機材** — 実験デーで使ってよい評価ボードや部品を一覧にする。壊してよい機材に印を付ける
- **結果の記録** — 試したあと、結果と原因の推測を一行ずつ書く。写真を一枚添付できる
- **発表の進行** — 終わりの1時間で、一人3分ずつ発表する。進行役の画面に、発表順と残り時間を表示する。予想と違った試しを先に発表する
- **原因を考える一言** — 発表のあと、他の参加者が「こういう原因もありそう」を一言ずつ書ける。ベテランの考え方が若手に伝わる
- **試しの一覧** — 過去の実験デーの試しを、予想、結果、原因の推測とともに一覧で見られる

## User Stories

- **US-001 成果を求められない試しの時間がない問題**
  利用者（Bさん）は、うまくいくかわからないことを、安心して試せる時間がほしい。それにより、失敗を恐れずに試し、原因を考える経験を積みたい。
  背景: 現状は業務の成果につながる試ししか認められず、失敗は許されない雰囲気がある。試す機会がなく、失敗から学ぶ経験もない。

- **US-002 うまくいかなかった試しの原因を一人で考えられない問題**
  利用者（Aさん）は、試した結果がうまくいかなかったとき、他の人と一緒に原因を考えたい。それにより、ベテランの考え方を学びたい。
  背景: 現状は原因を考える時間も相手もなく、うまくいかなかった試しはそのまま終わる。

- **US-003 若手が試す経験を積めない問題**
  利用者（部門長）は、若手が試して失敗しながら学ぶ機会を、部署として用意したい。それにより、資料作成だけで技術の感覚が育たない状態を変えたい。
  背景: 現状は試作の機会が減り、ベテランが若い頃に持っていた試す時間が今の若手にはない。

## Open Questions

- 月に半日の時間を、業務の中で確保できるか。部門長の理解が必要になる
- 試したいことが思いつかない若手をどう支えるか。試しの例を用意するか
- 練習用の機材を十分に用意できるか
- **モックで確かめたいこと**: 試しの登録で予想を書き、発表で予想と結果を並べる流れが、原因を考えるきっかけになるか
- **モックで確かめたいこと**: 予想と違った試しを先に発表する進行で、失敗が「皆で考える材料」として受け取られるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **時間の確保ができない** — 業務が忙しい → 実験デーが中止される → 制度が形だけになる。軽減: 最初は四半期に一度から始め、成果を見て頻度を上げる
- **参加者が集まらない** — 試したいことがない → 参加しない → 会が成り立たない。軽減: 試しの例（ノイズ対策の比較、部品の温度特性など）を一覧で示す
- **安全上の事故** — 自由に試す → 危険な試しをする → 事故が起きる。軽減: 使ってよい機材と、電源や高電圧に関わる試しの安全手順を事前に示す
- **競争になる** — うまくいった試しが目立つ → 成果を競う → 失敗を発表しにくくなる。軽減: 予想と違った試しを先に発表し、成果を競わないことを明記する
