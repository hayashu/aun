# PRD: ブラウザの中で回路を組み、壊しても何も失わずに「なぜ壊れたか」がわかる壊してもいい仮想ベンチ（A5xB5-1）

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門には試作機や評価ボードがあるが、若手が自由に触れる機会は少ない。

Bさんは、ハードウェアを壊すことへの不安が強い。手に汗をかきやすく、部品を落としたり、ショートさせたりするのではないかと心配で、実物に手を出すのをためらう。情報系の学科に進んでいれば、プログラムはすぐに作って試せて、失敗しても何も壊れなかったのに、と思うこともある。**実物を壊す心配なく、ハードウェアの試行錯誤を練習できる場所がない**。練習できないので、実物に触る自信もつかない。

**誤解の実態**: Bさんは、評価ボードでLEDの電流制限抵抗の値を変えて試したかった。しかし、値を間違えてLEDを焼いてしまうのが怖くて、試さなかった。先輩に聞くと「計算すればわかるよ」と言われたが、計算の結果が本当に正しいのか、実際に試して確かめる勇気が出なかった。Aさんも、電源回路のコンデンサの値を変えたときにどうなるかを知りたかったが、評価ボードを壊すのが怖くて試せなかった。2人とも、試してみれば数分でわかることを、何週間も試せずにいた。

**気づきの実態**: 壊すことへの怖さは、実物を失う代償があるからである。代償のない場所で試せれば、怖さなく試行錯誤できる。ブラウザの中で回路を組み、値を変えて結果を見て、壊れたら「なぜ壊れたか」がわかる場があれば、プログラムを書くように気軽にハードウェアを試せる。そこで自信をつけてから実物に触れば、実物でも試せるようになる。

**練習機会の実態**: 市販の回路シミュレーターはあるが、専門家向けで設定が難しく、壊れたときに何が起きたかを教えてくれない。社内の研修は実物を使うもので、壊すことへの怖さは残る。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。若手が実物を壊すことを恐れて試作を避けている状況は、部門では把握されていない。

## Goals / Non-Goals

**Goals**

- 壊す心配なく、ハードウェアの試行錯誤を練習できる（仮想ベンチで試した回数を効果指標とする）
- 壊れたときに、なぜ壊れたかがわかる（壊れた試しのうち、本人が原因を一行で説明できた割合を効果指標とする）
- 実物に触る自信がつく（仮想ベンチで練習したあとに、同じ種類の試しを実物で行った割合を効果指標とする）

**Non-Goals**

- 本格的な回路シミュレーターの置き換え（設計の検証には既存のツールを使う。仮想ベンチは練習用）
- 精密な物理の再現（壊れる仕組みをわかりやすく示すことを優先し、精度は求めない）
- 先輩との練習課題（版2）、部署のカリキュラム（版3）の範囲

## Proposed Solution / Feature Description

ブラウザの中で、**電源、抵抗、LED、コンデンサなどの部品をつないで回路を組み、値を変えて結果を見られる仮想ベンチ**を提供する。部品に定格を超える電流や電圧がかかると、その部品が「焼けた」と表示され、何が起きたか（電流がいくらになり、定格のいくらを超えたか）が示される。壊しても何も失わず、元に戻すボタンですぐにやり直せる。

**主要な構成要素**:

- **部品の配置** — 電源、抵抗、LED、コンデンサ、スイッチなどの部品を選んでつなぐ。最初は少ない部品から始める
- **値の変更** — 抵抗の値、電源の電圧などを変えると、各部品に流れる電流と電圧がその場で表示される
- **壊れる表示** — 部品の定格を超えると、その部品が「焼けた」と表示される。何が起きたか（流れた電流、定格、超えた割合）を一行で示す
- **予想してから試す** — 値を変える前に、「どうなると思うか」を選ばせる。予想と結果を並べて示す
- **練習課題** — 「LEDを焼かずに一番明るく光らせる」のような課題を段階的に並べる。課題を解くうちに、定格と計算の関係が身につく
- **元に戻す** — 壊れたら、すぐに元に戻してやり直せる。壊すことが学びの一部であることを示す

## User Stories

- **US-001 壊すのが怖くて試せない問題**
  利用者（Bさん）は、実物を壊す心配なく、値を変えたらどうなるかを試したい。それにより、何週間も試せずにいた試行錯誤を、数分でできるようにしたい。
  背景: 現状は実物を壊す代償が怖くて試さない。試さないので、実物に触る自信もつかない。

- **US-002 壊れたときに何が起きたかわからない問題**
  利用者（Aさん）は、壊れたときに、なぜ壊れたのかを数字で知りたい。それにより、実物で試すときに、壊さない範囲を判断できるようになりたい。
  背景: 現状は壊れたときに何が起きたかを教えてくれるものがない。

## Open Questions

- 仮想ベンチで練習したことが、実物の試しに本当につながるか。仮想と実物の違いをどう伝えるか
- どこまでの部品と回路を扱うか。部品を増やすと操作が難しくなる
- **モックで確かめたいこと**: 部品を焼いてしまったとき、「怖い」ではなく「なるほど、こうなるのか」と感じられる表示になっているか
- **モックで確かめたいこと**: 練習課題を解く流れで、定格と計算の関係が自然に身につく感覚があるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **仮想と実物の違い** — 仮想で大丈夫だった → 実物でも同じと思う → 実物で壊す。軽減: 仮想ベンチは理想的な条件で計算していることを示し、実物では余裕を持つよう案内する
- **練習止まり** — 仮想ベンチで満足する → 実物に触らない → 実物の自信がつかない。軽減: 課題の最後に、実物で同じことを試す案内を示す
- **精度の誤解** — 簡略化した計算を本格的なものと思う → 設計の検証に使う → 誤った設計になる。軽減: 練習用であり、設計の検証には使わないことを明記する
- **教材との誤認** — 電子工作の教材に見える → 既存の教材と比べられる → 差別性を失う。回避: 壊れることを中心に置き、壊れたときの説明を充実させる
