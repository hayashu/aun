# PRD: 返事を選択式にして「真意」を言葉にしてもらう小さな試作提案カード（A1xB1-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B1（相手の真意がわからない × やりたいものづくりができない）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は本人が返事を読み解く個人ツール、版3はチームの制度を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門の業務の多くは会議資料のパワーポイント作成で、実際に手を動かして作る機会は少ない。

2人がものづくりの提案をすると、上司の返事は「いいね」「考えておくよ」「そのうちね」のような**どの意味にも取れる言葉**で返ってくる。上司の側にも事情がある。予算や人の割り当てがまだ決まっていない、はっきり断るとやる気をそぐのではないかと気にしている、などである。曖昧な返事は、上司なりの配慮から生まれている。

**誤解の実態**: Bさんは課長に、空いた時間で試作基板の評価をしてみたいと口頭で伝えた。課長は「いいね、落ち着いたらやろうか」と答えた。課長の頭の中では「今期の予算では無理だが、来期なら検討できる」という意味だった。Bさんは今期中のどこかで声がかかると思って待った。3か月後、評価は外部に発注された。課長はBさんに伝えたつもりでいた。Bさんは約束を破られたと感じた。

**気づきの実態**: 食い違いの原因は、どちらの能力でもなく、**返事の形**にある。口頭の「いいね」には、条件も期限も含まれていない。上司は自分の真意を言葉にしたつもりで、提案者はその言葉に含まれていない条件を想像できない。提案が口頭である限り、返事も口頭の曖昧な言葉になりやすい。

**練習機会の実態**: 社内には正式な企画提案の様式があるが、数十ページの資料を前提としており、「空き時間に評価をやってみたい」程度の小さな提案には重すぎる。小さな提案ほど口頭で済まされ、返事も記録に残らない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。しかし、具体的にどのような場面の言葉をどう変えるかは示していない。

## Goals / Non-Goals

**Goals**

- 小さな提案への返事が、条件と期限を含む形で返ってくる（返事のうち「条件付き」「いつ頃」が明記された割合を効果指標とする）
- 提案者と上司の間で、返事の意味の食い違いが減る（後から「そういう意味ではなかった」と判明した件数を効果指標とする）
- 小さなものづくりの提案の数が増える（月あたりのカード提出数を効果指標とする）

（一つめは返事の形を変える目標で、カードの設計で直接届く。二つめはその結果である）

**Non-Goals**

- 正式な企画審査の置き換え（大きな案件は既存の審査を通す。本書は小さな提案に限る）
- 提案の可否を自動で判定すること（判断は上司のもので、ツールは返事の形を整えるだけである）
- 提案者の評価・ランキング（提案数を評価に使うと、数だけの提案が増える）
- 返事の真意を本人が読み解く練習（版1の範囲）

## Proposed Solution / Feature Description

5分で書ける**小さな試作提案カード**と、上司が**選択式で返事をする画面**を提供する。返事の選択肢は「やってよい／条件付きでやってよい／今はできない」の三つで、条件付きと今はできないを選んだ場合は、条件か理由と「いつ頃なら見直せるか」を一行書くことを求める。曖昧な言葉が入る余地を、返事の形でなくす。

**主要な構成要素**:

- **提案カード** — やりたいこと、使う時間（週何時間か）、必要なもの、業務とのつながりを、それぞれ一行で書く。資料を作らずに出せることが前提である
- **選択式の返事** — 上司は三つの選択肢から選ぶ。「条件付き」なら条件を、「今はできない」なら理由の分類（予算／人／時期／方針）と見直し時期を選ぶ。自由記述は一行だけにする
- **返事の見直し日** — 「今はできない」「条件付き」の返事には見直し日が付き、その日に双方へ知らせる。保留のまま忘れられることを防ぐ
- **縮小の相談** — 上司が「この規模なら可能」と縮小案を返せる欄を設ける。提案者は縮小案を受けるか、出し直すかを選べる
- **カードの一覧** — 提案者と上司が、出したカードと返事の履歴を一覧で見られる。同じ提案を何度も口頭で繰り返す必要がなくなる

## User Stories

- **US-001 「いいね」の意味が食い違う問題**
  利用者（Bさん）は、提案への返事を、条件と時期がわかる形で受け取りたい。それにより、許可だと思って待ち続け、後で外注されていたと知る事態を避けたい。
  背景: 現状は口頭の「いいね」に条件も期限も含まれず、上司の真意は上司の頭の中にしかない。食い違いは数か月後に、機会が別に移ったときに初めてわかる。

- **US-002 はっきり断るのが気まずい問題**
  利用者（課長）は、提案を断るときに、相手のやる気をそがずに理由と見直しの時期を伝えたい。それにより、曖昧な返事で期待を持たせ続けることを避けたい。
  背景: 現状は断る言葉を選びにくく、「そのうちね」でやり過ごす。結果として提案者は待ち続け、後でより大きく失望する。

## Open Questions

- 上司が選択式の返事を「堅苦しい」と感じて使わないおそれがある。口頭で返したあとに、カードの返事を後から付ける運用でもよいか
- 理由の分類（予算／人／時期／方針）で足りるか。「方針」を選ぶと、それ以上説明しなくてよい逃げ道にならないか
- 提案者と上司の2人だけで閉じるべきか、チームに公開すべきか。公開すると他の人の提案が参考になるが、断られた記録も見える
- **モックで確かめたいこと**: 提案カードが5分以内で書け、上司の返事が1分以内で済むか
- **モックで確かめたいこと**: 「今はできない」を選んだ返事を見た提案者が、突き放されたと感じずに次の行動を考えられるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **上司が使わない** — 選択式が面倒 → 口頭で済ませる → カードが宙に浮く。軽減: 通知から1タップで三択を返せる形にし、条件の記入は後回しにできるようにする
- **断りの記録が残る** — 「今はできない」が履歴に残る → 提案者が萎縮する → 提案が減る。軽減: 履歴は本人と上司だけが見られる設定を標準にする
- **形だけの「条件付き」** — 条件を曖昧に書く → 結局意味が読めない → 元の問題に戻る。軽減: 条件欄に例を示し、見直し日を必須にする
- **提案数の競争** — 提出数が見える → 数を増やすための提案が出る → 上司の負担が増える。軽減: 提出数を評価に使わない方針を明記する
