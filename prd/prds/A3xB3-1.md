# PRD: 遅れや詰まりを「結論→状況→対策→相談」の順で伝える進捗報告の下書きツール（A3xB3-1）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B3（適切なコミュニケーション方法がわからない × 自分で進める道筋を作れない）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は上司と部下の信号の合図、版3はチームの朝会の型を扱う。A2×B3（完了の基準）とは異なり、本セルは「遅れや詰まりという悪い知らせの伝え方」を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

自分で区切りを作るのが苦手なBさんは、仕事が予定より遅れがちである。遅れそのものは珍しいことではないが、問題は**遅れをどう伝えればよいかがわからない**ことにある。悪い知らせを先に言うのか、言い訳と思われないか、どこまで説明すればよいか。伝え方がわからないので、遅れを報告するのが怖くなり、報告を先延ばしにする。先延ばしにするほど、遅れは大きくなる。

**誤解の実態**: Bさんはノイズ対策の評価で、測定器の不調から作業が1週間遅れていた。課長への報告では、測定器の不調の経緯から話し始め、5分たってから「それで、1週間遅れそうです」と言った。課長は「最初に結論を言って」と言い、さらに「なぜもっと早く言わなかったのか」と聞いた。Bさんは遅れが確定するまで言わないほうがよいと思っていた。Aさんは逆に、遅れを報告するときに対策を言わず、「遅れています、すみません」とだけ伝えた。課長は「で、どうするの？」と聞き返し、Aさんは答えに詰まった。

**気づきの実態**: 遅れの報告には、職場で期待される型がある。最初に結論（どれだけ遅れるか）、次に状況（なぜか）、それから対策（どうするか）、最後に相談（何を判断してほしいか）。さらに、遅れは確定する前に「遅れそう」の段階で伝えるのがよいとされる。2人はこの型を知らないので、報告のたびに課長に問い詰められ、報告がますます怖くなる。

**練習機会の実態**: 報連相の研修では「結論から話す」と教わったが、遅れという悪い知らせをどう伝えるかは扱わなかった。実際の報告の場で失敗すると、上司の印象が悪くなる。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。遅れの報告が先延ばしにされたことによる影響は、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 遅れの報告が早くなる（遅れに気づいてから上司に報告するまでの日数を効果指標とする）
- 報告が上司に一度で伝わる（報告のうち、上司から「結論は？」「対策は？」と聞き返されなかった割合の自己申告を効果指標とする）
- 遅れを報告することへの怖さが減る（「遅れを報告するのが怖くない」の自己申告を効果指標とする）

**Non-Goals**

- 遅れそのものをなくすこと（遅れは起きるものとして扱い、伝え方を整える）
- 上司への報告の自動送信（下書きまでを作り、伝えるのは本人である）
- 文章の添削・敬語の修正（既存サービスの領域）
- 上司との合図（版2）、チームの朝会（版3）の範囲

## Proposed Solution / Feature Description

遅れや詰まりに気づいたら、**「どれだけ遅れるか」「なぜか」「どうするか」「何を判断してほしいか」の4つに答えさせ、報告の下書きをその順で組み立てる**個人向けWebツールを提供する。さらに、計画した区切りの日に、予定どおりかを本人に聞き、遅れそうなら「いま伝える」ことを促す。

**主要な構成要素**:

- **区切りの確認** — 本人が決めた区切り（一次案、評価完了など）の日に、「予定どおり／遅れそう／遅れた」を聞く。「遅れそう」の段階で報告を促す
- **4つの問い** — どれだけ遅れるか（日数）、なぜか（一行）、どうするか（対策を一つ以上）、何を判断してほしいか（期限の延長、手伝い、優先度の変更など）に答える
- **報告の下書き** — 4つの答えを、結論→状況→対策→相談の順に並べた下書きにする。口頭用（30秒で話せる長さ）とチャット用の2つを出す
- **対策の候補** — 対策が思いつかないときに、よくある対策（範囲を絞る、手伝いを頼む、順番を入れ替える）を候補で示す
- **報告の振り返り** — 報告したあとの上司の反応（すぐ了承、聞き返された、追加の相談になった）を記録する。聞き返された項目を、次の報告で注意する点として示す

## User Stories

- **US-001 経緯から話して「結論は？」と言われる問題**
  利用者（Bさん）は、遅れを報告するときに、結論から伝える形を準備したい。それにより、経緯を長く話して問い詰められ、報告が怖くなる事態を避けたい。
  背景: 現状は報告の型を知らず、経緯から話し始める。上司に問い詰められるたびに、次の報告を先延ばしにする。

- **US-002 遅れを伝えても対策を言えない問題**
  利用者（Aさん）は、遅れを報告するときに、自分なりの対策と相談したいことを一緒に伝えたい。それにより、「で、どうするの？」と聞き返されて答えに詰まる事態を避けたい。
  背景: 現状は遅れの事実だけを伝え、対策を準備していない。

## Open Questions

- 「遅れそう」の段階で報告することを、本人が受け入れられるか。確定してから言いたい気持ちが強いかもしれない
- 下書きの型が、上司ごとの好みに合うか
- **モックで確かめたいこと**: 4つの問いに答えて下書きができるまでが、報告の直前の3分で終わるか
- **モックで確かめたいこと**: 下書きを見て、本人が「これなら報告できる」と怖さが和らぐか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **型への依存** — 下書きを読み上げるだけになる → 上司の質問に答えられない → かえって信頼を失う。軽減: 下書きは要点だけにし、本人が自分の言葉で話す前提にする
- **言い訳の型になる** — 「なぜか」の欄が長くなる → 言い訳に聞こえる → 上司の印象が悪くなる。軽減: 「なぜか」は一行に制限し、対策の欄を広く取る
- **区切りの確認の負担** — 区切りのたびに聞かれる → 面倒になる → 使わなくなる。軽減: 確認は区切りの日だけに限り、1タップで答えられるようにする
- **文化的な単純化** — 「日本の上司は結論を先に求める」と一般化する → 上司個人の好みと合わない → 偏見を強める。軽減: 振り返りで本人の上司の好みを学ぶ形にする
