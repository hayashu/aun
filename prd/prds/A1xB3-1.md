# PRD: 「いい感じに進めておいて」から隠れた期限を推測して自分でマイルストーンを切る依頼分解ツール（A1xB3-1）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B3（相手の真意がわからない × 自分で進める道筋を作れない）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は依頼者と受け手の間、版3はチームの依頼の仕組みを扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

上司からの依頼は「いい感じに進めておいて」「急ぎじゃないから」「まとまったら見せて」のような言葉で来る。**その言葉の裏にある期限や完成度の期待が読めない**。そのうえBさんは、マイルストーンがないと自分で区切りを作って進めるのが苦手である。2つが重なると、仕事は締め切り直前まで形にならない。

**誤解の実態**: 課長はBさんに「急ぎじゃないから、ノイズ対策の案をまとめておいて」と頼んだ。課長の頭の中では、2週間後の部長報告に使う予定だった。Bさんは言葉どおり急ぎではないと受け取り、他の資料作成を優先した。10日後に課長から「明後日の部長報告に使いたいんだけど」と言われ、徹夜で仕上げた。同じ週、Aさんは「まとまったら見せて」と言われた調査を、完成するまで見せなかった。課長は途中で方向を確認したかった。Aさんが3週間かけた調査は、方向違いで半分が使えなかった。

**気づきの実態**: 依頼の言葉から期限を推測する手がかりはある。依頼された時期、上司の予定表にある報告会、過去の似た依頼の流れである。2人はこうした手がかりを依頼の言葉と結びつける習慣がない。さらに、受けた依頼を自分で区切りに分ける方法を知らないので、「いつ途中で見せるべきか」も決められない。

**練習機会の実態**: タスク管理アプリは、期限が決まっている前提で作られている。期限が言葉に隠れている依頼を、どう区切るかは教えてくれない。上司に毎回期限を聞くのは、信頼されていないように感じて気が引ける。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。依頼の期限が曖昧なことによる手戻りは、部門では測られていない。

## Goals / Non-Goals

**Goals**

- 期限の読み違えで、締め切り直前に慌てる件数が減る（依頼の実際の期限の3日前までに一次案ができていた割合を効果指標とする）
- 途中で見せるべき時点で見せられる（依頼のうち、完成前に一度以上上司に確認した割合を効果指標とする）
- 依頼を受けたあと、手をつけるまでの迷いが減る（依頼を受けてから最初の区切りを決めるまでの日数を効果指標とする）

**Non-Goals**

- 上司の予定表の自動取得（他人の予定を勝手に読む形は、信頼を損ねる。手がかりは本人が入力する）
- 上司の真意の断定（推測は候補として示し、確かめる一言とセットにする）
- プロジェクト管理ツールの置き換え（個人の依頼を区切るまでを扱い、チームの進捗管理はしない）
- 依頼者と受け手の間の確認の型（版2）、チームの依頼ルール（版3）の範囲

## Proposed Solution / Feature Description

依頼の言葉を入力すると、**先に自分で「本当の期限」と「期待される完成度」を推測させ、そのあとで手がかりと確かめる一言を返し、最後に依頼を3つ程度の区切りに分けさせる**個人向けWebツールを提供する。期限の読み違えを防ぐことと、自分で進める道筋を作ることを、ひと続きで行う。

**主要な構成要素**:

- **依頼の記録** — 誰から、どんな言葉で、何を頼まれたかを書く。「急ぎじゃない」「いい感じに」のような言葉には印を付ける
- **自分の推測** — 手がかりを見る前に、本当の期限（今週／2週間以内／1か月以内／わからない）と完成度（たたき台／ほぼ完成）を本人が選ぶ
- **手がかりの確認** — 依頼の時期、近くにある報告会や会議、過去の似た依頼を本人に思い出させる質問を出す。答えをもとに、期限の候補を幅で示す
- **確かめる一言** — 「部長報告に使われる予定はありますか」「途中で一度見ていただくなら、いつ頃がよいですか」のように、期限を直接問い詰めずに確かめる一言を選ばせる
- **区切りの作成** — 依頼を「方向の確認」「一次案」「仕上げ」の3つ程度に分け、それぞれの日付を本人が決める。方向の確認の区切りでは、上司に見せることを促す
- **振り返り** — 依頼が終わったら、実際の期限と自分の推測を比べる。読み違えた依頼の言葉と、その上司の傾向を本人に返す

## User Stories

- **US-001 「急ぎじゃない」を言葉どおりに受け取る問題**
  利用者（Bさん）は、「急ぎじゃない」と言われた依頼の本当の期限を、手がかりから推測して確かめたい。それにより、締め切り直前に頼まれ直して徹夜で仕上げる事態を避けたい。
  背景: 現状は言葉どおり後回しにし、本当の期限が近づいてから知らされる。そのときには準備の時間がすでに失われている。

- **US-002 完成するまで見せずに方向がずれる問題**
  利用者（Aさん）は、「まとまったら見せて」と言われた依頼でも、途中で方向を確かめる時点を自分で決めたい。それにより、3週間かけた調査が方向違いで使えなくなる事態を避けたい。
  背景: 現状は言葉どおり完成してから見せ、ずれは最後に判明する。

## Open Questions

- 手がかりの質問が、本人の職場の実態に合うか。報告会の周期や上司の習慣は職場ごとに違う
- 振り返りまで続けて使ってもらえるか。振り返りがなければ、上司の傾向を学べない
- **モックで確かめたいこと**: 依頼の入力から区切りの作成までを、依頼を受けた直後の5分で終えられるか
- **モックで確かめたいこと**: 先に自分で期限を推測させる順序が、手がかりを見たときの「なるほど」につながるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **推測の誤り** — 期限の候補を外す → 間違った区切りで進める → かえって慌てる。軽減: 推測は確かめる一言とセットでしか示さず、確かめることを前提にする
- **上司への不信** — 依頼の言葉を裏読みし続ける → 上司の言葉を信じなくなる → 関係が悪くなる。軽減: 「急ぎじゃない」が本当に急ぎでない場合もあることを、候補の一つとして必ず示す
- **区切りの負担** — 小さな依頼まで区切る → 手間が増える → 使われなくなる。軽減: 1週間以内の依頼は区切りを省略できる短い流れを用意する
- **文化的な単純化** — 「日本の上司は期限を言わない」と一般化する → 偏見を強める。軽減: 振り返りから、その上司個人の傾向を学ぶ形にする
