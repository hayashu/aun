# PRD: 試作で受けた指摘を「何が・なぜ・次にどう」に分けて、確かめる質問まで作る試作の振り返りノート（A4xB1-1）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B1（失敗の原因がわからない × やりたいものづくりができない）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は指摘する側のフィードバックの型、版3はチームの試作レビュー基準と次の機会の保証を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門の業務の多くは会議資料のパワーポイント作成で、実際に手を動かして作る機会は少ない。

その少ない機会を得ても、2人は**うまくいかなかったときに、何が悪かったのかがわからない**。上司や先輩の指摘は「もうちょっと考えて」「これじゃ使えないな」のような短い言葉で、具体的に何をどう直せばよいかは言われない。原因がわからないので、次に同じ機会が来ても同じ失敗をしそうで、自分から次の機会を求められない。上司のほうも、一度うまくいかなかった人には次の機会を回しにくくなる。

**誤解の実態**: Bさんは、念願だった評価用の治具の製作を任された。2週間かけて作った治具を課長に見せると、「うーん、これだと現場では使いにくいな」と言われ、治具は使われなかった。Bさんは、寸法が悪かったのか、材料が悪かったのか、使い方の想定が違ったのかがわからなかった。聞き返そうとしたが、課長は次の会議に向かってしまった。次の治具の製作は、別の先輩に任された。Aさんも、小さな試作基板の評価を任されたが、報告のあとに「詰めが甘い」と言われ、何が甘かったのかわからないまま終わった。

**気づきの実態**: 「使いにくい」「詰めが甘い」の裏には、具体的な理由がある。治具なら「作業者が片手で扱えない」「部品の交換に工具が要る」など。上司の頭の中にはその理由があるが、言葉にされない。指摘を受けたその場で、「どの点が使いにくいですか」「どこを詰めればよかったですか」と確かめれば、原因はわかった。しかし2人は動揺していて、何を聞けばよいかもわからなかった。

**練習機会の実態**: 指摘を受けたあとに、それを振り返る方法を教わる機会はない。指摘はその場で終わり、記録にも残らない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。若手のものづくりの機会が、一度の失敗で途切れている件数は測られていない。

## Goals / Non-Goals

**Goals**

- 試作の指摘を受けたあと、原因が具体的にわかる（指摘のうち、本人が「何が・なぜ」を一行で書けるようになった割合を効果指標とする）
- 指摘の意味を確かめる質問を出せる（指摘を受けてから、確かめる質問を出すまでの日数を効果指標とする）
- 次のものづくりの機会を自分から求められる（失敗のあとに、次の機会を申し出た件数を効果指標とする）

**Non-Goals**

- 試作の技術的な正解の提示（ツールは指摘を整理するだけで、技術の答えは出さない）
- 上司の指摘の言い方を変えること（版2の範囲）
- チームの試作レビュー基準（版3の範囲）

## Proposed Solution / Feature Description

試作で受けた指摘を記録すると、**指摘を「何が（対象）」「なぜ（理由）」「次にどう（改善）」に分けさせ、わからない部分を確かめる質問を作る**個人向けWebツールを提供する。分けられなかった部分が、確かめるべき点になる。確かめたあとは、次の機会に向けた改善点として残す。

**主要な構成要素**:

- **指摘の記録** — 誰に、どんな言葉で指摘されたかを書く。試作の種類（治具、基板、評価、筐体など）を選ぶ
- **3つに分ける** — 指摘を「何が」「なぜ」「次にどう」に分けて書かせる。わからない欄は「わからない」と書いてよい
- **原因の候補** — 「何が」「なぜ」がわからない場合に、その試作の種類でよくある原因（治具なら片手で扱えない、交換に工具が要る、作業者の位置から見えないなど）を候補で示す
- **確かめる質問** — 「わからない」と書いた欄について、「どの点が使いにくかったですか」「現場の作業者が使う場面を想定すべきでしたか」のような確かめる質問を作る。本人の言葉に直させる
- **次の機会への改善点** — 確かめた結果を「次にどう」として残す。たまった改善点を、次の試作を申し出るときの材料にする

## User Stories

- **US-001 「使いにくい」と言われて何が悪いかわからない問題**
  利用者（Bさん）は、試作で受けた短い指摘から、具体的な原因を確かめたい。それにより、次の治具の製作で同じ失敗をせず、次の機会を自分から申し出たい。
  背景: 現状は短い指摘の理由がわからず、聞き返せないまま終わる。次の機会は別の人に回り、ものづくりから遠ざかる。

- **US-002 指摘を受けたときに動揺して聞き返せない問題**
  利用者（Aさん）は、指摘を受けたあとに、落ち着いて確かめる質問を準備したい。それにより、「詰めが甘い」の意味を知らないまま終わる事態を避けたい。
  背景: 現状は指摘の場で動揺し、何を聞けばよいかわからない。

## Open Questions

- 原因の候補を、試作の種類ごとにどこまで用意できるか
- 指摘から時間がたってから確かめる質問を出すことを、上司はどう受け取るか
- **モックで確かめたいこと**: 指摘を3つに分ける作業で、「わからない」部分が確かめるべき点として浮かび上がるか
- **モックで確かめたいこと**: たまった改善点を見て、次の機会を申し出る自信が持てるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **自己批判の強化** — 指摘を細かく分ける → 失敗を繰り返し考える → 落ち込む。軽減: 「次にどう」の欄を中心に置き、改善点として前向きに残す
- **候補の思い込み** — 原因の候補から選ぶ → 確かめずに原因を決めつける → 違う改善をする。軽減: 候補は確かめる質問とセットでしか示さない
- **上司の負担** — 確かめる質問が増える → 上司が面倒がる → 関係が悪くなる。軽減: 質問は一度に一つに絞るよう促す
- **文化的な単純化** — 「日本の上司は理由を言わない」と一般化する → 偏見を強める。軽減: 指摘の言い方は人によって違うことを前提にし、上司個人の傾向を振り返りから学ぶ
