# PRD: 話し手と聞き手が会話のあとに「どこで置いていかれたか」を高さの線で指し合う置いていかれ地点マップ（A4xB6-2）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B6（失敗の原因がわからない × 具体と抽象を行き来する会話が苦手）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は一人で高さのずれを振り返るシート、版3は注意を具体例つきで返すチームのフィードバックの型を扱う。A4×B4-2（理解の分かれ目シート）は分野の用語がわからなくなった地点を指す話、本PRDは話の高さが飛んだ地点を指す話を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。2人の上司の課長は、方針や考え方を抽象的な言葉で語ることを好む。

抽象的に話す人と具体的に聞く人の会話では、**会話が噛み合わなかったことは2人ともわかっているのに、どこで噛み合わなくなったのかを2人とも言えない**。話し手は「伝え方が悪かったのか、相手の理解が足りないのか」がわからない。聞き手は「どこからわからなくなったのか」を説明できない。原因がわからないので、次の会話でも同じところで噛み合わない。

**誤解の実態**: 課長はBさんに、次の試作の狙いを説明した。「今回の試作は、量産を見据えた検証というより、構想の筋の良さを見る位置づけだから」と話し始め、次に「だから評価は全部やらなくていい、肝の3項目で」と言い、最後に「温度は85度条件だけでいい」と具体的な指示で終わった。Bさんは最後の指示だけを覚え、評価を85度条件の1項目だけにした。課長は「3項目って言ったよね」と言った。会話のあと、課長は「最初に狙いを話したのに」と思い、Bさんは「狙いの話のどこが指示だったのかわからなかった」と思った。Bさんが置いていかれたのは、抽象的な「狙い」から「肝の3項目」へ降りた地点だった。

**気づきの実態**: 会話を「話の高さの流れ」として2人で見直し、聞き手が「ここで置いていかれた」と指せば、原因は話し手の伝え方と聞き手の受け取り方の両方から見える。話し手は、自分が高さを飛ばした地点に気づき、聞き手は、自分がどの高さの話を聞き落としやすいかに気づく。しかし、会話のあとに2人で振り返る手順は職場にない。

**練習機会の実態**: 上司は部下の理解度を確かめる手段として「わかった？」と聞くが、部下は「わかりました」と答えるしかない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。会話のあとに2人で振り返る機会の有無は、部門では把握されていない。

## Goals / Non-Goals

**Goals**

- 噛み合わなかった会話の原因が、2人の間で見える（マップで聞き手が地点を指した会話の数を効果指標とする）
- 同じ地点で置いていかれる回数が減る（同じ種類の地点が続けて指された回数の推移を効果指標とする）
- 話し手が、自分の高さの飛ばし方に気づく（話し手が「自分が飛ばした」と認めた地点の数を効果指標とする）

**Non-Goals**

- どちらが悪かったかの判定（マップはずれの地点を見るもので、責任を問わない）
- 会話の録音・文字起こし（話し手が会話の流れを思い出して書く）
- 一人の振り返り（版1）、チームのフィードバックの型（版3）の範囲

## Proposed Solution / Feature Description

会話のあとに2人で使う**置いていかれ地点マップ**を提供する。話し手が、自分が話した流れを3〜5段で書き、各段の高さ（方針・構造・具体策・事実）を選ぶ。聞き手は、その流れを見て「ここで置いていかれた」地点を一つ指し、何がわからなかったかを選択式で答える。2人は、高さの線の上で指された地点を見ながら、次にどうするかを一行ずつ書く。

**主要な構成要素**:

- **話の流れ** — 話し手が、話した内容を3〜5段で書き、各段に高さの印を付ける。高さの線が折れ線のように表示される
- **置いていかれた地点** — 聞き手が、線の上で置いていかれた地点を一つ指す。理由を「前の段とのつながりがわからなかった」「指示なのか説明なのかわからなかった」「言葉の意味がわからなかった」から選ぶ
- **次にどうするか** — 話し手は「次は高さを飛ばさずに〇〇を挟む」、聞き手は「次はこの地点で質問する」を、それぞれ一行で書き、並べて表示する
- **地点の一覧** — 過去のマップで指された地点が並び、同じ種類の飛ばし方や聞き落としが続いているかを2人で見られる

## User Stories

- **US-001 どこからわからなくなったのか説明できない問題**
  利用者（Bさん）は、課長の話のどこで置いていかれたかを、話の流れの上で指して伝えたい。それにより、「わかりました」と言って違うことをする状態を変えたい。
  背景: 現状は最後の具体的な指示だけを覚え、抽象的な狙いから降りた地点を聞き落とす。

- **US-002 伝えたつもりで伝わらない原因がわからない問題**
  利用者（課長）は、自分の話のどこで部下が置いていかれたかを知りたい。それにより、「最初に話したのに」と感じる場面を減らしたい。
  背景: 現状は部下の理解を「わかった？」で確かめるしかなく、どこで高さを飛ばしたのかに気づけない。

- **US-003 2人の間に入っても原因を整理できない問題**
  利用者（Aさん）は、課長とBさんの会話が噛み合わなかったとき、2人がマップを使って原因を見られるようにしたい。それにより、調整役として間に入る負担を減らしたい。
  背景: 現状は2人の言い分を聞いても、どこがずれたのかを整理できない。

## Open Questions

- 話し手（上司）が、会話のあとに流れを書く手間を負ってくれるか
- 聞き手が「置いていかれた」と指すことに抵抗を感じないか
- 会話の流れを書く人の記憶が正確でないと、マップが成り立たない
- **モックで確かめたいこと**: 高さの折れ線の上で聞き手が地点を指したとき、話し手が「ここで飛ばした」と納得できるか
- **モックで確かめたいこと**: 2人が「次にどうするか」を並べて見たとき、責め合いではなく、お互いの工夫として受け取れるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **責任の押しつけ合い** — 地点が指される → どちらが悪いかの議論になる → 関係が悪くなる。軽減: マップには責任を問う項目を置かず、2人とも「次にどうするか」を書く形にする
- **上司が使わない** — 流れを書く手間がかかる → 上司が使わない → 聞き手だけが困る。軽減: 聞き手が流れを書き、話し手は確認するだけでもよい形を用意する
- **記録の転用** — マップが残る → 評価に使われる → 正直に指さなくなる。軽減: マップは2人だけが見られる設定にする
