# PRD: 抽象的に話す側が「たとえば」を一つ添え、聞く側が近い例を選んで返す具体例すり合わせカード（A1xB6-2）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B6（相手の真意がわからない × 具体と抽象を行き来する会話が苦手）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は一人で具体例を作るノート、版3は方針に例を添えるチームのルールを扱う。A1×B1-2（選択式の返事）は提案への返事を選択式にする話、本PRDは抽象的な指示の意味を具体例で合わせる話を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。2人の上司の課長は、方針や考え方を抽象的な言葉で語ることを好む。

抽象的な言葉を使う側と、具体的に考える側の間で、**同じ言葉を違う具体例で受け取ったまま、ずれに気づかない**。話す側は、自分の頭の中に具体例があるので、伝わったと思っている。聞く側は、別の具体例を思い浮かべて、わかったと思っている。どちらも確かめる手順を持っていない。

**誤解の実態**: 課長は朝会で「今期は、もっとシンプルにしていこう」と言った。Bさんは回路の部品点数を減らすことだと受け取り、部品削減の案を考え始めた。Aさんは会議の数を減らすことだと受け取り、定例の統合を提案した。課長が考えていたのは、顧客向けの製品仕様の選択肢を減らすことだった。3人が別々の「シンプル」を進め、2週間後の会議で初めてずれがわかった。課長は「なぜ伝わらないのか」と感じ、2人は「最初に例を言ってくれれば」と感じた。

**気づきの実態**: 抽象的な言葉に具体例が一つ添えられていれば、聞く側は自分の解釈と比べられる。聞く側が「これに近いですか」と例を返せば、話す側はずれに気づける。しかし、話す側は具体例を添える習慣がなく、聞く側は例を返すと「話を理解していない」と思われそうで、どちらも一歩目を踏み出さない。

**練習機会の実態**: 会議の進め方の研修はあるが、「言葉の具体例を確かめ合う」手順は扱わない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。抽象的な指示の解釈がずれた件数は、社内で記録されていない。

## Goals / Non-Goals

**Goals**

- 抽象的な指示に、具体例が一つ添えられる（カードで送られた指示のうち、「たとえば」が書かれた割合を効果指標とする）
- 聞く側の解釈のずれが、作業を始める前にわかる（聞く側が例を返し、話す側が「違う」と答えた件数を効果指標とする）
- 例を返すことへの気まずさが下がる（「例を返しやすかった」の自己申告を効果指標とする）

**Non-Goals**

- 指示の正しさの評価（カードは意味を合わせるもので、指示の良し悪しを問わない）
- 会話の録音・自動要約（その場の会話を記録すると、気軽に使えなくなる）
- 一人で具体例を作るノート（版1）、チームのルール（版3）の範囲

## Proposed Solution / Feature Description

話す側と聞く側の2人で使う**具体例すり合わせカード**を提供する。話す側は、抽象的な指示を一行で書き、「たとえば」を一つ添えて送る。聞く側は、自分が思い浮かべた具体例を書き、話す側の例と比べて「近い／少し違う／全然違う」を選んで返す。話す側は、聞く側の例に「それで合っている／ここが違う」を一言で返す。

**主要な構成要素**:

- **指示のカード** — 話す側が、指示を一行で書き、「たとえば」を一つ添える。「たとえば」が空のままだと送れないようにする
- **聞く側の例** — 聞く側が、自分が思い浮かべた具体例を一つ書き、話す側の例との近さを3段階で選ぶ
- **一言の返事** — 話す側が、聞く側の例に「合っている／ここが違う」を選び、違うときは一行で補う
- **カードの一覧** — 送ったカードと返事が並ぶ。同じ言葉でずれた回数が見える

## User Stories

- **US-001 同じ言葉を違う具体例で受け取る問題**
  利用者（Bさん）は、課長の抽象的な指示に添えられた例と、自分が思い浮かべた例を比べたい。それにより、作業を始める前にずれに気づきたい。
  背景: 現状は課長の「シンプルに」を自分の解釈で進め、2週間後にずれがわかる。

- **US-002 伝えたつもりが伝わらない問題**
  利用者（課長）は、自分の指示が部下にどう受け取られたかを、作業の前に知りたい。それにより、「なぜ伝わらないのか」と感じる場面を減らしたい。
  背景: 現状は部下が何を思い浮かべたかを知る手段がなく、結果を見て初めてずれに気づく。

- **US-003 例を返すと理解していないと思われそうな問題**
  利用者（Aさん）は、気まずさなく自分の解釈を上司に返したい。それにより、わからないまま進める状態を変えたい。
  背景: 現状は「具体的には？」と聞くと理解力を疑われそうで、聞けない。

## Open Questions

- 課長が毎回「たとえば」を書くことを面倒に感じないか
- 口頭の指示を、カードに書き起こす手間を誰が負うか
- 「全然違う」が続いたとき、話す側が責められていると感じないか
- **モックで確かめたいこと**: 話す側が指示と「たとえば」を書き、聞く側が例と近さを返す往復が、それぞれ1分ほどで終わるか
- **モックで確かめたいこと**: 2人の具体例が並んで表示されたとき、ずれが一目でわかるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **話す側が使わない** — 例を書く手間がある → 課長が使わない → 聞く側だけが困る。軽減: 聞く側からも「たとえばを教えてください」とカードを起こせるようにする
- **形だけの「たとえば」** — 例を書くのが義務になる → 意味のない例が書かれる → ずれが見えない。軽減: 聞く側の例と並べて見せ、例の質を責めない
- **評価への転用** — ずれの回数が記録される → 上司や部下の評価に使われる → 正直に返さなくなる。軽減: カードは2人だけが見られる設定にする
