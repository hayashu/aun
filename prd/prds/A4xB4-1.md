# PRD: 分野をまたぐ手戻りの経緯を、やりとりの記録から並べて「どこで食い違ったか」を探す手戻り経緯マップ（A4xB4-1）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B4（失敗の原因がわからない × 専門領域の違いで認識がずれる）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は2分野の理解の分かれ目を並べるシート、版3はチームの手戻りレビュー会を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがるプロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。Bさんの部署は機械系の社員が多い。

分野をまたぐ仕事では、手戻りがよく起きる。試作の段階で基板と筐体が合わない、評価の条件が電気と機械で違っていた、などである。手戻りが起きると、**誰の何が原因だったのかがわからない**。電気側は機械側の情報が遅かったと思い、機械側は電気側の説明が足りなかったと思う。原因がはっきりしないまま、どちらも自分のせいかもしれないと感じ、あるいは相手のせいだと思って終わる。同じ手戻りが次の試作でも起きる。

**誤解の実態**: 2回目の試作で、基板のコネクタが筐体の開口部と2mmずれていた。Bさんは自分の配置ミスだと思い、上司に謝った。しかし、なぜずれたのかはわからなかった。後で調べると、機械側が開口部の位置を一度変更しており、その変更はチャットで一言伝えられていた。Bさんはそのチャットを見落としていた。一方、機械側は図面の正式な改版を出しておらず、変更は口頭とチャットだけだった。原因は、Bさんの見落としと、機械側の伝え方の両方にあった。調整役のAさんも、どこで食い違ったのかを説明できなかった。

**気づきの実態**: 手戻りの原因は、やりとりの記録（メール、チャット、図面の改版、議事録）の中にある。それらを時系列に並べれば、どの時点で誰が何を知っていて、どこで情報が食い違ったかが見える。しかし、記録は複数の場所に散らばっていて、並べる手間がかかる。2人は並べる方法を知らず、記憶だけで原因を考えるので、原因がはっきりしない。

**練習機会の実態**: 手戻りが起きたとき、部門では修正の対応だけが行われ、原因の分析はされない。品質部門の不具合分析は、顧客に影響する大きな不具合が対象である。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。分野をまたぐ手戻りの原因は、部門では分析されていない。

## Goals / Non-Goals

**Goals**

- 分野をまたぐ手戻りの原因が、具体的な時点と出来事で説明できる（手戻りのうち、食い違った時点を特定できた割合を効果指標とする）
- 原因が自分だけにあるのか、両方にあるのかを正しく把握できる（手戻りのうち、原因を一方だけでなく両方の要因に分けられた割合を効果指標とする）
- 同じ種類の手戻りが減る（マップで特定した原因と同じ種類の手戻りが、その後に起きた件数を効果指標とする）

**Non-Goals**

- 責任の判定（誰が悪いかを決めない）
- メールやチャットの自動取り込み（記録は本人が選んで貼り付ける。他人のやりとりを勝手に読まない）
- 2分野の理解の並べ合い（版2）、チームのレビュー会（版3）の範囲

## Proposed Solution / Feature Description

手戻りが起きたら、**関係するやりとり（チャット、メール、図面の改版、議事録）を本人が選んで時系列に並べ、各時点で「電気側が知っていたこと」「機械側が知っていたこと」を書き込む**個人向けWebツールを提供する。並べると、情報が片方にしか届いていなかった時点が浮かび上がる。そこが食い違った時点である。

**主要な構成要素**:

- **手戻りの記録** — 何が合わなかったか（コネクタの位置が2mmずれた、など）を書く
- **やりとりの並べ替え** — 関係するやりとりを、日付、種類（チャット、メール、図面、会議）、内容の要約で登録する。登録すると時系列に並ぶ
- **知っていたことの書き込み** — 各時点で、電気側と機械側がそれぞれ何を知っていたかを書き込む。片方だけが知っていた時点に印が付く
- **食い違いの時点** — 片方だけが知っていた時点のうち、手戻りの原因になったものを本人が選ぶ。その時点で「何があれば防げたか」を一行書く
- **原因の分け方** — 原因を「見落とし」「伝え方（正式な改版がなかったなど）」「確認の不足」に分けて示す。一方だけの原因でないことが見えるようにする

## User Stories

- **US-001 手戻りの原因がわからず自分のせいだと思い込む問題**
  利用者（Bさん）は、手戻りが起きたときに、どの時点で情報が食い違ったかを知りたい。それにより、すべてを自分の配置ミスだと思い込まず、正しい対策を取りたい。
  背景: 現状は記憶だけで原因を考え、はっきりしないまま自分のせいだと思う。原因が伝え方にもあった場合、同じ手戻りが次の試作でも起きる。

- **US-002 調整役なのに食い違いを説明できない問題**
  利用者（調整役のAさん）は、分野をまたぐ手戻りの経緯を、記録をもとに説明したい。それにより、両方の分野に対策を求められるようにしたい。
  背景: 現状は記録が散らばっていて、経緯をたどれない。

## Open Questions

- やりとりを並べる手間が大きすぎないか。関係するやりとりが多い場合はどうするか
- 本人が見落としたやりとりを、自分で見つけられるか
- 他の人のやりとりを本人が要約して登録することに、抵抗はないか
- **モックで確かめたいこと**: やりとりを時系列に並べたとき、片方だけが知っていた時点がひと目でわかるか
- **モックで確かめたいこと**: 原因の分け方を見て、本人が「自分だけのせいではなかった」と感じつつ、自分の見落としも認められるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **相手を責める道具になる** — 相手の伝え方の問題が見える → 相手を責める → 関係が悪くなる。軽減: 原因は「何があれば防げたか」で書く形にし、相手の名前ではなく出来事で示す
- **入力の負担** — やりとりの登録に時間がかかる → 使われなくなる → 原因がはっきりしないまま。軽減: 関係するやりとりを5件程度に絞って登録するよう促す
- **自己正当化** — 相手の原因ばかり探す → 自分の見落としを認めない → 自分の対策を取らない。軽減: 原因の分け方で、自分の側の要因も必ず一つ以上考えるよう促す
- **記録の扱い** — 他人のやりとりの要約を本人が持つ → 情報の扱いに問題が出る。軽減: 登録する内容は要約に限り、原文は貼らないよう示す
