# PRD: 答える側が「今いい／あとで／この資料を見て」をワンタップで返せる質問チケット（A1xB2-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B2（相手の真意がわからない × ハードウェアの知識が足りず焦る）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は質問する本人の学習計画、版3は部署の教える仕組みを扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門は機械系の社員が多く、筐体・機構・材料の知識が前提として会話が進む。

2人はハードウェアの知識を早く身につけたくて、先輩によく質問する。先輩の側は、自分の業務で忙しいときに声をかけられることが多い。そのとき先輩は「追々わかるよ」「基礎からやるといいよ」と短く返す。**先輩の真意（今は時間がない／自分で調べてほしい／今は知らなくてよい）は、言葉にされないまま相手に渡る**。

**誤解の実態**: Bさんは機械の先輩に、筐体の板厚の決め方を口頭で聞いた。先輩は図面の締め切り直前で、「それは追々わかるよ」と答えた。先輩としては「今は手が離せないので、社内の設計基準書を見てほしい」という意味だった。Bさんは「今は知らなくてよい」と受け取った。翌週の設計レビューで、Bさんの基板配置が板厚の制約と合わないことがわかった。先輩は「聞いてきたのに調べなかった」と思い、Bさんは「知らなくていいと言われた」と思った。

**気づきの実態**: 質問の場面では、答える側の状況が質問する側から見えない。忙しいから短く答えたのか、知らなくてよいから短く答えたのかは、言葉だけでは区別できない。答える側も、自分の短い返事が別の意味で受け取られたことに気づかない。どちらも悪意はなく、**質問と返事の形**がずれを生んでいる。

**練習機会の実態**: 部門のチャットで質問することもできるが、全員が見る場で初歩的な質問をするのは気が引ける。個別チャットでは、先輩が忙しいときに既読のまま返事が来ない。返事が来ない理由もわからない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。部門内の質問がどれだけ未解決のまま終わっているかは測られていない。

## Goals / Non-Goals

**Goals**

- 質問への返事の意味が食い違う件数が減る（質問者が受け取った意味と、回答者が込めた意味が後で食い違ったと判明した件数を効果指標とする）
- 質問が放置される件数が減る（チケットのうち、3営業日以内に何らかの返事が付いた割合を効果指標とする）
- 答える側の負担が増えない（回答者が1チケットに使った時間の自己申告を効果指標とする）

（一つめと二つめは返事の形で直接届く。三つめは使い続けてもらうための制約条件である）

**Non-Goals**

- 質問への自動回答（AIで答えると、先輩とのつながりが生まれない。答えるのは人である）
- 回答者の評価やランキング（回答数を競わせると、雑な回答が増える）
- 質問する本人の学習計画づくり（版1の範囲）
- 部署全体の教育制度（版3の範囲）

## Proposed Solution / Feature Description

質問を**チケット**として送り、答える側が**ワンタップで返事の意味を明示できる**Webツールを提供する。返事の選択肢は「今すぐ話せる／あとで（いつ頃）／この資料を見て／今は知らなくて大丈夫」の四つ。忙しい先輩でも1タップで返せ、その選択肢自体が真意を言葉にする。

**主要な構成要素**:

- **質問チケット** — 何を知りたいか、いつまでに必要か、自分でどこまで調べたかを短く書く。期限があることで、答える側は優先度を判断できる
- **ワンタップ返事** — 回答者は四つの選択肢から選ぶ。「あとで」には時間帯を、「この資料を見て」には資料名かページを一行添える。「今は知らなくて大丈夫」には、いつ頃必要になるかを選ぶ
- **返事の受け取り確認** — 質問者は、返事を受け取ったら「わかった／まだわからない」を返す。「まだわからない」なら、チケットが回答者に戻る
- **質問の宛先候補** — 分野ごとに「この話なら誰に聞けばよいか」を、本人が答えてよいと登録した人から候補として出す。毎回同じ先輩に集中するのを防ぐ
- **よくある質問の蓄積** — 「この資料を見て」で返されたチケットは、資料へのリンク付きで部門の質問集にたまる。第2段階に置き、現時点のプロトタイプには入っていない

## User Stories

- **US-001 短い返事が別の意味で受け取られる問題**
  利用者（Bさん）は、先輩の返事が「今は時間がない」のか「今は知らなくてよい」のかを、はっきりした形で受け取りたい。それにより、調べるべきことを調べずにレビューで指摘される事態を避けたい。
  背景: 現状は口頭の短い返事に真意が含まれず、ずれは翌週のレビューで初めてわかる。

- **US-002 忙しいときに質問を受けて困る問題**
  利用者（機械の先輩）は、手が離せないときにも、質問者を突き放さずに返事をしたい。それにより、短い返事が誤解される事態と、返事をしないまま放置する事態の両方を避けたい。
  背景: 現状は忙しいときに丁寧に返す余裕がなく、短い言葉で済ませるか、返事を後回しにして忘れる。

## Open Questions

- 四つの選択肢で足りるか。「自分もよく知らない」という返事の選択肢が必要かもしれない
- 質問者が期限を短く書きすぎると、回答者が追い立てられる。期限の上限を設けるべきか
- 口頭で聞けば済む質問まで、チケットにする必要があるか。口頭で聞いたあとに、返事の意味だけをチケットで確かめる使い方もありうる
- **モックで確かめたいこと**: 回答者の画面で、1タップで返事が済み、負担に感じないか
- **モックで確かめたいこと**: 質問者が「今は知らなくて大丈夫（〇月頃必要）」を受け取ったとき、安心して他の学習に移れるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **回答者が使わない** — チケットの確認が手間 → 口頭で返す → 記録が残らない。軽減: 通知から1タップで返事できる形にし、アプリを開かなくても済むようにする
- **質問の集中** — 詳しい先輩に質問が集まる → その人の負担が増える → 返事が遅れる。軽減: 宛先候補を複数出し、一人あたりの未回答件数が多いときは別の人を勧める
- **形式的なやりとり** — チケットが事務的に感じる → 先輩との関係が冷える → 雑談から学ぶ機会が減る。軽減: 「今すぐ話せる」を選んだら対面かチャットで話すことを促し、チケットは入口に留める
- **評価への転用** — 回答数が記録される → 評価に使われる → 義務的な回答になる。軽減: 回答数を表示せず、評価に使わない方針を明記する
