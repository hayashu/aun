# PRD: 会話の途中で「上げて（つまり？）」「下げて（たとえば？）」を気軽に合図し合う抽象度の合図カード（A3xB6-2）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B6（適切なコミュニケーション方法がわからない × 具体と抽象を行き来する会話が苦手）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は一人で「つまり」の一行を作る下書き、版3は会議の進行キットを扱う。A3×B3-2（青・黄・赤の信号）は進み具合を合図する話、本PRDは会話の抽象度のずれを合図する話を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。2人の上司の課長は、方針や考え方を抽象的な言葉で語ることを好む。

抽象的に話す人と具体的に話す人の会話では、**お互いの話の高さがずれていることに気づいても、「もう少し具体的に」「で、つまり？」と言い出しにくい**。部下から上司に「具体的には？」と聞くのは失礼に感じられ、上司から部下に「つまり？」と聞くと責めているように聞こえる。結果として、2人とも高さがずれたまま話し続け、会話の終わりに「わかったような、わからないような」状態が残る。

**誤解の実態**: 課長はBさんとの1on1で、「これからの君のキャリアは、技術の幅と深さのバランスだと思う。T字型というか、軸を持ちつつ横にも広げる感じで」と30分話した。Bさんは、「明日から何をすればよいのか」がわからなかったが、上司の話を遮って「具体的には？」と聞くのは失礼だと思い、うなずき続けた。課長はBさんがうなずいていたので伝わったと思った。逆に、Bさんが試作の状況を細かく説明したとき、課長は途中で話を見失ったが、Bさんを傷つけたくなくて「なるほど」と言い続けた。

**気づきの実態**: 高さのずれに気づいたその場で、軽い合図を出せれば、ずれは数秒で直る。「下げて（たとえば？）」「上げて（つまり？）」と、高さの方向だけを伝えれば、相手を責める言葉にならない。2人の間であらかじめ「合図を出してよい」と決めておけば、立場の違いがあっても出しやすい。しかし、そうした決めごとは職場にない。

**練習機会の実態**: 1on1の研修は上司向けにあるが、部下が話の高さを調整してもらう頼み方は扱わない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。1on1で部下が理解できないまま終わった件数は、社内で記録されていない。

## Goals / Non-Goals

**Goals**

- 会話の途中で、高さのずれを合図できる（1回の会話で出された合図の数を効果指標とする）
- 会話の終わりに「わかったような、わからないような」状態が減る（会話のあとの「次に何をするかわかった」の自己申告を効果指標とする）
- 合図を出すことへの気まずさが下がる（「合図なら出せた」の自己申告を効果指標とする）

**Non-Goals**

- 会話の録音・文字起こし（記録されると、気軽に合図を出せなくなる）
- 話し方の評価（合図の数で、上司や部下の話し方を採点しない）
- 一人の下書き（版1）、会議の進行（版3）の範囲

## Proposed Solution / Feature Description

1on1や打ち合わせで2人が使う**抽象度の合図カード**を提供する。会話を始める前に、2人がそれぞれの画面で「合図を出してよい」に同意する。会話中、どちらかが「下げて（たとえば？）」か「上げて（つまり？）」のボタンを押すと、相手の画面にやわらかい色で合図が表示される。会話の最後に、2人が「次にやること」を一行ずつ書き、並べて見る。

**主要な構成要素**:

- **始める前の同意** — 2人が「この会話では、合図を出してよい」に同意する。同意の画面に、合図は責めるものではなく高さを合わせるためのものだと書く
- **合図ボタン** — 「下げて（たとえば？）」「上げて（つまり？）」の2つのボタン。押すと相手の画面に合図が出る。言葉を添えなくてよい
- **次にやることの照らし合わせ** — 会話の最後に、2人がそれぞれ「次に相手（自分）がやること」を一行で書き、並べて表示する。ずれていればその場で直す
- **合図の振り返り** — 会話ごとに、どちらの合図が何回出たかだけを2人に返す。合図が多かった会話と、次にやることが一致した会話の関係を見られる

## User Stories

- **US-001 上司の抽象的な話を遮れない問題**
  利用者（Bさん）は、上司の話が抽象的すぎると感じたとき、失礼にならない形で「たとえば？」を伝えたい。それにより、30分うなずいたまま何をすればよいかわからない状態を変えたい。
  背景: 現状は上司の話を遮ることが失礼に感じられ、うなずき続ける。

- **US-002 部下の具体的な話を見失っても言えない問題**
  利用者（課長）は、部下の話の行き先を見失ったとき、責めずに「つまり？」を伝えたい。それにより、「なるほど」と言い続けて理解しないまま終わる状態を変えたい。
  背景: 現状は「で、つまり？」と言うと部下を追い詰めるように感じ、言えない。

- **US-003 調整役として2人の高さをつなげない問題**
  利用者（Aさん）は、課長とBさんの会話に入ったとき、2人の高さのずれを合図で見えるようにしたい。それにより、間に入って言い換える負担を減らしたい。
  背景: 現状はずれに気づいても、どちらに合わせて言い換えればよいかわからない。

## Open Questions

- 画面を見ながらの会話が、かえって不自然にならないか。対面では合図カードを机に置く紙の形のほうがよいか
- 上司が合図を受け入れてくれるか
- 合図が多すぎると、会話が途切れすぎないか
- **モックで確かめたいこと**: 合図ボタンを押したときに相手の画面に出る表示が、責められているように感じない柔らかさに収まっているか
- **モックで確かめたいこと**: 会話の最後に2人の「次にやること」が並んだとき、ずれがその場で直せる程度にわかりやすいか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **上司が使わない** — 上司が合図の仕組みを面倒に感じる → 部下だけが同意しても意味がない → 仕組みが止まる。軽減: 上司向けに「合図で1on1が短く終わる」ことを示す
- **合図の誤用** — 合図を嫌みとして使う → 関係が悪くなる → 使われなくなる。軽減: 合図には言葉を添えず、色と方向だけを示す
- **記録の転用** — 合図の回数が残る → 評価に使われる → 合図を出さなくなる。軽減: 回数は2人だけに返し、会話の中身は記録しない
