# PRD: 相談の前に「誰に・何を・どこまで」を組み立てる下書きツール（A3xB4-1）

版: v1（2026-11-22、パイロット） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B4（適切なコミュニケーション方法がわからない × 専門領域の違いで認識がずれる）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は2人の間、版3は場の仕組みを扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。Bさんの部署は機械系の社員が多く、電気側の話ができる相手が少ない。

2人はそれぞれ別の理由で、**相談や報告を「どう出すか」を組み立てられない**。Aさんは、誰に・いつ・どの順で話を通すべきかという段取りがわからない。Bさんは、相手が何を知っていて何を知らないかがわからないまま説明を始めてしまう。どちらも中身は正しいのに、出し方のせいで話が通らない。

**誤解の実態**: Bさんは試作基板の発熱が想定を超えていることに気づき、筐体の通気設計を変えてほしいと考えた。Bさんはこれを「ディレーティングが足りない」という電気側の言葉で説明し、Aさんに伝えた。Aさんは重要度を判断できず、次の定例会議でそのまま議題に出した。会議では機械チームのリーダーが初めてこの話を聞くことになり、「なぜ事前に言わないのか」という空気の中で「持ち帰って検討します」とだけ返された。Aさんはこれを前向きな返事と受け取り、Bさんは用語が伝わっていないことに気づかなかった。2週間後、筐体の金型発注が予定どおり進んでいたことがわかり、通気口の追加は次の試作まで持ち越しになった。

**気づきの実態**: 2人とも、会議の前に「準備が足りない」と気づく手がかりを持っていない。Aさんは、日本の職場では重要な変更を会議の前に関係者へ個別に伝えておく（根回し）ことが多いと知識としては知っている。しかし、今回の件がそれに当たるのかを判断できない。Bさんは、自分の説明が専門用語に頼っていることに、相手の反応を見るまで気づけない。そして相手は、わからなくても質問しないことが多い。

**練習機会の実態**: 報連相の研修や、ビジネスマナーの本はある。しかし扱うのは一般論で、「いま手元にあるこの件を、誰に、どの順で、どの言葉で出すか」を組み立てる手助けはしない。上司に相談すれば教えてもらえるが、毎回聞くのは気が引ける。実際の会議は練習の場にならず、外せば提案そのものが流れる。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げている。分野をまたぐ用語のずれについては、社内で測られた記録がない。

## Goals / Non-Goals

**Goals**

- 会議の場で初めて聞かされる関係者が減る（重要な変更を議題に出す前に、関係者へ個別に伝えた割合を効果指標とする）
- 説明が専門用語のせいで伝わらない場面が減る（説明のあとに相手から用語の確認を受けた回数、または「わからなかった」と後でわかった件数を効果指標とする）
- 相談の準備にかかる心理的な負担が下がる（相談を出すまでに迷った時間の自己申告を効果指標とする）

（最初の二つは結果を変える目標で、相手の反応にも左右される。三つめは本人の負担で、ツールが直接届く。まずは三つめで続けて使われることを確かめ、そのうえで前の二つを見る）

**Non-Goals**

- 文章の添削・敬語の修正（既存サービスの領域。扱うのは出す順序と前提であり、文面ではない）
- 唯一の正しい段取りの提示（職場や人によって違い、単一の正解を出せば嘘になる）
- 相手側（聞き手）への働きかけ（版2・版3の範囲。この版は話し手が自分で準備することに限る）
- 上司・同僚による評価や採点（他人が見る前提にすると、迷っていることを書けなくなる）
- 実際の連絡の自動送信（下書きまでを作り、送るかどうかは本人が決める）

## Proposed Solution / Feature Description

相談や報告を出す前に、**「誰に・何を・どこまで」を本人に答えさせてから、出し方の下書きを返す**Webツールを提供する。質問に答えるうちに、自分では気づかなかった準備不足（伝えていない関係者、相手が知らない言葉）が見えるようにする。完成した文章を渡すのではなく、組み立てる手順そのものを本人の中に残すことが目的である。

**主要な構成要素**:

- **件の入力** — 相談したい内容を一言で書き、種類（報告／相談／提案／反対意見）と急ぎ度を選ぶ。ここで種類を選ばせること自体が、出し方を考える最初の一歩になる
- **関係者マップ** — その件で影響を受ける人を挙げさせ、「この人はもう知っているか」「会議の前に個別に伝えるべきか」を一人ずつ答えさせる。影響が大きいのに未連絡の人がいれば、議題に出す前の確認を促す
- **前提チェック** — 説明に使う言葉を書き出させ、相手の分野（機械／電気／ソフト／営業など）を選ぶと、その分野の人には通じにくそうな言葉に印を付ける。言い換えは本人に考えさせ、例は答えたあとにしか見せない
- **出す順の下書き** — 上の回答から「誰に・どの順で・どの言葉で」の段取り表と、最初の一言の下書きを作る。下書きは候補として複数出し、一つに決めつけない
- **振り返り** — 相談を出したあと、相手の反応（すぐ通った／質問された／保留された）を記録する。保留が多い種類や、印が付いたまま使った言葉を本人に返す
- **分野別の用語辞書** — 前提チェックの判定に使う、分野ごとの「通じにくい言葉」の一覧。最初は手作業で作り、第2段階で利用者の記録から育てる。現時点のプロトタイプには小さな固定の一覧だけを入れる

## User Stories

- **US-001 会議で初めて聞かされる人を作ってしまう問題**
  利用者（Aさん）は、重要な変更を議題に出す前に、誰に先に伝えておくべきかを知りたい。それにより、会議の場で関係者に「聞いていない」と思わせず、提案を内容で判断してもらいたい。
  背景: 現状は段取りを判断できないまま議題に出し、会議で「持ち帰って検討」と返される。それを前向きな返事と受け取って待ち、気づいたときには後工程が進んでいて、変更が次の機会まで持ち越される。

- **US-002 専門用語のせいで説明が伝わらない問題**
  利用者（Bさん）は、説明を始める前に、自分の言葉のうち相手の分野では通じにくいものを知りたい。それにより、言い換えを用意してから話し、相手が質問しないまま誤解する事態を避けたい。
  背景: 現状は相手の反応を見るまで用語のずれに気づけない。しかも相手は質問しないことが多く、ずれは後工程で結果としてしか現れない。

- **US-003 何度も上司に聞くのが気まずい問題**
  利用者は、出し方に迷ったときに、上司に聞く前に自分で一度組み立ててみたい。それにより、聞くとしても「この順でよいか」という確認だけで済ませたい。
  背景: 現状は毎回ゼロから聞くか、聞かずに出して外すかの二択になっている。

## Open Questions

- 関係者マップの「個別に伝えるべきか」の判定を、何を根拠に出すか。影響の大きさと役職から機械的に出すと職場の実態とずれ、出さなければ本人の迷いが減らない
- 分野別の用語辞書を誰が作るか。最初の一覧の質がツールの信頼性を左右する。社内の各分野の人に少しずつ書いてもらう形が現実的か
- 振り返りを続けて記録してもらえるか。記録が途切れると、本人に返す集計が成り立たない
- **モックで確かめたいこと**: 関係者マップと前提チェックを順に答えたあと、段取り表が出てくる流れが、相談前の数分で終えられる長さに収まるか
- **モックで確かめたいこと**: 前提チェックで印が付いた言葉を見て、本人が自分で言い換えを考える気になるか（すぐ答えを見たくなるか）

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **入力の手間** — 質問が多い → 急ぎの相談では使われない → 本当に必要な場面で役に立たない。軽減: 急ぎ度が高いときは関係者マップだけに絞る短い流れを用意する
- **マナー本との誤認** — 段取りを教えるものに見える → 一般論の研修と比べられる → 差別性を失う。回避: 一般論を示さず、手元の件について本人に答えさせる形を守る
- **判定の誤り** — 用語の判定や根回しの要否を断定的に出す → 誤った安心を与える → かえって外す。軽減: 判定は「通じにくいかもしれない」という候補として示し、決めるのは本人にする
- **文化的な単純化** — 「日本の職場では根回しが必要」と一般化する → 職場ごとの実態と合わない → 偏見を強める。軽減: 段取りの候補を複数示し、振り返りから本人の職場の傾向を学ぶ
- **相手側の問題の見落とし** — 話し手の準備だけを求める → 聞き手が質問しない文化が温存される → 本人だけが負担を負う。軽減: 版2・版3と組み合わせる前提を明記し、この版単独で解決すると言わない
