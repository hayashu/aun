# PRD: 依頼する側が過去の資料から「このくらいの粗さ」を選んで見せる粒度の見本合わせ（A2xB6-2）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A2×B6（暗黙の期待・ルールがわからない × 具体と抽象を行き来する会話が苦手）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は一人で抽象度を見積もるはしご、版3は報告の種類ごとの粒度ガイドを扱う。A2×B1-2（完成ライン合意シート）は枚数や完成度を言葉で合意する話、本PRDは抽象度を実物の見本で合わせる話を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。2人の上司の課長は、方針や考え方を抽象的な言葉で語ることを好む。

依頼する側と受ける側の間で、**「ざっくり」「しっかり」「全体像」といった言葉が指す粗さが、2人の頭の中で違う**。言葉で粒度を合わせようとしても、言葉そのものが抽象的なので、ずれが残る。抽象的に話す人ほど、自分の言葉で粒度が伝わったと思っている。

**誤解の実態**: 課長はAさんに「来週の部長会向けに、ざっくりでいいから進捗をまとめておいて」と頼んだ。Aさんは「ざっくり」を短くてよいと受け取り、3行のメモを作った。課長が思い浮かべていたのは、前回の部長会で使った「課題ごとに一行、色分けした1枚の表」だった。課長は「ざっくりって言ったけど、これはさすがに粗すぎる」と言った。別の日、Bさんは課長から「しっかり調べて」と頼まれ、10枚の資料を作ったが、課長が求めていたのは要点3つだった。

**気づきの実態**: 粒度は、言葉より実物の見本で合わせたほうが早い。課長が「前回の部長会のあの表くらい」と見本を一つ指せば、ずれはほとんど起きなかった。依頼する側は、自分の頭の中にある見本を、相手も知っていると思い込んでいる。受ける側は、見本を見せてほしいと頼むのは手間をかけさせると感じている。

**練習機会の実態**: 部門には過去の資料が共有フォルダにあるが、「どの資料がどの粗さか」は整理されておらず、依頼のときに見本として指す習慣もない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。依頼の粒度のずれで作り直しになった件数は、社内で記録されていない。

## Goals / Non-Goals

**Goals**

- 依頼に粒度の見本が添えられる（見本合わせで送られた依頼のうち、見本が一つ選ばれた割合を効果指標とする）
- 粒度のずれによる作り直しが減る（「粗すぎる」「細かすぎる」と言われた件数の自己申告を効果指標とする）
- 依頼にかかる手間が増えない（依頼する側が見本を選ぶのにかかった時間を効果指標とする）

**Non-Goals**

- 資料の中身の指示（見本は粗さを示すもので、内容をまねさせるものではない）
- 資料の出来の評価・採点（見本合わせは依頼の前の合意で、出来を測らない）
- 一人のはしご（版1）、チームの粒度ガイド（版3）の範囲

## Proposed Solution / Feature Description

依頼する側と受ける側の2人で使う**粒度の見本合わせ**を提供する。依頼する側は、依頼を一行で書き、過去の資料の縮小画像の中から「このくらいの粗さ」を一つ選んで送る。受ける側は、見本を見て「この粗さで作ります」か「もう少し粗く／細かくでよいですか」を返す。見本の画像は粗さだけが伝わるよう、ぼかして表示する。

**主要な構成要素**:

- **粒度の棚** — 過去の資料を「一行」「1枚の表」「数枚の説明」「詳しい報告」の4段で並べた棚。各資料は、中身が読めない程度にぼかした縮小画像で表示する
- **依頼のカード** — 依頼する側が、依頼の一行と締め切りを書き、棚から見本を一つ選んで送る
- **受け手の返事** — 受ける側が、見本を見て「この粗さで」「もう少し粗く」「もう少し細かく」のどれかを返す。違う段を選んで返すこともできる
- **合意の記録** — 合意した見本と依頼が並び、次に同じ種類の依頼をするときに使える

## User Stories

- **US-001 「ざっくり」の粗さが2人で違う問題**
  利用者（Aさん）は、依頼の言葉ではなく見本で、どの粗さが求められているかを知りたい。それにより、3行のメモを出して「粗すぎる」と言われる状態を変えたい。
  背景: 現状は「ざっくり」という言葉だけで粗さを推測し、課長の頭の中の見本とずれる。

- **US-002 自分の見本が相手に伝わらない問題**
  利用者（課長）は、依頼のときに頭の中の見本を、手間なく相手に見せたい。それにより、作り直しを頼む場面を減らしたい。
  背景: 現状は自分の言葉で粒度が伝わったと思い、出てきたものを見て初めてずれに気づく。

- **US-003 見本を頼むのが気まずい問題**
  利用者（Bさん）は、依頼主に負担をかけずに、粗さを確かめたい。それにより、10枚作ってから「要点3つでよかった」と言われる状態を変えたい。
  背景: 現状は見本を見せてほしいと頼むと手間をかけさせると感じ、聞けない。

## Open Questions

- 過去の資料をぼかしても、社外秘の資料を棚に載せてよいか
- 4段の棚を誰が作り、どう更新するか
- 口頭の依頼のときにも、見本を選ぶ手間をかけてもらえるか
- **モックで確かめたいこと**: ぼかした縮小画像だけで、粗さの違いが一目で伝わるか
- **モックで確かめたいこと**: 依頼する側が棚から見本を選ぶ操作が、30秒ほどで終わるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **見本のまね** — 見本の中身までまねる → 依頼の目的に合わない資料ができる → かえって作り直しになる。軽減: 見本はぼかして粗さだけを見せる
- **棚の手入れ不足** — 棚に資料が増えない → 合う見本が見つからない → 使われなくなる。軽減: 合意した資料を、完成後にワンクリックで棚に足せるようにする
- **情報の扱い** — 社外秘の資料を棚に載せる → 閲覧範囲を超えて見られる → 情報管理の問題になる。軽減: 棚は部署の中だけで共有し、縮小画像はぼかしを必須にする
