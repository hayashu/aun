# PRD: 具体的な報告の頭に「つまり何か」を一行で添える練習をする「つまり一行」下書きツール（A3xB6-1）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B6（適切なコミュニケーション方法がわからない × 具体と抽象を行き来する会話が苦手）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は会話中に抽象度の上げ下げを合図し合う形、版3は会議の中に抽象と具体を往復する時間を入れる進行キットを扱う。A3×B3-1（結論→状況→対策→相談の下書き）は報告の順番の型の話、本PRDは具体の積み上げから抽象の一行を引き出す話を扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。2人の上司の課長は、方針や考え方を抽象的な言葉で語ることを好む。

Bさんは、**具体的な事実を順に積み上げて話すが、それが「つまり何なのか」を一行で言えない**。抽象的な話を好む課長は、最初に「つまり」を聞きたがる。Bさんの話は正確だが、課長は途中で話の行き先を見失い、「で、何が言いたいの」と遮る。Aさんは、Bさんの話の要点を課長向けに言い換える役を求められるが、自分も何を抜き出せばよいかわからない。

**誤解の実態**: Bさんは課長に、試作基板の評価結果を報告した。「温度試験で、45度の条件で電源ICの表面温度が98度でした。データシートの上限は105度です。ただ筐体に入れた状態では未測定で……」と、事実を順に話した。3分後、課長は「で、結局このままで行けるの？行けないの？」と聞いた。Bさんは「まだわかりません」と答え、課長は「わからないなら、何がわかれば判断できるのかを言って」と返した。Bさんが言うべきだったのは「筐体に入れた状態の測定が1つ足りず、まだ判断できない。来週測る」という一行だった。

**気づきの実態**: 具体を積み上げる人が「つまり」を言えないのは、まとめる力がないからではなく、具体を並べたあとに「だから何か」を自分に問う一手が習慣になっていないからである。事実を3つ書き、「だから何か」を問えば、多くの場合は一行が出る。しかし報告の直前には時間がなく、事実の順番を整えるだけで精一杯になる。

**練習機会の実態**: 報告の型（結論から話す）は研修で教わるが、「結論」をどう引き出すかは教わらない。型だけを知っていると、「結論から言います」と言ったあとに事実を並べてしまう。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。報告の途中で遮られた件数は、社内で記録されていない。

## Goals / Non-Goals

**Goals**

- 報告の前に、「つまり」の一行を書ける（ツールで一行を作ってから報告した件数を効果指標とする）
- 報告の途中で「で、何が言いたいの」と遮られる場面が減る（遮られた回数の自己申告を効果指標とする）
- 具体から抽象の一行を引き出すことに慣れる（ヒントを見ずに一行を書けた割合を効果指標とする）

**Non-Goals**

- 一行の自動生成（一行は本人が書く。ツールが作れば、本人の中に手順が残らない）
- 文章の添削・敬語の修正（扱うのは抽象の一行を引き出す手順で、文面ではない）
- 上司・同僚による評価や採点（他人が見る前提にすると、迷いを書けなくなる）

## Proposed Solution / Feature Description

報告の前に、**伝えたい事実を3つまで書き、それぞれに「だから何か」を問いかけ、最後に「つまり」の一行を本人に書かせる**Webツールを提供する。一行が書けたら、一行を先頭に、事実を後ろに並べた報告の骨組みを返す。

**主要な構成要素**:

- **事実の書き出し** — 伝えたい事実を3つまで、一行ずつ書く。測定値や条件など、具体のままでよい
- **「だから何か」の問い** — 事実ごとに「だから何か」を一行で書かせる。書けないときは、「判断できる／できない」「予定どおり／遅れ」「問題あり／なし」など、抽象の方向の選択肢を出す
- **「つまり」の一行** — 3つの「だから何か」を見ながら、相手に最初に言う一行を書く。相手（課長／部長／隣の分野の人）を選ぶと、その相手が最初に聞きたがることの例（「行ける／行けない」「何を決めてほしいか」）を一つ示す
- **報告の骨組み** — 「つまり」の一行を先頭に、事実を後ろに並べた骨組みを表示する。本人がそのまま話せるよう、短い文で並べる
- **練習の記録** — 書いた一行と、実際に遮られたかどうかを記録する。ヒントを使った回数が減っていく様子を本人に返す

## User Stories

- **US-001 事実を並べて「で、何が言いたいの」と遮られる問題**
  利用者（Bさん）は、報告の前に、事実から「つまり」の一行を自分で引き出したい。それにより、3分話してから遮られる状態を変えたい。
  背景: 現状は事実を順に話すことに精一杯で、一行にまとめる一手を踏まないまま報告している。

- **US-002 他人の話の要点を言い換えられない問題**
  利用者（Aさん）は、Bさんの具体的な報告を、課長向けの一行に言い換える手順を持ちたい。それにより、調整役として話をつなげるようになりたい。
  背景: 現状は何を抜き出せばよいかわからず、Bさんの話をそのまま伝えるか、黙っている。

## Open Questions

- 「だから何か」の選択肢を出しすぎると、本人が考えずに選ぶだけにならないか
- 事実が3つで足りない報告（複雑な評価結果）にどう対応するか
- 報告の直前の短い時間で使ってもらえるか
- **モックで確かめたいこと**: 事実を3つ書いて「だから何か」を問われたとき、本人が自分で一行を書けるか（選択肢を見たくなるか）
- **モックで確かめたいこと**: 一行が先頭に来た骨組みを見て、本人が「このほうが課長に通りそう」と感じるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **一行の質** — 本人の一行が的外れ → 骨組みが逆効果になる → かえって混乱する。軽減: 相手が最初に聞きたがることの例を示し、比べられるようにする
- **時間がない** — 報告の直前に使う余裕がない → 使われない。軽減: 事実1つと一行だけの短い流れを用意する
- **具体の軽視** — 「つまり」だけが大事だと受け取る → 事実を省く → 判断の根拠が伝わらない。軽減: 骨組みには必ず事実を後ろに残す
