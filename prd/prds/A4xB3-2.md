# PRD: 遅れた仕事の終わりに、上司と15分で「どこから遅れ始めたか」を時系列でたどる経緯たどりシート（A4xB3-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A4×B3（失敗の原因がわからない × 自分で進める道筋を作れない）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は本人の見積もり癖ノート、版3はチームの実績日数ライブラリを扱う。A2×B3-2（週次の期待合わせ）とは異なり、本PRDは遅れたあとの原因の共有を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門ではマイルストーンを決めずに仕事が渡されることが多く、進め方は担当者に任されている。

仕事が遅れると、上司は「なぜ遅れたの？」と聞く。部下は「思ったより時間がかかりました」と答える。会話はそこで終わる。**遅れの本当の原因は、上司と部下のどちらか一方だけでは見えない**ことが多い。部下は、自分の作業のどこで時間がかかったかを知っている。上司は、途中でどんな割り込みを頼んだか、どんな情報が遅れて届いたかを知っている。2人の知っていることを合わせないと、原因はわからない。

**誤解の実態**: Bさんは評価資料を1週間の予定で受け、2週間かかった。課長に理由を聞かれて「思ったより時間がかかりました」と答えた。課長は「計画性が足りない」と思った。しかし実際には、その2週間の間に課長自身が別の資料作成を2回Bさんに頼んでおり、さらに機械側からの測定データが4日遅れて届いていた。課長は自分の頼み事を忘れていた。Bさんは、上司の頼み事が原因だとは言いにくかった。2人とも、遅れの原因を半分ずつしか知らなかった。

**気づきの実態**: 遅れた仕事を時系列でたどれば、どこから遅れ始め、その時点で何があったかがわかる。割り込み、情報の遅れ、見積もりの甘さ。原因が部下だけにあるのではないとわかれば、部下は自分を責めすぎずに済み、上司は自分の頼み方を見直せる。しかし今は、遅れの話が「なぜ？」「時間がかかりました」で終わり、時系列をたどる場面がない。

**練習機会の実態**: 部門には振り返りの習慣がなく、遅れた仕事は次の仕事で取り返すものとされている。上司と部下が一緒に経緯をたどる場はない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。部下の遅れのうち、上司の割り込みや情報の遅れが関わっていた割合は測られていない。

## Goals / Non-Goals

**Goals**

- 遅れの原因が、上司と部下の両方の視点から明らかになる（遅れた仕事のうち、経緯たどりシートで遅れ始めた時点と原因が特定された割合を効果指標とする）
- 部下だけの責任と思われていた遅れの原因が、正しく分かれる（原因のうち、割り込みや情報の遅れなど部下以外の要因が含まれた割合を効果指標とする）
- 次の仕事で、同じ原因の遅れが減る（経緯たどりで決めた対策が、次の仕事で実行された割合を効果指標とする）

**Non-Goals**

- 遅れの責任の判定（誰が悪いかを決めない）
- 部下の評価（遅れの記録を評価に使わない）
- 本人の見積もり癖ノート（版1）、チームの実績日数ライブラリ（版3）の範囲

## Proposed Solution / Feature Description

遅れた仕事が終わったときに、**上司と部下が15分で、仕事の期間を時系列に並べ、各自が知っている出来事を書き込んでいく**経緯たどりシートを提供する。部下は自分の作業の進み具合を、上司は自分が頼んだことや外から届いた情報を書く。2人の書き込みを一本の時間軸に並べると、どこから遅れ始め、そのとき何があったかが見える。

**主要な構成要素**:

- **時間軸** — 仕事の開始から終わりまでの日付を横に並べ、予定の区切りと実際の区切りを示す。遅れ始めた日が自動で印付けされる
- **部下の書き込み** — 部下は、作業の進み具合と、時間がかかった作業を日付に書き込む
- **上司の書き込み** — 上司は、その期間に頼んだ別の仕事、届くのが遅れた情報、方針の変更などを日付に書き込む
- **重なりの表示** — 遅れ始めた時点の前後に、どんな出来事が重なっていたかを強調する。部下の作業の問題か、割り込みか、情報の遅れかが見える
- **次の対策** — 2人で、次の仕事で一つだけ変えることを決める（例:「別の仕事を頼むときは、元の仕事の締め切りを一緒に見直す」）

## User Stories

- **US-001 遅れの原因を自分だけのせいにされる問題**
  利用者（Bさん）は、遅れの原因を、上司と一緒に時系列でたどりたい。それにより、上司の割り込みや情報の遅れが関わっていたことを、言いにくさなく共有したい。
  背景: 現状は「なぜ遅れたの？」に「時間がかかりました」としか答えられず、計画性がないと思われる。上司の頼み事が原因だとは言いにくい。

- **US-002 自分の頼み事が部下を遅らせていることに気づかない問題**
  利用者（課長）は、部下の遅れに自分の頼み事が関わっていなかったかを知りたい。それにより、部下の計画性だけを問題にする誤りを避け、自分の頼み方を見直したい。
  背景: 現状は自分の割り込みを忘れ、遅れを部下の問題だと思い込む。

## Open Questions

- 上司が自分の頼み事を正直に書き込むか。書き込むと、自分の責任を認めることになると感じないか
- 15分で時間軸を埋められるか。長い仕事の場合はどうするか
- すべての遅れに経緯たどりをするのは負担が大きい。どの遅れを対象にするか
- **モックで確かめたいこと**: 2人の書き込みが一本の時間軸に並んだとき、遅れ始めた時点の重なりがひと目でわかるか
- **モックで確かめたいこと**: 上司の割り込みが見えたとき、部下が「自分だけのせいではなかった」と感じられ、上司も責められている感じがしないか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **責任の押し付け合い** — 原因が分かれる → 互いに相手のせいにする → 関係が悪くなる。軽減: シートには責任の欄を設けず、次の対策を一つ決めることを目的にする
- **上司が書き込まない** — 自分の割り込みを書くのが気まずい → 上司の書き込みが空になる → 原因が半分しか見えない。軽減: 上司の書き込みの例（頼んだ別の仕事、届くのが遅れた情報）を示し、書きやすくする
- **毎回の負担** — 遅れのたびに15分 → 負担が増える → 続かない。軽減: 予定の1.5倍以上遅れた仕事に絞る
- **評価への転用** — 経緯の記録が残る → 評価に使われる → 正直に書かなくなる。軽減: 記録は2人だけが見られる設定にする
