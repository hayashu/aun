# PRD: 「教える時間」と「誰が何を知っているか」を部署で見える化するOJT設計キット（A1xB2-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A1×B2（相手の真意がわからない × ハードウェアの知識が足りず焦る）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は質問する本人の学習計画、版2は質問と返事の形を扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門は機械系の社員が多く、筐体・機構・材料の知識が前提として会話が進む。

部門のOJTは、**先輩の善意と空き時間に任されている**。教える時間は業務として計上されず、誰が何を教えられるかも決まっていない。そのため、忙しい先輩は短い言葉で返事を済ませ、若手はその言葉の真意を読み取らなければならない。真意を読むのが得意な人ほど早く学び、苦手な人ほど取り残される。

**誤解の実態**: Bさんは筐体の板厚の決め方を先輩に聞き、「追々わかるよ」と言われて質問をやめた。翌週の設計レビューで板厚の制約との不整合を指摘された。Aさんは「基礎からやったほうがいい」と言われ、教科書を最初から読んで1か月を使った。2人の先輩はどちらも図面の締め切り前で、教える時間をとれなかった。部門長は、若手の立ち上がりが遅いと感じていたが、原因が教える仕組みにあるとは考えていなかった。

**気づきの実態**: 問題は個々の先輩の言葉遣いではない。**教えることが業務に組み込まれていない**ため、先輩は短く返すしかなく、若手は聞き返しにくい。誰がどの分野に詳しいかの一覧もないので、若手は身近な先輩一人に質問を集中させ、その先輩はますます短く返す。

**練習機会の実態**: 部門には新人研修があるが、入社直後の数週間で終わる。配属後のOJTには計画がなく、何をいつまでに身につけるかの目安もない。中途入社や他分野出身の若手は、新人研修の対象からも外れる。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。部門の若手が業務で一人立ちするまでの期間は測られていない。

## Goals / Non-Goals

**Goals**

- 若手の質問が、短い返事のまま放置される件数が減る（若手の質問のうち、教える時間の枠内で扱われた割合を効果指標とする）
- 若手が身につけるべき知識の範囲と順序が、部署で共有される（「次に何を学ぶべきかわかっている」と答えた若手の割合を効果指標とする）
- 教える負担が特定の先輩に集中しない（教える時間の枠の担当者の偏りを効果指標とする）

**Non-Goals**

- 研修教材の作成（既存の教科書と社内資料を使う。キットは時間と担当の仕組みを作る）
- 教える側の人事評価への直接の反映（評価に結びつけると、形だけの教育が増える。まずは業務時間として認めるところまでにする）
- 全社の教育制度の改定（一つの部署で試してから広げる）
- 個人の学習計画（版1）、質問と返事の形（版2）の範囲

## Proposed Solution / Feature Description

部署単位で、**「教える時間」の枠と「誰が何を知っているか」の地図**を作るキットを提供する。先輩は週に一定の時間を「教える枠」として登録し、若手はその枠に質問を予約する。先輩は枠の外で無理に答えなくてよい。若手は「いつ聞けば、きちんと答えてもらえるか」がわかる。真意を読む必要を、時間の仕組みでなくす。

**主要な構成要素**:

- **教える枠** — 先輩が週に30分などの枠を登録する。若手は枠に質問を予約し、事前に質問内容を書く。枠の時間は業務時間として計上する
- **知識の地図** — 部署の各メンバーが、自分が教えられる分野（筐体設計、材料、熱、回路など）を登録する。若手は分野から聞く相手を選べる
- **立ち上がり目安表** — 部署として、配属後3か月・6か月で身につけてほしい知識の範囲と順序を一覧にする。若手は自分の進み具合を確かめられ、先輩は何を優先して教えるかを判断できる
- **部署の振り返り** — 一か月ごとに、枠の利用数、分野ごとの質問数、担当の偏りをチームに返す。個人の質問数は出さない
- **質問の蓄積** — 枠で扱った質問と答えの要点を、部署の資料としてためる。第2段階に置き、現時点のプロトタイプには入っていない

## User Stories

- **US-001 いつ聞けばきちんと答えてもらえるかわからない問題**
  利用者（Bさん）は、先輩が質問にきちんと答えられる時間を知りたい。それにより、忙しいときに聞いて短い返事を誤解する事態を避けたい。
  背景: 現状は先輩の空き時間がわからず、忙しいときに聞いて「追々わかるよ」と返される。その真意を読み違え、レビューで指摘される。

- **US-002 何をどの順で学べばよいかわからない問題**
  利用者（Aさん）は、部署として期待される知識の範囲と順序を知りたい。それにより、教科書を最初から読むような遠回りを避けたい。
  背景: 現状は目安がなく、先輩の「基礎から」という言葉を手がかりにするしかない。

- **US-003 教える負担が自分に集中する問題**
  利用者（機械の先輩）は、教える時間を業務として確保し、それ以外の時間は自分の業務に集中したい。それにより、締め切り前に質問を受けて短く返し、誤解を生む事態を避けたい。
  背景: 現状は教える時間が業務として認められず、空き時間に対応するしかない。

## Open Questions

- 教える枠を業務時間として計上することを、部署の管理者が認めるか。認められなければ、枠は登録されない
- 立ち上がり目安表を誰が作るか。ベテランが作ると範囲が広すぎ、若手が作ると抜けが出る
- 枠の外で質問されたときに、先輩が「枠で聞いて」と言うのは冷たく感じられないか
- **モックで確かめたいこと**: 若手が知識の地図から分野を選び、教える枠に質問を予約するまでの流れが自然か
- **モックで確かめたいこと**: 立ち上がり目安表を見た若手が、焦りではなく「次の一歩」を感じられるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **形骸化** — 枠を登録しても使われない → 先輩が枠をやめる → 元に戻る。軽減: 最初は部署で2〜3人の枠から始め、利用状況を振り返りで共有する
- **枠の外の質問が減りすぎる** — 枠でしか聞けない雰囲気になる → 急ぎの質問が止まる → 業務が遅れる。軽減: 急ぎの質問は枠の外でもよいと明記する
- **目安表の圧力** — 3か月の目安に届かない → 若手が劣等感を持つ → 焦りが増す。軽減: 目安表は本人と教える側だけが見る設定にし、到達度を比べない
- **評価への転用** — 枠の担当数が記録される → 人事評価に使われる → 義務的になる。軽減: 担当数は部署単位で集計し、個人別に出さない
