# PRD: 週1回30分、事前に匿名で質問を出せる部署の「何でも質問タイム」（A3xB2-3）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A3×B2（適切なコミュニケーション方法がわからない × ハードウェアの知識が足りず焦る）の版3。方向性は「場・仕組みを変える（チーム／組織向け）」。版1は個人の質問の下ごしらえ、版2は分野をまたぐ教え合いのペアを扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門は機械系の社員が多く、筐体・機構・材料の知識が前提として会話が進む。

部門では、質問は個人が先輩に声をかけて行う。いつ、誰に、どう聞けばよいかは、**本人が空気を読んで判断する**しかない。先輩が忙しそうなら遠慮し、質問が初歩的すぎると思えば恥ずかしくて聞かない。質問の仕方がわからない人ほど、聞く回数が減り、知識不足が広がる。部門全体で見ると、同じ質問を何人もの若手が別々に抱えていることも多い。

**誤解の実態**: Bさんは筐体の材料の選び方を聞こうとしたが、先輩が忙しそうで聞けなかった。Aさんは熱解析の設定で3日間悩んだ。同じ時期、別の若手2人も、同じ材料の選び方と熱解析の設定で悩んでいた。4人とも、自分だけがわからないと思っていた。部門のベテランは、若手がこうした基本的なことで困っているとは知らなかった。ベテランは後で「まとめて聞いてくれれば、30分で全員に説明できたのに」と言った。

**気づきの実態**: 問題は、個人の質問の仕方だけではない。**質問してよい時間と場が決まっていない**ことが原因である。質問してよい時間が決まっていれば、空気を読む必要はない。事前に匿名で質問を出せれば、初歩的な質問の恥ずかしさもなくなる。同じ質問を持つ人がまとめて答えを聞けるので、ベテランの時間も節約できる。

**練習機会の実態**: 部門には勉強会があるが、ベテランが用意したテーマを発表する形で、若手が自分の質問を持ち込む場ではない。チャットの質問の場もあるが、名前が出るため初歩的な質問はしにくい。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。部門の若手が同じ質問を別々に抱えている状況は、測られていない。

## Goals / Non-Goals

**Goals**

- 若手が質問をためらわずに出せる（質問タイムに事前に出された質問の数を効果指標とする）
- 同じ質問を持つ人が、まとめて答えを得られる（質問のうち、「自分も知りたい」が2人以上付いた割合を効果指標とする）
- 一人で抱え込む時間が減る（「わからないことを一人で抱え込む時間が減った」の自己申告を効果指標とする）

**Non-Goals**

- 勉強会の置き換え（勉強会はそのまま残し、質問タイムは若手の質問に答える別の場とする）
- 質問者の評価（誰が何を質問したかを評価に使わない）
- 個人の質問の準備（版1）、教え合いのペア（版2）の範囲

## Proposed Solution / Feature Description

部署で**週に1回30分の「何でも質問タイム」**を設け、その運営をWebで支える仕組みを提供する。質問は事前に匿名で出せ、他の人は「自分も知りたい」の印を付けられる。当日は、印の多い質問から順に、その分野に詳しい人が答える。質問の仕方がわからなくても、質問の時間と場が決まっているので、空気を読む必要がない。

**主要な構成要素**:

- **事前の匿名質問** — 質問タイムの前日までに、質問を匿名で出す。分野（機械、電気、材料など）を選ぶ
- **自分も知りたい** — 他の人が出した質問に「自分も知りたい」の印を付けられる。印の数が、自分だけがわからないのではないことを示す
- **答える人の割り当て** — 質問の分野に詳しい人を、答える人として割り当てる。答える人は事前に質問を見て準備できる
- **当日の進行** — 当日は、印の多い質問から順に答える。進行役の画面に、質問の一覧と残り時間を表示する
- **答えのまとめ** — 答えの要点を一行ずつ残し、部署の質問集として後から見られるようにする

## User Stories

- **US-001 忙しそうな先輩に聞けない問題**
  利用者（Bさん）は、空気を読まずに質問してよい時間がほしい。それにより、先輩が忙しそうで聞けないまま一人で調べ続ける事態を避けたい。
  背景: 現状は質問の時間と場が決まっておらず、先輩の様子を見て遠慮する。わからないことが積み重なり、焦りが増す。

- **US-002 初歩的な質問が恥ずかしくて聞けない問題**
  利用者（Aさん）は、名前を出さずに、初歩的な質問を出したい。それにより、自分だけがわからないのではないかという不安なく、答えを得たい。
  背景: 現状はチャットの質問に名前が出て、初歩的な質問はしにくい。

- **US-003 若手が困っていることを知らない問題**
  利用者（ベテランの先輩）は、若手がどんなことで困っているかをまとめて知りたい。それにより、同じ説明を何度もするのではなく、一度にまとめて答えたい。
  背景: 現状は若手が困っていることを知らず、知ったとしても一人ずつ説明している。

## Open Questions

- 週に1回30分の時間を、部署の全員が確保できるか。参加は自由にするか
- 答える人の割り当てが、特定のベテランに偏らないか
- 匿名にすると、質問の背景がわからず答えにくくならないか
- **モックで確かめたいこと**: 事前の匿名質問と「自分も知りたい」の印で、若手が質問を出しやすいと感じられるか
- **モックで確かめたいこと**: 進行役の画面で、印の多い順に30分で答えを進められるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **質問が集まらない** — 質問タイムを設けても誰も出さない → 会が形だけになる → 中止される。軽減: 最初の数回は、ベテランが「自分が若手の頃に困ったこと」を質問として出す
- **答える人の偏り** — 詳しいベテランに質問が集中する → その人の負担が増える → 協力が得られなくなる。軽減: 答える人を分野ごとに複数用意し、順番に割り当てる
- **匿名の悪用** — 匿名で不適切な質問や批判が出る → 会の雰囲気が悪くなる → 参加者が減る。軽減: 進行役が事前に質問を確認し、業務の質問に限る
- **評価への転用** — 質問の内容が記録される → 若手の理解度の評価に使われる → 質問しなくなる。軽減: 質問者を記録せず、評価に使わない方針を明記する
