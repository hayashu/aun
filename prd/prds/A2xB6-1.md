# PRD: 「全体像を整理して」がどの抽象度の成果物を求めているかを見積もる抽象度のはしご（A2xB6-1）

版: v1（2026-11-23） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A2×B6（暗黙の期待・ルールがわからない × 具体と抽象を行き来する会話が苦手）の版1。方向性は「当事者の行動を支える（個人向けツール）」。版2は依頼の時に粒度の見本を合わせる形、版3は報告の種類ごとの粒度ガイドを扱う。A2×B3-1（完了条件プランナー）は「どこまでやれば完了か」の量の話、本PRDは「どの高さで書けばよいか」の抽象度の話を扱う。

---

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）は、電気・機械の両チームにまたがる製品改良プロジェクトの調整役を担当している。同じプロジェクトには、電気電子出身で入社3年目のBさん（20代後半）がいる。2人の上司の課長は、方針や考え方を抽象的な言葉で語ることを好む。

課長からの依頼は、**どの抽象度で答えればよいかが書かれていない**。「全体像を整理して」「論点をまとめて」と言われたとき、方針の一行を求められているのか、構造の図を求められているのか、具体的な作業の一覧を求められているのかがわからない。具体的に考えるのが得意な人ほど、細かい一覧を作り込み、「細かすぎる、で、結局どうするの」と返される。

**誤解の実態**: Bさんは課長から「試作の課題の全体像を整理しておいて」と頼まれた。Bさんは課題を42項目の表にまとめ、測定値と担当者まで書き込んだ。課長は表を見て「全体像って言ったよね。これだと何が大事かわからない」と言った。課長が求めていたのは、課題を3つの塊に分けて「どれから手を付けるか」を示す1枚だった。Aさんは別の依頼で逆のことが起き、方針の3行を出して「具体的に何をするのかが見えない」と言われた。

**気づきの実態**: 依頼の言葉には、求める抽象度の手がかりがある。「全体像」「方向性」は高め、「段取り」「手順」は低めのことが多い。依頼主が誰に見せるのか（部長か、現場か）も手がかりになる。しかし2人とも、手を動かす前に「どの高さで書くか」を決める手順を持っていない。そのため、自分の得意な高さで作り込んでから外す。

**練習機会の実態**: 資料作成の研修では、見た目の型や図の作り方は教わるが、依頼に合わせて抽象度を選ぶ手順は教わらない。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、外国人材の職場への不満として「暗黙の了解が理解できない」を挙げ、職場側の「ローコンテキスト化」を対策に掲げている。抽象度のずれで作り直しになった件数は、社内で記録されていない。

## Goals / Non-Goals

**Goals**

- 手を動かす前に、求められる抽象度を見積もれる（依頼を受けてから、はしごで高さを選んだ件数を効果指標とする）
- 抽象度のずれによる作り直しが減る（「細かすぎる」「具体性がない」と言われた件数の自己申告を効果指標とする）
- 依頼主への確かめが短く済む（「この高さでよいですか」と見本付きで確かめた割合を効果指標とする）

**Non-Goals**

- 資料の自動作成（扱うのは高さの見積もりで、中身は本人が作る）
- 唯一の正しい抽象度の判定（依頼主や場面で違い、断定すれば誤った安心を与える）
- 依頼主への働きかけ（版2・版3の範囲）

## Proposed Solution / Feature Description

依頼を受けたときに、**依頼の言葉と見せる相手を入力すると、4段の「抽象度のはしご」のどこが求められていそうかの候補を示し、本人が高さを選んでから作業を始める**Webツールを提供する。はしごの各段には、同じ題材を各段で書いた見本を並べ、高さの違いが目で見えるようにする。

**主要な構成要素**:

- **依頼の入力** — 依頼の言葉をそのまま書き、見せる相手（課長だけ／部長会／現場の担当者）と、使う場面（判断を仰ぐ／共有する／作業を割り振る）を選ぶ
- **抽象度のはしご** — 「方針（一行）」「構造（3〜5の塊）」「具体策（項目の一覧）」「手順（作業の順番）」の4段を縦に並べる。依頼の言葉と相手から、候補の段に印を付ける。決めるのは本人
- **段ごとの見本** — 同じ題材（例: 試作の課題）を4段それぞれで書いた見本を並べ、選んだ段の見本を大きく表示する
- **確かめの一言** — 選んだ段と見本から、依頼主に確かめる一言（「3つの塊に分けて、どれから手を付けるかを1枚にまとめるイメージでよいですか」）の下書きを作る
- **振り返り** — 出したあと、依頼主の反応（そのまま通った／上げて・下げてと言われた）を記録し、依頼主ごとの傾向を本人に返す

## User Stories

- **US-001 具体的に作り込みすぎて「細かすぎる」と言われる問題**
  利用者（Bさん）は、「全体像を整理して」と頼まれたとき、作業を始める前にどの高さで書くかを決めたい。それにより、42項目の表を作ってから作り直す状態を変えたい。
  背景: 現状は自分の得意な具体の高さで作り込み、依頼主が求めた高さとずれる。

- **US-002 抽象的すぎて「具体性がない」と言われる問題**
  利用者（Aさん）は、依頼主が求める高さを、見本を添えて短く確かめたい。それにより、方針だけを出して「何をするのか見えない」と言われる状態を変えたい。
  背景: 現状は依頼の言葉から高さを推測するしかなく、確かめる言い方もわからない。

## Open Questions

- 依頼の言葉から候補の段を示す判定を、何を根拠に作るか。言葉の一覧だけでは職場ごとの違いに合わない
- 段ごとの見本を、利用者の仕事に近い題材で用意できるか
- 4段で足りるか。現場によっては「数値の根拠」の段が要る
- **モックで確かめたいこと**: 同じ題材を4段で書いた見本を並べて見たとき、本人が「自分はいつも一番下で書いていた」と気づけるか
- **モックで確かめたいこと**: 依頼を入力して段を選び、確かめの一言を得るまでが、依頼を受けた直後の2〜3分で終わるか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **判定への依存** — 候補の段をそのまま信じる → 外れたときにツールのせいにする → 本人が考えなくなる。軽減: 候補は印だけにし、選ぶ操作を本人に必ずさせる
- **見本の古さ** — 見本が職場の実態と合わない → 参考にならない → 使われなくなる。軽減: 本人が通った資料を自分の見本として追加できるようにする
- **依頼主の気まぐれ** — 同じ依頼主でも日によって求める高さが違う → 傾向の記録が当てにならない → 確かめを省いて外す。軽減: 傾向は参考として示し、確かめの一言を毎回作る流れを残す
