# PRD: 自部署では聞きにくい初歩的な技術の質問を、他部署のベテランに匿名で相談できる「斜めの先輩」相談（A5xB2-2）

版: v1（2026-11-22） / 形式: Alpha+ PRD 101（Slide 27 テンプレート順）
※ セル A5×B2（安心して練習・相談できる場所がない × ハードウェアの知識が足りず焦る）の版2。方向性は「2人の間をつなぐ（コミュニケーション設計）」。版1は個人の設計判断ドリル、版3は部署の輪講を扱う。A5×B1-2（作り手つなぎ）はものづくりの進め方の相談、本PRDは技術知識の質問を扱う。

## Overview / Problem Statement

日本の製造業A社で、外国籍社員のAさん（30代、日本での滞在10年、JLPT N1保持）と、電気電子出身で入社3年目のBさん（20代後半）は、同じ製品開発部門で働いている。部門は機械系の社員が多く、筐体・機構・材料の知識が前提として会話が進む。

2人は、ハードウェアの初歩的な知識について、**自分の部署では質問しにくい**。入社3年目で初歩的なことを聞くのは恥ずかしい。同じ部署の先輩に聞くと、自分の知識不足が評価に影響しないかと心配になる。わからないまま会議に出て、話についていけないことが続く。一方、社内の他部署には、同じ分野のベテランがいる。他部署のベテランなら、評価に関係しないので、初歩的な質問も気兼ねなくできるはずである。

**誤解の実態**: Bさんは、設計会議で「このボスはドラフト角が足りない」と言われ、ドラフト角（金型から抜くための傾き）の意味がわからなかった。入社3年目で聞くのは恥ずかしく、同じ部署の先輩にも聞けなかった。調べてみたが、自分の設計にどう関係するのかはわからなかった。同じ工場の金型部門には、ドラフト角について何十年も扱ってきたベテランがいた。そのベテランは、若手に教えるのが好きだったが、Bさんとつながる経路はなかった。Aさんも、熱設計の初歩的な質問を、同じ部署では聞けずにいた。

**気づきの実態**: 質問しにくいのは、質問の内容ではなく、**質問の相手が自分の評価に関わる人だから**である。評価に関わらない他部署のベテランなら、初歩的な質問も気兼ねなくできる。さらに匿名で質問できれば、恥ずかしさもなくなる。しかし今は、他部署のベテランとつながる経路がない。

**練習機会の実態**: 社内には技術の問い合わせ窓口があるが、業務の正式な問い合わせ向けで、初歩的な質問を気軽にする場ではない。全社のチャットに質問する場もあるが、名前が出るため使いにくい。

**背景**: 経済産業省「高度外国人材研究会 報告書」（2024年7月26日）は、対策として「コミュニケーションのローコンテキスト化」を掲げている。若手が初歩的な質問を聞けずに困っている状況は、社内で把握されていない。

## Goals / Non-Goals

**Goals**

- 初歩的な技術の質問を、気兼ねなくできる（月あたりの匿名の質問の数を効果指標とする）
- 質問が、他部署のベテランから答えを得られる（質問のうち、3営業日以内に答えが付いた割合を効果指標とする）
- 知識不足への焦りが和らぐ（「わからないことを聞ける場所がある」の自己申告を効果指標とする）

**Non-Goals**

- 業務の正式な技術問い合わせの置き換え（業務の判断に関わる問い合わせは既存の窓口で扱う）
- 質問者の評価（質問者を記録せず、評価に使わない）
- 個人の設計判断ドリル（版1）、部署の輪講（版3）の範囲

## Proposed Solution / Feature Description

他部署のベテランが**「斜めの先輩」として登録し、若手が匿名で技術の質問を送れる**Webの仕組みを提供する。ベテランは得意な分野（金型、熱、材料、回路など）を登録する。若手は分野を選んで、匿名で質問を送る。答えは質問者だけに届き、質問者が許せば、匿名の質問と答えを全社の質問集に載せる。

**主要な構成要素**:

- **斜めの先輩の登録** — 他部署のベテランが、得意な分野と、答えられる頻度（週に数件など）を登録する
- **匿名の質問** — 若手が、分野を選んで匿名で質問を送る。質問者の名前と所属は、答える人にも知らされない
- **分野ごとの割り当て** — 質問は、その分野の斜めの先輩に順番に割り当てられる。質問者の部署の人には割り当てない
- **答えと追加の質問** — 斜めの先輩が答えると、質問者に届く。質問者は匿名のまま、追加の質問を一度だけ送れる
- **質問集への掲載** — 質問者が許せば、質問と答えを全社の質問集に匿名で載せる。同じ疑問を持つ他の若手も読める

## User Stories

- **US-001 初歩的な質問を自分の部署で聞けない問題**
  利用者（Bさん）は、入社3年目で聞くのが恥ずかしい初歩的な質問を、評価に関係しない相手に匿名で聞きたい。それにより、わからないまま会議に出て話についていけない状態を変えたい。
  背景: 現状は同じ部署の先輩に初歩的な質問をすると評価に影響しそうで、聞けない。調べてもわからず、知識不足への焦りが増す。

- **US-002 若手に教えたいのにつながる経路がない問題**
  利用者（金型部門のベテラン）は、自分の専門について、他部署の若手の質問に答えたい。それにより、自分の経験を若手に伝えたい。
  背景: 現状は他部署の若手とつながる経路がなく、若手が困っていることを知らない。

## Open Questions

- 斜めの先輩が十分に登録してくれるか。答える時間を業務として認めてもらえるか
- 匿名の質問では、質問の背景がわからず答えにくくならないか
- 答えの正確さを誰が確かめるか
- **モックで確かめたいこと**: 若手が分野を選んで匿名で質問を送る流れが、気兼ねなくできると感じられるか
- **モックで確かめたいこと**: 斜めの先輩が質問を受け取ったとき、背景がわからなくても答えやすい形になっているか

## Risks（教材外補強 — PRD 101 に Risks の形式は無い）

- **ベテランが集まらない** — 答える時間がない → 登録が少ない → 質問に答えが付かない。軽減: 最初は数人のベテランに声をかけ、答える件数に上限を設けて負担を抑える
- **匿名の悪用** — 匿名で不適切な質問をする → ベテランが嫌がる → 仕組みが止まる。軽減: 技術の質問に限ることを明記し、不適切な質問は斜めの先輩が断れるようにする
- **答えの誤り** — 答えが間違っている → 若手が誤った知識を持つ → 設計で外す。軽減: 質問集に載せる前に、別の斜めの先輩が確認できるようにする
- **評価への転用** — 質問の内容から質問者が推測される → 評価に影響する不安 → 質問しなくなる。軽減: 質問者の部署の人には割り当てず、質問集では質問の細部を一般化して載せる
